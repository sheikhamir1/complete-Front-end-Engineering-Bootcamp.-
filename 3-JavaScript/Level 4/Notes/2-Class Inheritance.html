The extends Keyword
Creating a child class from a parent class

Inheriting Features

Use class Child extends Parent to create a new class that inherits all methods from the parent. The child gets everything the parent has, plus its own unique features.

class Animal {
  constructor(name) { this.name = name; }
  run(speed) { alert(`${this.name} runs at ${speed}.`); }
}

class Rabbit extends Animal {
  hide() { alert(`${this.name} hides!`); }
}

let rabbit = new Rabbit("White Rabbit");
rabbit.run(5); // Inherited from Animal ✅
rabbit.hide(); // Own method ✅
Under the Hood: extends sets Rabbit.prototype.[[Prototype]] to Animal.prototype. If a method isn't found on Rabbit, JavaScript automatically looks at Animal.
Real-World Analogy

Vehicle Inheritance: A Car class extends Vehicle. All vehicles can startEngine() (inherited), but only cars might have openTrunk() (own method).

Overriding Methods & super
Customizing inherited behavior while keeping the parent's logic

Replacing and Enhancing

If you define a method in the child with the same name as the parent, the child's version is used. But often you want to add to the parent's logic, not erase it. That's what super is for.

class Rabbit extends Animal {
  hide() { alert(`${this.name} hides!`); }

  stop() {
    super.stop(); // Call parent's stop()
    this.hide(); // Then add child's behavior
  }
}

The super Keyword

  • super.method() — calls the parent's method.
  • super() — calls the parent's constructor (inside child constructor only).
  • Arrow functions don't have their own super; they borrow it from the surrounding scope.
Real-World Analogy

Asking Parents for Advice: When you override a method, it's like saying "I'll handle this my way." But with super, you're saying "I'll handle it my way, but first, let me ask my parents how they did it."

Overriding the Constructor
The golden rule: super() must be called before using this

Broken (No super)

class Rabbit extends Animal {
  constructor(name, earLength) {
    this.name = name; // Error!
    this.earLength = earLength;
  }
}

Fixed (super first!)

class Rabbit extends Animal {
  constructor(name, earLength) {
    super(name); // ✅ Must be first!
    this.earLength = earLength;
  }
}
Why? A derived class (one that extends another) does NOT create the this object itself. It relies on the parent constructor to build it. Calling super() tells the parent to set up this. Until super() runs, this doesn't exist!
Real-World Analogy

Building a House: The parent class pours the concrete foundation (super()). The child class adds the walls and roof (this.field = ...). You can't paint the walls before the foundation is poured!

Class Fields: A Tricky Note
Why parent constructors don't see overridden child fields

The Surprise

When a parent constructor runs, it uses its OWN class fields, not the child's overridden ones. But for methods, it uses the child's overridden version. This is different from Java/C++!

Fields (Parent wins)

class Animal {
  name = 'animal';
  constructor() {
    alert(this.name);
  }
}

class Rabbit extends Animal {
  name = 'rabbit';
}

new Rabbit(); // "animal" (!)

Methods (Child wins)

class Animal {
  showName() { alert('animal'); }
  constructor() {
    this.showName();
  }
}

class Rabbit extends Animal {
  showName() { alert('rabbit'); }
}

new Rabbit(); // "rabbit" ✅
Why? Initialization order! Child class fields are set after super() (the parent constructor) finishes. So during the parent constructor, the child field doesn't exist yet. But methods exist on the prototype immediately.

The Problem with super
Why this.__proto__.method() causes infinite loops

The Infinite Loop Bug

You might think super.method() just does this.__proto__.method(). But with multiple levels of inheritance, that breaks horribly!

let animal = { eat() { alert("Animal eats"); } };
let rabbit = { __proto__: animal, eat() { this.__proto__.eat.call(this); } };
let longEar = { __proto__: rabbit, eat() { this.__proto__.eat.call(this); } };

longEar.eat(); // Maximum call stack size exceeded!

What Happens?

When longEar.eat() runs, this is longEar. So this.__proto__ is rabbit. It calls rabbit.eat().

Inside rabbit.eat(), this is STILL longEar! So this.__proto__ is STILL rabbit. It calls rabbit.eat() again. Loop forever!

6 / 9
[[HomeObject]] Saves the Day
How JavaScript actually makes super work correctly

The Solution

JavaScript gives every method a special hidden property called [[HomeObject]]. It permanently remembers which object the method belongs to — regardless of this.

let rabbit = {
  eat() { // rabbit.eat.[[HomeObject]] = rabbit
    super.eat();
  }
};

let longEar = {
  __proto__: rabbit,
  eat() { // longEar.eat.[[HomeObject]] = longEar
    super.eat();
  }
};

longEar.eat(); // Works! ✅
How it works: super uses [[HomeObject]] to find the parent, NOT this.__proto__. longEar.eat knows its HomeObject is longEar, so it looks at longEar.__proto__ (which is rabbit). Then rabbit.eat knows its HomeObject is rabbit, so it looks at rabbit.__proto__ (which is animal). Chain works perfectly!
Real-World Analogy

GPS Bracelet: Think of [[HomeObject]] as a GPS bracelet that a method wears. It always knows its "home address" (where it was born), not just its current location (this). super uses this home address to find the parent.

Methods Are Not "Free"
Why copying methods with super can break

The Copy Problem

Because methods remember their [[HomeObject]], they are tied to their original object. If you copy a method with super to a different object, the super still points to the old parent!

let rabbit = {
  __proto__: animal,
  sayHi() { super.sayHi(); } // HomeObject = rabbit
};

let tree = {
  __proto__: plant,
  sayHi: rabbit.sayHi // Copied method!
};

tree.sayHi(); // Says "I'm an animal" (?!)
// It should say "I'm a plant"!
Syntax Matters! [[HomeObject]] only works for methods defined as method() {}, not method: function() {}. The latter is treated as a "free function" and gets no [[HomeObject]] or super access.
Real-World Analogy

Company Keycard: A method's [[HomeObject]] is like a keycard programmed for one specific building. If you borrow the keycard and use it at a different building, it still tries to open doors at the original building. It doesn't adapt to the new location.

Summary
Everything you need to remember about Class Inheritance

Basic Rules

  • extends links child prototype to parent prototype
  • Override methods by defining same name in child
  • super.method() calls the parent's version
  • super() in constructor must run before this

Under the Hood

  • [[HomeObject]] remembers method's birthplace
  • super uses HomeObject, not this
  • Don't copy methods that use super
  • Parent constructor uses parent fields, child methods
