Eval: Running Code Strings

Executing text as JavaScript

What is eval?

The built-in eval(code) function takes a string of JavaScript code and executes it. It returns the result of the last statement in that string.

Real-World Analogy: Imagine a restaurant where instead of ordering from a menu, you hand the chef a handwritten recipe on a napkin. eval is that chef. It will cook whatever is written on that napkin!

Basic Examples

let code = 'alert("Hello")'; eval(code); // Hello let value = eval('1+1'); alert(value); // 2 let result = eval('let i = 0; ++i'); alert(result); // 1 (returns last statement)

Access to Local Variables

eval runs in the current scope, meaning it can read and modify variables around it.

let x = 5; eval("x = 10"); alert(x); // 10, value modified!

The Dangers of Eval

Why modern developers avoid it

"Eval is Evil"

In modern programming, eval is used very sparingly. Here is why you should avoid it:

  • Security Risks: If you eval user input, a malicious user could inject harmful code.
  • Breaks Minifiers: Tools that shrink code (minifiers) rename variables to save space (e.g., myLongVar → a). But if eval uses myLongVar, the minifier can't rename it, breaking the compression.
  • Hard to Debug: Code inside a string is invisible to debuggers and syntax checkers.

Strict Mode Saves the Day

In strict mode ("use strict"), eval gets its own isolated scope. Variables created inside the string won't leak out.

"use strict"; eval("let x = 5; function f() {}"); alert(typeof x); // undefined (doesn't leak out) alert(typeof f); // undefined

What to use instead?

If you must execute code dynamically, there are safer alternatives.

1. window.eval()

Forces the code to run in the global scope, so it can't mess with local variables.

let x = 1; { let x = 5; window.eval('alert(x)'); // 1 (Global) }

2. new Function()

Creates a function from a string. It runs in the global scope and forces you to pass data explicitly as arguments, which is much safer.

let f = new Function('a', 'alert(a)'); f(5); // 5

Currying

Functions one argument at a time

What is Currying?

Currying is a technique where a function with multiple arguments—like f(a, b, c)—is transformed into a sequence of functions that take one argument at a time: f(a)(b)(c).

Real-World Analogy: Ordering a custom car. Instead of giving the factory a massive list of specs all at once, you first pick the model, then the color, then the interior. Each step narrows it down until you get the final product.

Basic Currying Implementation

function curry(f) { return function(a) { return function(b) { return f(a, b); }; }; } function sum(a, b) { return a + b; } let curriedSum = curry(sum); alert( curriedSum(1)(2) ); // 3

Currying doesn't call the function immediately. It just transforms it so it can be called step-by-step.

Why Use Currying?

Creating convenient "Partial" functions

The Logging Example

Let's say we have a logging function: log(date, importance, message). Using advanced currying (like Lodash's _.curry), we can create highly reusable, pre-configured functions.

Step-by-Step Specialization

function log(date, importance, message) { alert(`[${date.getHours()}:${date.getMinutes()}] [${importance}] ${message}`); } // Curry it (e.g., using lodash _.curry) log = _.curry(log); // 1. Normal call still works log(new Date(), "DEBUG", "some debug"); // 2. Create a partial for TODAY's logs let logNow = log(new Date()); // Now we only need importance and message! logNow("INFO", "message"); // [10:15] INFO message // 3. Create a partial for TODAY's DEBUG logs let debugNow = logNow("DEBUG"); // Now we only need the message! debugNow("message"); // [10:15] DEBUG message
The Benefit: Instead of passing new Date() and "DEBUG" every single time you log something, currying lets you lock in those repeating arguments and create a quick, custom shortcut function.

Advanced Currying Implementation

Handling multiple arguments dynamically

The simple curry wrapper only works for 2 arguments. Here is a multi-argument version. It checks: "Do I have enough arguments yet?" If yes, it runs. If no, it waits for more.

function curry(func) { return function curried(...args) { if (args.length >= func.length) { // If we have enough arguments, call the original function return func.apply(this, args); } else { // Otherwise, return a partial function waiting for more args return function(...args2) { return curried.apply(this, args.concat(args2)); } } }; } function sum(a, b, c) { return a + b + c; } let curriedSum = curry(sum); alert( curriedSum(1, 2, 3) ); // 6, normal call alert( curriedSum(1)(2,3) ); // 6, currying first arg alert( curriedSum(1)(2)(3) ); // 6, full currying

Limitations

This only works for functions with a fixed, known number of arguments (func.length). It won't work for functions that use rest parameters like function f(...args).

Reference Type

Why do we lose this?

The Mystery of the Missing this

Have you ever tried to call a method dynamically and gotten an error because this became undefined?

The Broken Code

let user = { name: "John", hi() { alert(this.name); }, bye() { alert("Bye"); } }; user.hi(); // Works! "John" // Dynamically choose the method: (user.name == "John" ? user.hi : user.bye)(); // Error! this is undefined

Why does user.hi() work, but extracting it and calling it breaks? It seems like the same function! The answer lies in how JavaScript passes information from the dot . to the parentheses ().

Real-World Analogy: Imagine a sealed envelope with a return address (the object). When you write user.hi(), the dot . hands the envelope directly to the parentheses (). But when you extract it like let hi = user.hi or use a ternary operator, you throw the envelope away and just hand over the letter inside. The parentheses no longer know who sent it!

Reference Type Under the Hood

The invisible "envelope" of data

The Internal Type

JavaScript uses a hidden "Reference Type" to keep track of where a method came from. It's not something you can touch in code; it's strictly used by the engine under the hood.

A Reference Type value consists of three pieces of data:

  • base: The object (e.g., user)
  • name: The property name (e.g., "hi")
  • strict: Is strict mode on?

How the Dot Operator Works

When you write user.hi, the dot doesn't just return the function. It returns a Reference Type value: (user, "hi", true).

When the parentheses () see this Reference Type, they say: "Ah, the base is user, so I will set this = user!"

How Extraction Breaks It

When you assign let hi = user.hi or use ( ... ? user.hi : user.bye), JavaScript throws away the Reference Type envelope. It only keeps the raw function. When the parentheses () run, they just see a raw function with no return address, so this becomes undefined.

// Method extracted from object = loses Reference Type envelope let hi = user.hi; hi(); // Error! Just a raw function now.

This is why methods like func.bind() exist—they manually lock in the this value so it doesn't get lost when you pass functions around!
