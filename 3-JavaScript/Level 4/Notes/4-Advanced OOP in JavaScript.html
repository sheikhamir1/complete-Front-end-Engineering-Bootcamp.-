Extending Built-in Classes

Supercharging Native Objects

Adding Features to Arrays

Just like you can extend your own classes, you can extend JavaScript's built-in classes like Array, Map, etc. This lets you create "enhanced" versions of native objects.

Real-World Analogy: Imagine buying a standard car (Array) and upgrading it to a "SuperCar" (PowerArray). You add a new button (method) like isEmpty(), but it still drives and functions exactly like a normal car.

Creating a PowerArray

class PowerArray extends Array { isEmpty() { return this.length === 0; } } let arr = new PowerArray(1, 2, 5, 10, 50); alert(arr.isEmpty()); // false // filter is a built-in method, but it's smart! let filteredArr = arr.filter(item => item >= 10); alert(filteredArr); // 10, 50 // The result is STILL a PowerArray! alert(filteredArr.isEmpty()); // false (works!)

Why does filter return a PowerArray? Built-in methods like filter and map look at the object's constructor property. Since filteredArr was created from a PowerArray, it uses PowerArray as the constructor for the new result. This keeps your custom methods available down the line!

Symbol.species

Controlling What Built-in Methods Return

Changing the Factory Setting

Sometimes, you don't want methods like filter to return your custom class. You might want them to return the basic, plain Array instead. JavaScript provides a special static getter called Symbol.species for this.

Real-World Analogy: Your SuperCar factory normally produces SuperCars. By setting Symbol.species, you're telling the factory: "When you do internal repairs (like filter), give me back a standard basic Car, not a SuperCar."

Forcing filter to return a normal Array

class PowerArray extends Array { isEmpty() { return this.length === 0; } // Tell built-in methods to use the plain Array constructor static get [Symbol.species]() { return Array; } } let arr = new PowerArray(1, 2, 5, 10, 50); let filteredArr = arr.filter(item => item >= 10); // filteredArr is now a plain Array, NOT PowerArray alert(filteredArr.isEmpty()); // Error: filteredArr.isEmpty is not a function

No Static Inheritance in Built-ins

There is one quirk with built-in classes: they do not inherit static methods from each other. For example, Array extends Object, but Array does not have Object.keys(). They are independent at the static level. This is different from your custom classes, where statics are normally inherited.

Class Checking: "instanceof"

Verifying an Object's Family Tree

How to check an object's type

The instanceof operator checks if an object belongs to a certain class (or any class in its inheritance chain). It returns a boolean.

Real-World Analogy: Think of it like checking someone's passport. Is this person (object) a citizen of France (Class)? Or are they a citizen of Europe (Parent Class)? instanceof checks the whole family tree.

Basic Usage

class Rabbit {} let rabbit = new Rabbit(); alert(rabbit instanceof Rabbit); // true // Also works with built-in classes let arr = [1, 2, 3]; alert(arr instanceof Array); // true alert(arr instanceof Object); // true (Array inherits from Object)

How it works under the hood

instanceof walks up the prototype chain. It asks: "Is Rabbit.prototype anywhere in rabbit's chain of prototypes?"

It also checks a static method called Symbol.hasInstance if you want to write custom logic for how a class verifies its instances.

Custom Type Checking

Symbol.hasInstance & Object.prototype.toString

Custom Logic with Symbol.hasInstance

You can define your own rules for what makes an object an "instance" of your class.

class Animal { static [Symbol.hasInstance](obj) { // Custom rule: if it canEat, it's an Animal if (obj.canEat) return true; } } let obj = { canEat: true }; alert(obj instanceof Animal); // true!

The Secret Type Tagger: toString

Plain objects print as [object Object]. But if you borrow the built-in Object.prototype.toString method and use .call(), it acts like a super-powered typeof that tells you exactly what something is.

let s = Object.prototype.toString; alert( s.call(123) ); // [object Number] alert( s.call(null) ); // [object Null] alert( s.call([]) ); // [object Array] alert( s.call(alert) ); // [object Function]

Customizing the toString Tag

You can use Symbol.toStringTag to customize what the secret type tag says for your own objects.

let user = { [Symbol.toStringTag]: "User" }; alert( {}.toString.call(user) ); // [object User]

Type Checking Summary

Method What it works for What it returns
typeof Primitives (strings, numbers) String ("number")
{}.toString Primitives, Built-ins, Custom Objects String ("[object Array]")
instanceof Objects Boolean (true/false)

Mixins

Breaking the Single-Inheritance Rule

The Problem with Single Inheritance

In JavaScript, a class can only extend one parent class. You can't have class B extends A, C. But what if you have a class User and you want to add event-handling capabilities from an EventEmitter class?

Real-World Analogy: Think of a class as a person. You can only be born from one set of parents (Single Inheritance). Mixins are like taking a class or getting a certification. You're still you, but you've "mixed in" new skills (like learning to fly a plane) without changing your parents.

How Mixins Work

A Mixin is simply an object full of useful methods. We can copy those methods into a class's prototype using Object.assign().

// 1. Define the mixin (the "power-up") let sayHiMixin = { sayHi() { alert(`Hello ${this.name}`); }, sayBye() { alert(`Bye ${this.name}`); } }; // 2. Define the class class User { constructor(name) { this.name = name; } } // 3. Mix the methods into the User prototype Object.assign(User.prototype, sayHiMixin); // Now User can say hi! new User("Dude").sayHi(); // Hello Dude!

Now, User can still extend Person, and also include sayHiMixin. Mixins can even inherit from other mixins internally using super!

The EventMixin

A Practical Mixin for Real Apps

Adding Walkie-Talkie Abilities to Any Object

Many objects in programming need to "broadcast" events when things happen (like a user logging in, or a menu item being clicked). An EventMixin adds a walkie-talkie to any class so it can trigger events and let others listen to them.

EventMixin Code

let eventMixin = { // 1. Subscribe to an event on(eventName, handler) { if (!this._eventHandlers) this._eventHandlers = {}; if (!this._eventHandlers[eventName]) { this._eventHandlers[eventName] = []; } this._eventHandlers[eventName].push(handler); }, // 2. Unsubscribe from an event off(eventName, handler) { let handlers = this._eventHandlers?.[eventName]; if (!handlers) return; for (let i = 0; i < handlers.length; i++) { if (handlers[i] === handler) { handlers.splice(i--, 1); } } }, // 3. Generate (trigger) an event trigger(eventName, ...args) { if (!this._eventHandlers?.[eventName]) { return; // no handlers for that event } this._eventHandlers[eventName].forEach(handler => handler.apply(this, args)); } };

Using the EventMixin

Putting the Walkie-Talkie to Work

Creating a Reactive Menu

Let's say we have a Menu class. When a user selects an item, the menu needs to tell the rest of the app about it. Instead of hardcoding connections, we mix in the event system.

Menu Implementation

// The Class class Menu { choose(value) { this.trigger("select", value); } } // Plug in the Mixin! Object.assign(Menu.prototype, eventMixin); let menu = new Menu(); // Add a listener (someone turns on their walkie-talkie) menu.on("select", value => alert(`Value selected: ${value}`)); // Trigger the event (the menu broadcasts) menu.choose("123"); // Alerts: "Value selected: 123"

Summary of Mixins

  • What is it? A way to add methods to classes without using inheritance.
  • How does it work? By copying methods from a mixin object into a class's prototype using Object.assign().
  • When to use it? When multiple unrelated classes need the same behavior (like event handling, logging, or formatting), but they don't share a common parent class.
  • Watch out! Be careful with naming. If a mixin has a method with the same name as the class, it will overwrite it, which can cause bugs.
