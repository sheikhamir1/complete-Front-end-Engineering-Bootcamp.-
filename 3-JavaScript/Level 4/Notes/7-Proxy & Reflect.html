Proxy & Reflect

Controlling Objects at the Lowest Level

A Proxy is an object that wraps around another object and intercepts its operations—like reading or writing properties. You can handle these operations yourself or pass them along to the original object.

Real-World Analogy: Think of a Proxy as a Security Receptionist at a building. You don't talk directly to the employees (the target object); you talk to the receptionist. The receptionist can log your visit, deny you access, or call the employee for you.

Alongside Proxy, JavaScript introduced Reflect, a built-in tool that makes writing proxies easier and safer. We'll explore both!

The Basics of Proxy

Wrapping an Object

Creating a Proxy

The syntax is simple: let proxy = new Proxy(target, handler)

  • target: The original object you want to wrap.
  • handler: An object containing "traps" — methods that intercept specific operations.

An Empty Wrapper (Transparent Proxy)

If you provide an empty handler, the proxy just passes everything through to the target.

let target = {}; let proxy = new Proxy(target, {}); // No traps proxy.test = 5; // Writing to proxy alert(target.test); // 5 (Appeared in target!) alert(proxy.test); // 5 (We can read it too)

What are Traps?

Under the hood, JavaScript uses "internal methods" (like [[Get]] or [[Set]]) to read/write objects. A trap is a function in your handler that intercepts these internal methods.

Internal Method Trap Name Triggers when...
[[Get]] get Reading a property
[[Set]] set Writing to a property
[[HasProperty]] has Using the in operator
[[Delete]] deleteProperty Using delete
[[Call]] apply Calling a function

The "get" Trap

Intercepting Reads & Default Values

How it works

When you read a property, the get(target, property, receiver) trap fires. You can return whatever you want, or look it up in the original target.

Use Case: Have you ever tried to read an array index that doesn't exist? You get undefined. Let's use a Proxy to return 0 instead for missing numbers.

Array with Default Value 0

let numbers = [0, 1, 2]; numbers = new Proxy(numbers, { get(target, prop) { if (prop in target) { return target[prop]; // Exists? Return it. } else { return 0; // Doesn't exist? Return 0. } } }); alert( numbers[1] ); // 1 alert( numbers[123] ); // 0 (No undefined!)

Smart Dictionary

Another great use case: a translation dictionary that returns the original phrase if it hasn't been translated yet, instead of undefined.

let dictionary = { "Hello": "Hola" }; dictionary = new Proxy(dictionary, { get(target, phrase) { if (phrase in target) return target[phrase]; else return phrase; // Return the untranslated phrase } }); alert(dictionary["Hello"]); // Hola alert(dictionary["Welcome"]); // Welcome

The "set" Trap

Validation & Protecting Writes

Validating Data Types

The set(target, property, value, receiver) trap fires when a property is changed. This is perfect for validation. If the new value is invalid, you can reject it.

Important Rule (Invariant): The set trap must return true if the write was successful, and false if it failed. If you return false, JavaScript will throw a TypeError!

Numbers-Only Array

Let's create an array that only accepts numbers. If you try to push a string, it fails.

let numbers = []; numbers = new Proxy(numbers, { set(target, prop, val) { if (typeof val == "number") { target[prop] = val; return true; // Success! } else { return false; // Reject! Triggers TypeError } } }); numbers.push(1); // Works numbers.push(2); // Works numbers.push("test"); // TypeError: 'set' on proxy returned false

Notice how elegant this is? We didn't have to override array methods like .push() or .unshift(). Under the hood, they all use the basic [[Set]] operation, so our proxy catches them automatically!

Protecting Properties

Hiding Internal Data (Underscore convention)

Developers use an underscore (e.g., _password) to mean "don't touch this!" But it's just a polite request; JavaScript doesn't enforce it. Let's use a Proxy to actually block access.

The Fortress Proxy

let user = { name: "John", _password: "***" }; user = new Proxy(user, { get(target, prop) { if (prop.startsWith('_')) throw new Error("Access denied"); let value = target[prop]; // Bind methods to the original target so they can see _password return (typeof value === 'function') ? value.bind(target) : value; }, set(target, prop, val) { if (prop.startsWith('_')) throw new Error("Access denied"); target[prop] = val; return true; }, deleteProperty(target, prop) { if (prop.startsWith('_')) throw new Error("Access denied"); delete target[prop]; return true; }, ownKeys(target) { // Hide from for..in and Object.keys return Object.keys(target).filter(key => !key.startsWith('_')); } }); alert(user._password); // Error: Access denied
Why value.bind(target)? If your object has a method like checkPassword(), it needs to read this._password. But this would be the Proxy, which blocks access! Binding the method to the target gives it a "backstage pass" to read private properties safely.

Other Useful Traps

"has" for Ranges & "apply" for Functions

The "has" Trap

Intercepts the in operator. Let's make an object that checks if a number is in a specific range.

let range = { start: 1, end: 10 }; range = new Proxy(range, { has(target, prop) { return prop >= target.start && prop <= target.end; } }); alert(5 in range); // true alert(50 in range); // false

The "apply" Trap

Proxies can wrap functions too! The apply trap intercepts function calls. It's perfect for creating "decorators" that add behavior (like a delay) to a function.

function delay(f, ms) { return new Proxy(f, { apply(target, thisArg, args) { setTimeout(() => target.apply(thisArg, args), ms); } }); } function sayHi(user) { alert(`Hello, ${user}!`); } sayHi = delay(sayHi, 3000); sayHi("John"); // Runs after 3 secs
Why Proxy over normal wrapper? A normal function wrapper loses the original function's properties (like name or length). A Proxy forwards everything to the target, so sayHi.length still works perfectly!

Introducing Reflect

The Perfect Partner for Proxy

What is Reflect?

Reflect is a built-in object that provides methods for calling JavaScript internal methods. For every Proxy trap, there is a matching Reflect method with the exact same arguments.

Real-World Analogy: If the Proxy is the Receptionist, Reflect is the Walkie-Talkie. When the receptionist decides a request is okay, they use the walkie-talkie to patch the call through to the employee exactly as it was dialed.

Reflect vs Normal Operations

Normal Operation Reflect Call
obj[prop] Reflect.get(obj, prop)
obj[prop] = val Reflect.set(obj, prop, val)
delete obj[prop] Reflect.deleteProperty(obj, prop)

Forwarding Operations Safely

Instead of manually writing target[prop] = val, use Reflect. It ensures nothing is forgotten (like returning true for the set trap).

user = new Proxy(user, { get(target, prop, receiver) { alert(`GET ${prop}`); return Reflect.get(target, prop, receiver); // Forward it! }, set(target, prop, val, receiver) { alert(`SET ${prop}=${val}`); return Reflect.set(target, prop, val, receiver); // Forward it! } });

Why Reflect.get is Essential

The "receiver" argument and Getters

The Inheritance Problem

If an object has a getter (e.g., get name()), and we use a simple target[prop] in our proxy, the getter's this context gets lost when inheritance is involved. It points to the original target, not the inheriting object.

The Broken Way (Without Reflect)

let user = { _name: "Guest", get name() { return this._name; } }; let userProxy = new Proxy(user, { get(target, prop) { return target[prop]; // "this" is forced to be "target" (user) } }); let admin = { __proto__: userProxy, _name: "Admin" }; alert(admin.name); // Outputs: Guest (Wrong! Should be Admin)

The Fixed Way (With Reflect)

Reflect.get takes a 3rd argument: receiver. This correctly preserves the this context for getters.

let userProxy = new Proxy(user, { get(target, prop, receiver) { // receiver = admin return Reflect.get(target, prop, receiver); // Passes the correct "this" } }); let admin = { __proto__: userProxy, _name: "Admin" }; alert(admin.name); // Outputs: Admin (Correct!)

Proxy Limitations

What Proxies CAN'T do

1. Built-in Objects & "Internal Slots"

Some built-in objects like Map, Set, Date, and Promise have "internal slots" (like [[MapData]]). Proxies don't have these slots, so built-in methods fail when they try to access them on the Proxy.

The Fix: Bind the method to the target object! typeof value == 'function' ? value.bind(target) : value

2. Private Class Fields

Private fields (like #name) also use internal slots. A proxy cannot access them. The fix is the same: bind the method that uses the private field to the original target object.

3. Proxy is NOT the Target (Strict Equality)

A proxy is a different object than its target. proxy === target is false. If you use the original object as a key in a Set or Map, the proxy won't be able to find it!

let allUsers = new Set(); let user = new User("John"); allUsers.add(user); user = new Proxy(user, {}); // Wrap in proxy alert(allUsers.has(user)); // false! The proxy is not the original user.

Revocable Proxies

The Self-Destructing Wrapper

Turning off Access

Sometimes you want to give someone temporary access to an object, and then take it away. A Revocable Proxy can be "revoked" or disabled at any moment.

Real-World Analogy: A temporary ID badge. You can use it to get into the building, but HR can deactivate your badge instantly. After that, the badge doesn't work anymore.

Creating a Revocable Proxy

let object = { data: "Valuable data" }; // Destructure to get both proxy and the revoke function let {proxy, revoke} = Proxy.revocable(object, {}); // Pass the proxy somewhere else alert(proxy.data); // Valuable data // Later... time's up! revoke(); // Destroys the proxy connection alert(proxy.data); // Error! Proxy is revoked.

Clean up with WeakMap

A good practice is to store the revoke function in a WeakMap using the proxy as a key. That way, if the proxy is deleted from memory, the revoke function is too.

let revokes = new WeakMap(); let {proxy, revoke} = Proxy.revocable(object, {}); revokes.set(proxy, revoke); // Later, find and revoke revokes.get(proxy)(); // Revokes instantly!
