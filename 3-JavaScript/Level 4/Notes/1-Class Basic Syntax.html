Real-World Analogy

A class is like an architectural blueprint for a house. The blueprint itself isn't a house — it's the template. You use the blueprint to build actual houses (objects). Every house built from the same blueprint has the same structure, but different families (data) living inside.

The class Syntax
Defining a blueprint for objects

Basic Structure

The class keyword provides a clean syntax to define object templates. The constructor() method runs automatically when you create a new object.

class User {
  constructor(name) {
    this.name = name; // Initialize state
  }

  sayHi() {
    alert(this.name); // Define behavior
  }
}

let user = new User("John");
user.sayHi(); // John
No Commas Between Methods! A common mistake is adding commas between methods like in object literals. In classes, commas are not allowed and will cause a syntax error.
Real-World Analogy

Building a House: The constructor is the foundation-laying ceremony — it happens once when the house is first built. sayHi is like the doorbell — a feature every house has that can be used anytime.

What is a Class, Really?
Under the hood, it's not magic — it's just a function

Unveiling the Magic

A class in JavaScript is not a completely new entity. It's a special kind of function. When you write class User, JavaScript does two things behind the scenes.

class User {
  constructor(name) { this.name = name; }
  sayHi() { alert(this.name); }
}

// Proof: User is a function
alert(typeof User); // function

// The constructor is the function itself
alert(User === User.prototype.constructor); // true

// Methods live in User.prototype
alert(User.prototype.sayHi); // code of sayHi
What class User actually does:
1. Creates a function named User from the constructor method.
2. Stores all other methods (like sayHi) in User.prototype.
When you call user.sayHi(), it's found in the prototype — exactly like we learned before!

Not Just Syntactic Sugar
Important differences between class and plain functions

Why Classes Are Different

You could write the same thing using old-style constructor functions. But class adds important safety features that plain functions don't have.

Feature Plain Function class
Call without new Works (but breaks this) ❌ Throws Error
Strict mode Optional ✅ Always strict
Methods enumerable Yes (shows in for..in) No (hidden from for..in)
toString() "function User..." "class User..."
class User {
  constructor() {}
}

User(); // Error: Class constructor User cannot be invoked without 'new'
Real-World Analogy

Microwave vs Stove: You can cook the same meal on a stove (plain function) or in a microwave (class). The result is similar, but the microwave has built-in safety features — it won't start with the door open (new requirement) and has automatic shut-off (strict mode).

Class Expressions
Classes can be assigned, passed around, and created dynamically

Just Like Functions

Classes don't have to be declared at the top level. They can be expressions — assigned to variables, passed as arguments, or even returned from functions.

Named Class Expression

let User = class MyClass {
  sayHi() {
    alert(MyClass); // Visible inside
  }
};

new User().sayHi(); // Works
alert(MyClass); // Error! Not visible outside

Dynamic Class Creation

function makeClass(phrase) {
  return class {
    sayHi() {
      alert(phrase);
    }
  };
}

let User = makeClass("Hello");
new User().sayHi(); // Hello
Real-World Analogy

Custom Factory: A dynamic class is like a factory that can reconfigure its assembly line based on your order. You tell it "Hello" and it produces a machine that says "Hello".

Getters, Setters & Computed Names
Adding smart properties and dynamic method names

Validation with Getters/Setters

Just like in object literals, classes support get and set. They allow you to control how properties are read and written — perfect for validation.

class User {
  constructor(name) {
    this.name = name; // Invokes the setter!
  }

  get name() {
    return this._name;
  }

  set name(value) {
    if (value.length < 4) {
      alert("Name is too short.");
      return;
    }
    this._name = value;
  }
}

let user = new User("John");
alert(user.name); // John

user = new User(""); // "Name is too short."

Computed Method Names

You can also use square brackets to compute method names dynamically:

class User {
  ['say' + 'Hi']() {
    alert("Hello");
  }
}

new User().sayHi(); // Hello

Class Fields
Adding properties directly in the class body

Properties, Not Just Methods

Previously, classes only had methods. Class fields let you add properties right in the class body with a simple = assignment.

class User {
  name = "John"; // Class field

  sayHi() {
    alert(`Hello, ${this.name}!`);
  }
}

new User().sayHi(); // Hello, John!
Important: On the Object, Not the Prototype! Class fields are set on each individual object, not on User.prototype. This means every instance gets its own separate copy.
let user = new User();
alert(user.name); // John (on the object)
alert(User.prototype.name); // undefined (NOT on prototype)
Real-World Analogy

Personal Locker vs Shared Gym: Methods are like shared gym equipment — everyone uses the same treadmill (prototype). Class fields are like personal lockers — each member gets their own locker with their own stuff (individual object).

Bound Methods with Class Fields
The elegant solution to the "losing this" problem

The "Losing this" Problem

When you pass an object method as a callback (like to setTimeout), this is lost. Class fields provide an elegant fix using arrow functions.

Broken (loses this)

class Button {
  constructor(value) {
    this.value = value;
  }
  click() {
    alert(this.value);
  }
}

let button = new Button("hello");
setTimeout(button.click, 1000);
// undefined

Fixed (Arrow Function Field)

class Button {
  constructor(value) {
    this.value = value;
  }
  click = () => {
    alert(this.value);
  }
}

let button = new Button("hello");
setTimeout(button.click, 1000);
// hello ✅
Real-World Analogy

Pre-programmed Remote: A regular method is like a universal remote — it might control any TV depending on where you point it. An arrow function class field is like a remote permanently paired to YOUR TV. No matter who borrows it, it always controls your TV.

Summary
Everything you need to remember about Class Basic Syntax

Core Concepts

  • Classes are blueprints for creating objects
  • Under the hood, a class is a special function
  • constructor() initializes new objects
  • Methods go to Class.prototype
  • Class fields go on individual objects

Safety Features

  • Must be called with new
  • Always in strict mode
  • Methods are non-enumerable
  • No commas between methods
  • Arrow function fields auto-bind this
