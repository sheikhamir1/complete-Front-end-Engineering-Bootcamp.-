What is Recursion?
A function that calls itself to solve smaller versions of the same problem

Core Idea

Recursion is when a function solves a task by calling itself with a simpler input. It keeps breaking the problem down until it reaches a trivially simple case it can answer immediately.

Base Case

The condition where the function stops calling itself and returns a direct answer. Without it, recursion runs forever (stack overflow!).

// The stopping point
if (n == 1) {
  return x; // Direct answer
}

Recursive Step

The part where the function calls itself with a smaller/simpler input, moving toward the base case.

// Break problem down
else {
  return x * pow(x, n - 1);
}
Real-World Analogy

Matryoshka Dolls: You open a doll, and inside is a smaller doll. You keep opening dolls (recursive step) until you reach the tiniest one that can't be opened (base case). Each doll is the "same kind" but simpler/smaller.

Two Ways of Thinking
Iterative vs Recursive — Same result, different mindset

Let's write pow(x, n) — a function that raises x to the power n. Example: pow(2, 4) = 2×2×2×2 = 16.

ITERATIVE Using a Loop

function pow(x, n) {
  let result = 1;

  for (let i = 0; i < n; i++) {
    result *= x;
  }

  return result;
}

pow(2, 3); // 8

Multiply x by itself n times using a loop. Straightforward and familiar.

RECURSIVE Call Self

function pow(x, n) {
  if (n == 1) {
    return x; // base case
  } else {
    return x * pow(x, n-1);
  }
}

pow(2, 3); // 8

xn = x × xn-1. Simplify until n=1, then return directly.

Key Insight: The recursive approach says: "I don't need to calculate the whole thing. If someone gives me pow(2,3), I just need 2 × pow(2,2). Let a smaller version of me handle the rest!"

How Recursion Unfolds
Tracing pow(2, 4) step by step

Watch how pow(2, 4) breaks down and then builds back up:

Winding Down (Breaking Apart)

1
pow(2, 4) → needs 2 × pow(2, 3)
2
pow(2, 3) → needs 2 × pow(2, 2)
3
pow(2, 2) → needs 2 × pow(2, 1)
4
pow(2, 1) → Base case! Returns 2

Unwinding (Building the Answer)

4
pow(2, 1) = 2
3

2

1
pow(2, 4) = 2 × 8 = 16 ✅
Real-World Analogy

Asking a boss for an answer: You ask your manager a question. They don't know, so they ask their manager (recursive call). This goes up the chain until someone knows the answer (base case). Then the answer travels back down the chain to you.

Shorthand version: return (n == 1) ? x : (x * pow(x, n - 1)); — One line, same logic!

The Execution Context & Call Stack
How JavaScript keeps track of where it is in recursive calls

What is the Call Stack?

Every function call creates an execution context — a record of its variables and where it paused. When a function makes a nested call, the current context is pushed onto a stack, and the new call runs. When it finishes, the previous context is popped off and resumed.

Real-World Analogy

A stack of plates: You add plates on top (push) and remove from the top (pop). The last plate added is the first one removed — that's LIFO (Last In, First Out). Or think of a browser back button — each page you visit gets pushed, and "back" pops the most recent one.

Here's how the stack grows and shrinks during pow(2, 3):

Stack Grows (Calls Made)

pow(2,1) — n=1 → base case!
pow(2,2) — waiting for pow(2,1)
pow(2,3) — waiting for pow(2,2)

Stack Shrinks (Calls Return)

pow(2,1) → returns 2 ✓
pow(2,2) → returns 4 ✓
pow(2,3) → returns 8 ✓
Recursion depth = max stack size. For pow(2,3), the depth is 3. Each context uses memory, so deep recursion (e.g., n=100,000) can cause a stack overflow. JavaScript engines typically allow ~10,000 nested calls.

Recursion vs Iteration
When to use which? Understanding the trade-offs
Aspect Iteration Recursion
Memory Uses a single context — low, fixed memory One context per call — memory grows with depth
Speed Generally faster (no call overhead) Slightly slower (function call overhead)
Code Clarity Can be verbose for complex structures Often shorter & cleaner
Stack Overflow No risk Risk if depth is too large (~10,000+)
Best For Simple loops, known iterations Trees, nested structures, divide & conquer

Why Use Recursion?

  • Shorter, more readable code
  • Naturally fits tree/nested structures
  • Easy to reason about (base case + step)
  • Elegant divide-and-conquer solutions

Watch Out For

  • Stack overflow on deep recursion
  • Slightly more memory usage
  • Can be harder to debug
  • Not always the fastest option
Rule of thumb: Any recursion can be rewritten as a loop, but sometimes the rewrite is complex and not worth it. Use recursion when it makes your code clearer and the depth stays manageable.

Recursive Traversals
Where recursion truly shines — navigating nested structures

Company Salary Example

A company has departments. Each department may have employees or sub-departments (which can have their own sub-departments). How do we sum all salaries?

function sumSalaries(dept) {
  if (Array.isArray(dept)) {
    // Base: it's a list of people
    return dept.reduce(
      (sum, p) => sum + p.salary, 0
    );
  } else {
    // Recursive: it has sub-depts
    let sum = 0;
    for (let sub of
      Object.values(dept)) {
        sum += sumSalaries(sub);
      }
    return sum;
  }
}

sumSalaries(company); // 7700

Logic: If the input is an array → sum directly. If it's an object → recurse into each sub-department. Works for any nesting depth!
Real-World Analogy

Counting people in a building: If the room has people, count them. If it has sub-rooms, go into each sub-room and count (recursion). You don't need to know the building layout in advance — the same logic works for any layout.

Recursive Data Structures
Structures that are defined in terms of themselves

What Makes a Structure Recursive?

A recursive data structure is one that contains a smaller version of itself. We've already seen this: a department can contain sub-departments (same type!).

HTML Document

An HTML tag can contain:

  • Text
  • Comments
  • Other HTML tags (which can contain more tags...)
<div>
  <p> Hello </p>
  <div>
    <span> Nested! </span>
  </div>
</div>

Company Structure

A department is either:

  • An array of employees (base)
  • An object of sub-departments (recursive)
dept = {
  sales: [// array
    {name, salary}
  ],
  development: { // object
    sites: [...],
    internals: [...]
  }
}
Pattern: A recursive structure is like a fractal — zoom in on any part and you see the same pattern. This self-similarity is exactly why recursive functions are the natural tool for traversing them.

Linked List
A recursive data structure that's an alternative to arrays

Why Linked Lists?

Arrays are great, but inserting/deleting at the beginning is slow — all elements must shift. Linked lists solve this by chaining objects with value and next pointers. No renumbering needed!

Structure Visualization

value 1
→
value 2
→
value 3
→
value 4
→
null
let list = {
  value: 1,
  next: {
    value: 2,
    next: {
      value: 3,
      next: {
        value: 4,
        next: null
      }
    }
  }
}; // Each node = { value, next → node or null }
Real-World Analogy

A scavenger hunt: Each clue gives you a location and points to the next clue. To find the 3rd clue, you must start from clue 1 and follow the chain. You can't skip ahead — but you can easily insert a new clue between any two existing ones.

Linked List Operations & Summary
Fast insertions, slow access — and wrapping it all up

Key Operations

Prepend (Add to Start)

// New node points to old list
list = {
  value: "new",
  next: list // → old head
};
// Just update head! O(1)

Remove from Middle

// Skip over the node to delete
list.next = list.next.next;
// Node is unlinked & garbage collected
Operation Array Linked List
Access by index O(1) ⚡ O(n)
Insert at start O(n) O(1) ⚡
Delete at start O(n) O(1) ⚡
Insert at end O(1) ⚡ O(n)*

*O(1) with a tail pointer

Lists can be enhanced: Add a prev pointer for backward navigation (doubly linked list), add a tail reference for fast end-access. The structure adapts to your needs.

Key Takeaways

Recursion

  • A function calling itself with a simpler input
  • Always needs a base case to stop
  • Shorter, cleaner code for nested problems

Call Stack

  • Tracks where each function paused
  • LIFO — last called, first returned
  • Deep recursion = more memory used

Linked Lists

  • Nodes chain via next pointers
  • Fast insert/delete, slow random access
  • A classic recursive data structure
