The Modern Methods
Replacing __proto__ with safer, standardized functions

Why Change?

__proto__ is outdated and deprecated for getting/setting. It's only still allowed inside object literals { __proto__: ... }. For everything else, use the modern API.

Action Old Way (Deprecated) Modern Way
Read Prototype obj.__proto__ Object.getPrototypeOf(obj)
Set Prototype obj.__proto__ = ... Object.setPrototypeOf(obj, proto)
Create Object { __proto__: ... } Object.create(proto)
let animal = { eats: true };

// Create: same as { __proto__: animal }
let rabbit = Object.create(animal);

alert(rabbit.eats); // true

// Read
alert(Object.getPrototypeOf(rabbit) === animal); // true

// Change (not recommended on the fly!)
Object.setPrototypeOf(rabbit, {});
Performance Warning: Changing [[Prototype]] on an existing object with Object.setPrototypeOf is very slow. It breaks JavaScript engine optimizations. Only set prototypes at creation time!

Object.create() Power
Creating objects with prototypes and property descriptors in one step

The Optional Second Argument

Object.create accepts an optional second argument: property descriptors. This lets you define properties with specific flags right from the start.

let animal = { eats: true };

let rabbit = Object.create(animal, {
  jumps: {
    value: true,
    enumerable: true,
    writable: true,
    configurable: true
  }
});

alert(rabbit.jumps); // true

The Ultimate Clone

We can use Object.create to make a truly exact copy of an object — including all property flags and the correct prototype.

let clone = Object.create(
  Object.getPrototypeOf(obj), // Same prototype
  Object.getOwnPropertyDescriptors(obj) // All properties + flags
);
Real-World Analogy

Custom Home Building: Object.create is like ordering a custom-built house. You choose the foundation (proto) AND you can specify the fixtures and locks (descriptors) all at once before moving in.

The __proto__ Problem
Why storing user-provided keys in objects can break

The Bug

Objects are often used as key/value dictionaries. But if a user types __proto__ as a key, the assignment is silently ignored!

let obj = {};

let key = prompt("What's the key?", "__proto__");
obj[key] = "some value";

alert(obj[key]); // [object Object], NOT "some value"!

Why Does This Happen?

__proto__ isn't a regular property — it's an accessor on Object.prototype. When you write obj.__proto__ = "some value", you're calling a setter that expects an object or null. A string is ignored.

This can be a security vulnerability on servers if user input changes the prototype!

Real-World Analogy

VIP Entrance: Imagine a building where the door labeled "VIP" is actually a special control panel, not a normal room. If a guest says "Put my coat in the VIP room", the system tries to execute a command instead of storing the coat. The key name triggers special behavior.

Solution 1: Use Map
The safest way to store arbitrary key/value pairs

No Prototype Problems

Maps are designed specifically for key/value storage. They don't inherit from Object.prototype, so __proto__ is treated like any other key.

let map = new Map();

let key = prompt("What's the key?", "__proto__");
map.set(key, "some value");

alert(map.get(key)); // "some value" ✅ Works perfectly!
Best Practice: If your primary use case is storing and retrieving key/value pairs (especially with user-provided keys), always prefer Map over plain objects. It's safer and provides better methods like .size, .has(), and .forEach().
Real-World Analogy

Storage Lockers: A Map is like a bank of safe deposit boxes. Every key opens a box, and the label "VIP" is just another label on a box — it has no special powers over the vault.

Solution 2: "Very Plain" Objects
Creating objects with absolutely no prototype

Object.create(null)

If you prefer the object syntax over Map, you can create a "pure dictionary" — an object with [[Prototype]] set to null. It has no inherited methods and no __proto__ accessor.

let obj = Object.create(null);
// Or: obj = { __proto__: null }

let key = prompt("What's the key?", "__proto__");
obj[key] = "some value";

alert(obj[key]); // "some value" ✅ Works!

Why It Works

Without a prototype, there's no inherited __proto__ getter/setter. Now __proto__ is treated as a regular data property!

Side Effect: No Built-in Methods

let obj = Object.create(null);

alert(obj); // Error! No toString method

// But Object.keys still works (it's not on the prototype):
alert(Object.keys(obj)); // [] ✅

Summary
Everything you need to remember about Prototype Methods & Pure Dictionaries

Modern Methods

  • Object.create(proto, descriptors) — create with prototype + flags
  • Object.getPrototypeOf(obj) — read prototype
  • Object.setPrototypeOf(obj, proto) — change prototype (slow!)
  • Use { __proto__: ... } only in literals

Safe Dictionaries

  • Plain objects risk __proto__ bugs with user keys
  • Map is the safest for arbitrary key/value pairs
  • Object.create(null) creates "pure" dictionaries
  • Pure dictionaries lack toString but work with Object.keys
