The Problem: Arbitrary Arguments
JavaScript functions can accept any number of arguments — but how do we catch them all?

The Issue

Many built-in JS functions accept any number of arguments: Math.max(arg1, arg2, ..., argN). But a regular function only uses what's defined:

Extra Arguments Are Lost

function sum(a, b) {
  return a + b;
}

sum(1, 2, 3, 4, 5);
// Only 1 + 2 = 3 ❌
// 3, 4, 5 are ignored!

Solution: Rest Parameters

function sumAll(...args) {
  let sum = 0;
  for (let arg of args) sum += arg;
  return sum;
}

sumAll(1); // 1
sumAll(1,2,3); // 6 ✅
The ... (three dots) gather the remaining parameters into a real Array. You can loop over it, use .map(), .reduce(), and all other array methods.

Rest Parameters Deep Dive
Gathering specific variables first, then the rest

Partial Gathering

You don't have to gather everything. You can define the first few parameters as normal variables, and gather only the remaining ones:

function showName(firstName, lastName, ...titles) {
  console.log(firstName + ' ' + lastName);
  // titles = ["Consul", "Imperator"]
  console.log(titles[0]); // Consul
  console.log(titles.length); // 2
}

showName("Julius", "Caesar", "Consul", "Imperator");
Important Rule: Rest parameters must be at the very end. The following causes an error:
function f(arg1, ...rest, arg2) { // ❌ Error!
  // arg2 after ...rest makes no sense
  // ...rest already gathers EVERYTHING remaining
}
Real-World Analogy

At a checkout counter: "I'll pay for the TV with this gift card (firstName), that item with cash (lastName), and put everything else on my credit card (...titles)." The "rest" must be last because you're grouping all remaining items.

The Old Way: "arguments" Variable
Before rest parameters existed, this was the only option

What is arguments?

Every regular function has a special arguments object that holds all passed arguments. It works, but it has major downsides.

function showName() {
  console.log(arguments.length);
  console.log(arguments[0]);
  console.log(arguments[1]);
}

showName("Julius", "Caesar");
// 2, "Julius", "Caesar"

Problems with arguments

  • Not a real array — it's "array-like". No .map(), .reduce(), etc.
  • Captures ALL arguments — can't partially capture like rest params.
  • Arrow functions don't have it — accessing arguments in an arrow function grabs it from the outer normal function.

Why Rest is Better

  • Real Array — supports all array methods.
  • Partial capture — (a, b, ...rest) works cleanly.
  • Works everywhere — including arrow functions.
Best Practice: Use ...rest parameters in modern code. Only use arguments when reading old codebases.

Spread Syntax
The exact opposite of Rest — expanding an array into individual items

The Problem Spread Solves

Math.max() expects individual numbers: Math.max(3, 5, 1). Passing an array directly fails!

Without Spread

let arr = [3, 5, 1];

Math.max(arr);
// NaN ❌
// Expects numbers, got an array

With Spread

let arr = [3, 5, 1];

Math.max(...arr);
// 5 ✅
// Same as Math.max(3, 5, 1)

Spread is Flexible

// Multiple arrays
let arr1 = [1, -2, 3];
let arr2 = [8, 3, -8];

Math.max(...arr1, ...arr2); // 8

// Mix with normal values
Math.max(1, ...arr1, 2, ...arr2, 25); // 25
Real-World Analogy

Opening a bag of candy: You can't give the whole bag to someone who wants individual pieces. ...arr opens the bag and spreads the candies out individually so they can be picked one by one.

Spread Use Cases
Merging arrays, converting strings, and more

Merging Arrays

let arr1 = [3, 5, 1];
let arr2 = [8, 9, 15];

let merged = [0, ...arr1, 2, ...arr2];

// [0, 3, 5, 1, 2, 8, 9, 15]

String to Array

let str = "Hello";

[...str];
// ["H", "e", "l", "l", "o"]

Spread vs Array.from

Both convert iterables to arrays, but there's a key difference:

Method Iterables Array-likes
[...obj] ✅ Yes ❌ No
Array.from() ✅ Yes ✅ Yes
// Array-like (has .length)
let arrayLike = {
  0: "a", 1: "b",
  length: 2
};

Array.from(arrayLike); // ✅
[...arrayLike]; // ❌ Error
Rule of thumb: Use [...obj] when you know it's an iterable (array, string, map, set). Use Array.from() when dealing with array-like objects (e.g., DOM collections).

Copying Arrays & Objects
Using spread to create independent copies (shallow clones)

Copying an Array

let arr = [1, 2, 3];
let arrCopy = [...arr];

// Same contents?
JSON.stringify(arr) ===
  JSON.stringify(arrCopy); // true

// Same reference?
arr === arrCopy; // false ✅

arr.push(4);
// arr = [1,2,3,4]
// arrCopy = [1,2,3] ← unchanged!

Copying an Object

let obj = { a: 1, b: 2, c: 3 };
let objCopy = { ...obj };

// Same contents?
JSON.stringify(obj) ===
  JSON.stringify(objCopy); // true

// Same reference?
obj === objCopy; // false ✅

obj.d = 4;
// obj = {a:1,b:2,c:3,d:4}
// objCopy = {a:1,b:2,c:3} ← safe!
Real-World Analogy

Photocopying a document: You and a friend each have a copy. If your friend scribbles on theirs, your copy stays clean. arr === arrCopy is false because they're two separate pieces of paper, not the same one.

Shorter than Object.assign({}, obj): Spread syntax does the same thing with less code. That's why it's the preferred way to create shallow copies of arrays and objects.

Summary: Rest vs Spread
Same syntax, opposite purposes — here's how to tell them apart

The Key Difference

Both use ... but do completely opposite things. The difference is where they appear:

REST Gathers → Array

Items → One Group

Appears in: Function definition (parameters)

function sum(...args) {
  // args = [1, 2, 3]
  return args.reduce(
    (a,b) => a+b, 0
  );
}
sum(1, 2, 3); // 6

SPREAD Array → Items

One Group → Items

Appears in: Function call or array literal

let arr = [1, 2, 3];

Math.max(...arr);
// Same as: max(1, 2, 3)
// Returns 3

Key Takeaways

  • Rest ...args — gathers remaining arguments into an array
  • Must be the last parameter in function definition
  • Creates a real array with all methods
  • Spread ...arr — expands an iterable into individual values
  • Great for merging, copying, and passing arrays
  • Works on any iterable (arrays, strings, sets)
  • Old arguments — avoid in modern code
  • Not a real array, no partial capture
  • Arrow functions don't have it
