The new Function Syntax
Creating functions dynamically from strings at runtime

How It Works

There's one more way to create a function. It's rarely used, but sometimes there's no alternative. The function is created literally from a string passed at runtime.

let func = new Function([arg1, arg2, ...argN], functionBody);

With Arguments

let sum = new Function('a', 'b', 'return a + b');

alert( sum(1, 2) ); // 3

Without Arguments

let sayHi = new Function('alert("Hello")');

sayHi(); // Hello

Historical Syntax

For historical reasons, arguments can also be given as a comma-separated list. These three declarations mean the same:

new Function('a', 'b', 'return a + b'); // basic syntax
new Function('a,b', 'return a + b'); // comma-separated
new Function('a , b', 'return a + b'); // comma-separated with spaces
Key Use Case: Receiving code from a server dynamically. Example: let str = ... receive code from server ...; let func = new Function(str); func();

The Closure Quirk of new Function
Why functions created this way can't see outer variables

Global Scope Only

Usually, a function remembers where it was born via [[Environment]]. But new Function sets its [[Environment]] to reference the global Lexical Environment, not the current one. So, it can't access outer variables!

new Function (Error)

function getFunc() {
  let value = "test";

  let func = new Function('alert(value)');

  return func;
}

getFunc()(); // Error: value is not defined

It looks in the global scope, not inside getFunc.

Regular Function (Works)

function getFunc() {
  let value = "test";

  let func = function() { alert(value); };

  return func;
}

getFunc()(); // "test"

Remembers the Lexical Environment of getFunc.

Real-World Analogy

Remote Worker: A regular function is like an employee who works in your office — they can see the whiteboards on the walls (outer variables). An employee created via new Function is like a remote contractor who only has access to the public company website (global scope) and whatever you explicitly send them in an email (arguments).

Why This Quirk Exists
The minifier problem and why this is actually a good thing

The Minifier Problem

Before JavaScript goes to production, it's compressed by a minifier — a tool that removes spaces, comments, and renames local variables to shorter names (e.g., userName → a).

1
You write: let userName = "John";
2
Minifier changes it to: let a = "John"; (safe, because it's local)
3
Problem: If new Function could access outer variables, the string 'alert(userName)' would break because userName no longer exists — it's now a!
Architectural Note: Even without minifiers, relying on outer variables from a dynamically created string is error-prone and bad practice. Explicit is always better!

The Solution: Pass as Arguments

function getFunc() {
  let value = "test";

  // Pass value explicitly as an argument
  let func = new Function('val', 'alert(val)');

  return () => func(value); // Pass it when calling
}

getFunc()(); // "test" ✅ Works perfectly!
Summary of new Function: Functions created with new Function have [[Environment]] referencing the global Lexical Environment. They cannot use outer variables. This is actually good — it prevents errors with minifiers and enforces better architecture by forcing you to pass data explicitly via arguments.

Scheduling: setTimeout
Running a function once after a delay

Basic Syntax

setTimeout allows us to run a function once after a specified interval of time.

let timerId = setTimeout(func|code, [delay], [arg1], [arg2], ...)

Simple Example

function sayHi() {
  alert('Hello');
}

setTimeout(sayHi, 1000); // Runs after 1 second

With Arguments

function sayHi(phrase, who) {
  alert( phrase + ', ' + who );
}

setTimeout(sayHi, 1000, "Hello", "John");
// Hello, John (after 1 sec)
Common Mistake: Novice developers sometimes add brackets () after the function. This runs the function immediately and passes undefined (or the return value) to setTimeout!
// WRONG! Runs sayHi immediately:
setTimeout(sayHi(), 1000);

// CORRECT! Passes the function reference:
setTimeout(sayHi, 1000); // or
setTimeout(() => sayHi(), 1000);
Real-World Analogy

Kitchen Timer: You put pasta in the water and set a timer for 8 minutes. When 8 minutes pass, the timer rings (the function runs). You only want it to ring once.

Canceling Timers & setInterval
Stopping a scheduled call and running code repeatedly

Canceling with clearTimeout

A call to setTimeout returns a "timer identifier". Use it to cancel!

let timerId = setTimeout(
  () => alert("never happens"), 1000
);

clearTimeout(timerId);
// Canceled! Nothing happens.

setInterval

Same syntax as setTimeout, but runs the function repeatedly after the given interval.

// Repeat every 2 seconds
let timerId = setInterval(
  () => alert('tick'), 2000
);

// Stop after 5 seconds
setTimeout(() => {
  clearInterval(timerId);
  alert('stop');
}, 5000);
Note: In most browsers, the internal timer continues "ticking" while showing alert. If you don't dismiss the alert quickly, the next interval will fire immediately after you close it.
Real-World Analogy

Snooze Button: setInterval is like a recurring alarm that goes off every 5 minutes until you explicitly cancel it (clearInterval). clearTimeout is like turning off the oven timer before it goes off because you took the cake out early.

Nested setTimeout
A more flexible alternative to setInterval

Self-Scheduling Functions

Instead of setInterval, we can schedule the next call at the end of the current one. This is more flexible because we can change the delay dynamically!

// Instead of: setInterval(() => alert('tick'), 2000);

let timerId = setTimeout(function tick() {
  alert('tick');
  timerId = setTimeout(tick, 2000); // (*) Schedule next
}, 2000);

Practical Example: Dynamic Delay

If the server is overloaded, increase the polling interval (5s → 10s → 20s → 40s):

let delay = 5000;

let timerId = setTimeout(function request() {
  // ...send request...

  if (request failed due to server overload) {
    delay *= 2; // Increase interval!
  }

  timerId = setTimeout(request, delay);
}, delay);
Real-World Analogy

Doctor's Follow-up: With setInterval, you book appointments every 2 weeks forever, even if you're healthy. With nested setTimeout, at each visit the doctor decides: "Come back in 2 weeks" or "You need more recovery, come back in 4 weeks." The schedule adapts.

Timing Precision: setInterval vs Nested setTimeout
Why nested setTimeout guarantees a minimum delay between executions

The Execution Time Problem

With setInterval, the real delay between calls is shorter than what you set, because the time the function takes to run "consumes" part of the interval.

setInterval

10ms
func() ~7ms
3ms gap
func() ~7ms

The engine waits for func to complete, then checks if the time is up. If so, it runs immediately. In extreme cases, calls happen with no pause at all.

Nested setTimeout

10ms
func() ~7ms
10ms
func()

A new call is planned at the end of the previous one. This ensures the delay is between executions, not from start to start. More precise!

// setInterval: delay is from START to START
let i = 1;
setInterval(function() { func(i++); }, 100);

// Nested setTimeout: delay is from END to START
let i = 1;
setTimeout(function run() {
  func(i++);
  setTimeout(run, 100);
}, 100);

Garbage Collection & Zero Delay
Memory leaks with timers and the special setTimeout(func, 0)

GC and Timers

When a function is passed to setInterval/setTimeout, an internal reference is created and saved in the scheduler. This prevents the function from being garbage collected, even if there are no other references to it.

// The function stays in memory until the scheduler calls it
setTimeout(function() {...}, 100);

// For setInterval, it stays until clearInterval is called!
// Side effect: outer variables also stay alive.
Best Practice: When you don't need the scheduled function anymore, cancel it with clearTimeout/clearInterval, even if it's very small. Otherwise, it might hold onto large outer variables in memory!

Zero Delay setTimeout

setTimeout(func, 0) (or just setTimeout(func)) schedules the function to run "as soon as possible", but after the current script is complete.

setTimeout(() => alert("World"));

alert("Hello");

// Output: "Hello" first, then "World"
// The scheduler only "checks the calendar" after the current script ends.
Browser Limit: In the browser, after five nested timers, the interval is forced to be at least 4 milliseconds. So zero delay is not actually zero in practice for deeply nested calls.

Summary
Everything you need to remember about new Function & Scheduling

new Function

  • Creates a function from a string at runtime
  • [[Environment]] references the global scope, not outer
  • Cannot access outer variables (by design!)
  • Pass data explicitly via arguments
  • This prevents issues with minifiers

Scheduling

  • setTimeout: Run once after delay
  • setInterval: Run repeatedly
  • Use clearTimeout/clearInterval to cancel
  • Don't add () when passing functions!
  • Nested setTimeout is more flexible & precise
