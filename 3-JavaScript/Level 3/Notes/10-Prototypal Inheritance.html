How objects borrow features from other objects, sharing methods without duplicating code.
Real-World Analogy

Prototypal inheritance is like family traits. You have your own unique qualities (own properties), but you also inherit traits from your parents (prototype). If someone asks you a skill you don't have, you check if your parents have it.

The [[Prototype]] Link
The hidden property that connects objects together

What is it?

Every JavaScript object has a special hidden property called [[Prototype]]. It's either null or references another object. When you try to read a property that's missing, JavaScript automatically looks for it in the prototype.

let animal = {
  eats: true
};

let rabbit = {
  jumps: true,
  __proto__: animal // Sets rabbit.[[Prototype]] = animal
};

alert(rabbit.jumps); // true (own property)
alert(rabbit.eats); // true (inherited from animal!)

__proto__ vs [[Prototype]]

__proto__ is a historical getter/setter for the internal [[Prototype]]. Modern code prefers Object.getPrototypeOf() / Object.setPrototypeOf(), but __proto__ is more intuitive for learning.

Real-World Analogy

Asking Parents: If you have your own car (own property), you use it. If you don't, you ask your parents if they have one you can borrow (prototype lookup). rabbit doesn't have eats, so it checks animal.

The Prototype Chain
Multi-level inheritance and its limitations

Chain Reactions

If a property isn't found on the object, JavaScript checks its prototype, and then the prototype's prototype, until it reaches null.

let animal = { eats: true, walk() { alert("Animal walk"); } };

let rabbit = { jumps: true, __proto__: animal };

let longEar = { earLength: 10, __proto__: rabbit };

longEar.walk(); // "Animal walk" (found in animal)
alert(longEar.jumps); // true (found in rabbit)

Limitations

  • No circles: JavaScript will throw an error if you try to assign __proto__ in a loop.
  • Only one parent: An object can only have one [[Prototype]]. No multiple inheritance.
  • Object or null only: The value of __proto__ can only be an object or null. Other types are ignored.
Real-World Analogy

Family Tree: If you don't know a recipe, you ask your mom. If she doesn't know, she asks her mom (your grandmother). The search goes up the family tree until someone knows or the tree ends.

Writing Doesn't Use Prototype
Reads go up the chain, writes stay local

The Write Rule

Prototypes are only used for reading properties. Write and delete operations work directly on the object itself.

let animal = {
  eats: true,
  walk() { /* Animal walk */ }
};

let rabbit = { __proto__: animal };

// This adds rabbit's OWN walk method, doesn't change animal
rabbit.walk = function() {
  alert("Rabbit! Bounce-bounce!");
};

rabbit.walk(); // "Rabbit! Bounce-bounce!" (found locally)
Why? Imagine if writing rabbit.eats = false changed animal.eats! All animals would suddenly stop eating. Write operations must only affect the current object, never the prototype.
Real-World Analogy

Family Cookbook: Reading a recipe from the family cookbook (prototype) is fine. But if you want to modify a recipe, you write it in your own personal notebook (own property). You don't scribble in the family book!

The Accessor Exception
Setters are triggered even when writing to an inherited property

Why Setters Work

We said writes don't use the prototype. But there's an exception: accessor properties. If a property has a setter in the prototype, assigning to it calls that setter function.

let user = {
  name: "John", surname: "Smith",
  set fullName(value) { [this.name, this.surname] = value.split(" "); },
  get fullName() { return `${this.name} ${this.surname}`; }
};

let admin = { __proto__: user, isAdmin: true };

alert(admin.fullName); // John Smith (getter from user)

// Calls the setter! But what does 'this' refer to?
admin.fullName = "Alice Cooper";

alert(admin.fullName); // Alice Cooper (admin modified)
alert(user.fullName); // John Smith (user protected!)
The Magic: The setter is called, but it writes to this.name and this.surname. Because this is admin (not user), the properties are created on admin. The prototype user stays untouched!

The Value of this
Shared methods, independent state

No Matter Where Found

No matter where a method is found — in the object or its prototype — this is always the object before the dot. This ensures inherited methods modify the correct object's state.

let animal = {
  walk() {
    if (!this.isSleeping) alert(`I walk`);
  },
  sleep() {
    this.isSleeping = true;
  }
};

let rabbit = { name: "White Rabbit", __proto__: animal };

// modifies rabbit.isSleeping, NOT animal.isSleeping
rabbit.sleep();

alert(rabbit.isSleeping); // true
alert(animal.isSleeping); // undefined
Shared Methods, Separate State: Multiple objects can inherit the same methods (saving memory), but when those methods write data using this, the data is stored on the individual object. No cross-contamination!
Real-World Analogy

Communal Kitchen: You and your roommates share a kitchen (the methods). But when you cook a meal (set a property), you put it in your own fridge (this = you). You don't put your food in someone else's fridge.

The for...in Loop
How iteration handles inherited properties

Inherited Properties Show Up

The for..in loop iterates over both own and inherited properties. Other methods like Object.keys and Object.values ignore inherited properties.

for..in (includes inherited)

for(let prop in rabbit) {
  alert(prop); // jumps, eats
}

Object.keys (own only)

alert(Object.keys(rabbit));
// ["jumps"] (no eats!)

Filtering with hasOwnProperty

for(let prop in rabbit) {
  let isOwn = rabbit.hasOwnProperty(prop);

  if (isOwn) {
    alert(`Our: ${prop}`); // Our: jumps
  } else {
    alert(`Inherited: ${prop}`); // Inherited: eats
  }
}
Where does hasOwnProperty come from? It's inherited from Object.prototype.hasOwnProperty. But why doesn't it show up in for..in? Because it has enumerable: false! All Object.prototype properties are non-enumerable, so for..in skips them.

Summary
Everything you need to remember about Prototypal Inheritance

Core Rules

  • Objects have a hidden [[Prototype]] property
  • Use __proto__ to set it (or Object.setPrototypeOf)
  • Reads traverse the prototype chain
  • Writes act directly on the object (except setters)
  • this is always the object before the dot

Iteration

  • for..in includes inherited properties
  • Object.keys/values ignore inherited
  • Use hasOwnProperty to filter
  • Object.prototype properties are non-enumerable
  • Chain limit: no circles, single parent only
