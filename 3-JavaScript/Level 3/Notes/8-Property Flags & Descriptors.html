An object property is like a document in a filing cabinet. Usually, you can edit it, find it in the index, or throw it away. But with property flags, you can make it read-only (writable), hidden from the index (enumerable), or permanently locked in place (configurable).

The Three Property Flags
Every property has three hidden switches that control its behavior

Beyond Key-Value

Until now, a property was just a "key-value" pair. But an object property actually has three special attributes (flags) that control what you can do with it.

writable

If true, the value can be changed. If false, the property is read-only.

enumerable

If true, the property shows up in loops like for..in and Object.keys(). If false, it's hidden from those loops.

configurable

If true, the property can be deleted and its flags can be modified. If false, it's a one-way lock — you can't delete it or change its flags.

Default Behavior: When you create a property the "usual way" (e.g., let user = { name: "John" }), all three flags are true. You only need to change them when you want to restrict access.

Getting & Setting Descriptors
How to inspect and modify the hidden flags

Getting Flags

The method Object.getOwnPropertyDescriptor lets you query the full information about a property.

let user = { name: "John" };

let descriptor = Object.getOwnPropertyDescriptor(user, 'name');

alert(JSON.stringify(descriptor, null, 2));
/* {
  "value": "John",
  "writable": true,
  "enumerable": true,
  "configurable": true
} */

Setting Flags

The method Object.defineProperty lets you change the flags (or create a new property with specific flags).

Object.defineProperty(obj, propertyName, descriptor)
Important Gotcha: If you use defineProperty to create a new property and don't specify a flag, it defaults to false! This is the opposite of normal property creation.
let user = {};

Object.defineProperty(user, "name", {
  value: "John"
});

let desc = Object.getOwnPropertyDescriptor(user, 'name');
// writable: false, enumerable: false, configurable: false
3 / 10
Non-Writable
Making a property read-only

Setting writable: false

When writable is false, nobody can change the value of the property — it becomes read-only.

let user = { name: "John" };

Object.defineProperty(user, "name", {
  writable: false
});

user.name = "Pete"; // Error: Cannot assign to read only property 'name'
Strict Mode: Errors only appear in strict mode. In non-strict mode, the assignment simply fails silently — no error, but the value doesn't change.

Creating from Scratch

If you create a new property with defineProperty, you must explicitly set the flags you want to be true:

let user = {};

Object.defineProperty(user, "name", {
  value: "John",
  writable: false, // Read-only
  enumerable: true, // Must specify true!
  configurable: true // Must specify true!
});

user.name = "Pete"; // Error
Real-World Analogy

Museum Exhibit: A normal property is like a whiteboard — anyone can erase and rewrite it. A writable: false property is like a museum exhibit plaque — you can read it, but you can't draw on it.

4 / 10
Non-Enumerable
Hiding properties from loops and key listings

Setting enumerable: false

When enumerable is false, the property becomes invisible to for..in and Object.keys(). It still exists and can be accessed directly!

Without the Flag (Default)

let user = {
  name: "John",
  toString() {
    return this.name;
  }
};

for (let key in user) alert(key);
// name, toString

With enumerable: false

Object.defineProperty(user, "toString", {
  enumerable: false
});

for (let key in user) alert(key);
// name (toString hidden!)

Object.keys(user); // ["name"]
Why does this matter? Built-in methods like toString on normal objects are non-enumerable by default. This ensures they don't clutter up your loops. If you add a custom method, you probably want to make it non-enumerable too, so it behaves like the built-in ones.
Real-World Analogy

Staff-Only Door: A non-enumerable property is like a door that doesn't appear on the visitor's map (the loop). It still exists, and if you know the exact room number (property name), you can walk right in and use it. It's just hidden from the general tour.

5 / 10
Non-Configurable
The one-way street of property attributes

Setting configurable: false

This is the most restrictive flag. It prevents the property from being deleted and prevents its flags from being changed. It's a one-way road — once set, you can't go back!

let descriptor = Object.getOwnPropertyDescriptor(Math, 'PI');

/* {
  value: 3.141592653589793,
  writable: false,
  enumerable: false,
  configurable: false
} */

Math.PI = 3; // Error (writable: false)
delete Math.PI; // Error (configurable: false)
Object.defineProperty(Math, "PI", { writable: true }); // Error!

The One Exception

There is one minor exception: for a non-configurable property, you can change writable: true to false (adding another layer of protection). But you cannot change writable: false to true.

Real-World Analogy

Super Glue: Setting configurable: false is like super-gluing a vase to a shelf. You can't remove it, you can't move it, and you can't un-glue it. The only thing you're still allowed to do (if it wasn't locked) is to put a glass cover over it (writable: true → false).

6 / 10
The "Forever Sealed" Constant
Combining non-writable and non-configurable for ultimate protection

Maximum Lockdown

If you combine writable: false and configurable: false, you create a "forever sealed" constant — just like the built-in Math.PI.

let user = { name: "John" };

Object.defineProperty(user, "name", {
  writable: false,
  configurable: false
});

// None of these will work:
user.name = "Pete"; // Error (writable: false)
delete user.name; // Error (configurable: false)
Object.defineProperty(user, "name", { value: "Pete" }); // Error

Configurable but Writable

It's worth noting: if a property is non-configurable but still writable, you can change its value. You just can't delete it or change its flags.

Object.defineProperty(user, "name", {
  configurable: false
});

user.name = "Pete"; // Works fine! Value can change.
delete user.name; // Error! Can't delete.

Define Multiple & Smart Cloning
Working with many properties at once and cloning with flags intact

Object.defineProperties

Define many properties at once:

Object.defineProperties(user, {
  name: { value: "John", writable: false },
  surname: { value: "Smith", writable: false },
  // ...
});

Object.getOwnPropertyDescriptors

Get all descriptors at once. Together with defineProperties, you can make a "flag-aware" clone:

let clone = Object.defineProperties({}, Object.getOwnPropertyDescriptors(obj));

Why is this better?

Old Way (for..in)

for (let key in user) {
  clone[key] = user[key];
}

❌ Doesn't copy flags
❌ Ignores Symbol properties
❌ Ignores non-enumerable properties

Smart Way (Descriptors)

let clone = Object.defineProperties({},
  Object.getOwnPropertyDescriptors(obj)
);

✅ Copies all flags
✅ Includes Symbol properties
✅ Includes non-enumerable properties

Sealing Objects Globally
Locking down the entire object instead of individual properties

Three Levels of Lockdown

Instead of setting flags on individual properties, you can apply restrictions to the whole object at once.

Method What it does Analogy
Object.preventExtensions(obj) Forbids adding new properties Hotel at full capacity — no new guests
Object.seal(obj) Forbids adding/removing. Sets configurable: false for all Sealed shipping box — can't add or remove items
Object.freeze(obj) Forbids adding/removing/changing. Sets configurable: false, writable: false for all Frozen in ice — nothing changes at all

Test Methods

Each lockdown method has a corresponding test to check the object's state:

  • Object.isExtensible(obj) → Returns false if adding properties is forbidden
  • Object.isSealed(obj) → Returns true if adding/removing is forbidden and all properties have configurable: false
  • Object.isFrozen(obj) → Returns true if adding/removing/changing is forbidden and all properties have configurable: false and writable: false
Real-World Analogy

Building Security: preventExtensions locks the front door (no new tenants). seal also locks the exit doors (no tenants can leave). freeze locks all doors and glues all furniture to the floor (nobody can change anything).

Summary
Everything you need to remember about Property Flags & Descriptors

The Three Flags

  • writable – Can the value be changed?
  • enumerable – Is it visible in loops?
  • configurable – Can it be deleted or have flags changed?

Key Methods

  • Object.getOwnPropertyDescriptor – Get flags
  • Object.defineProperty – Set flags (new props default to false!)
  • Object.defineProperties – Set multiple
  • Object.getOwnPropertyDescriptors – Smart cloning
