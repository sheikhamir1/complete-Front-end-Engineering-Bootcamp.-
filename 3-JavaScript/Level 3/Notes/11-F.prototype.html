The Big Idea
How F.prototype connects constructors to inheritance

The Rule

When we create an object with new F(), the new operator sets the new object's [[Prototype]] to whatever is in F.prototype.

let animal = {
  eats: true
};

function Rabbit(name) {
  this.name = name;
}

Rabbit.prototype = animal; // "When new Rabbit is made, use animal as prototype"

let rabbit = new Rabbit("White Rabbit");

alert(rabbit.eats); // true (inherited from animal!)
Translation: Rabbit.prototype = animal means "Every new rabbit created from this constructor will inherit from animal." It's a one-time template assignment.
Real-World Analogy

Factory Blueprint: A car factory (Rabbit) has a blueprint (Rabbit.prototype). Every car that rolls off the assembly line (new Rabbit()) follows that blueprint. If the blueprint says "all cars have airbags" (eats: true), every car gets airbags.

Don't Confuse the Two
F.prototype vs [[Prototype]] — they are completely different things!

Two Completely Different Concepts

This is one of the most common sources of confusion in JavaScript. Let's clear it up once and for all.

Aspect F.prototype [[Prototype]]
What is it? A regular property on a function A hidden internal property on objects
Where does it live? On the constructor function (Rabbit.prototype) On every object (rabbit.__proto__)
What does it do? Acts as a template for new objects Links an object to its prototype for property lookup
When is it used? Only at new F() time Every time you read a property
Analogy The cookie cutter shape The cookie's family recipe link
Common Mistake: People often think F.prototype is the prototype of F. It's not! It's the prototype of objects created by new F(). On regular non-function objects, a property named prototype is just a regular property with no special meaning.
let user = {
  name: "John",
  prototype: "Bla-bla" // No magic at all! Just a regular property.
};

Only Used at new F() Time
Changing the prototype later doesn't affect existing objects

The Snapshot Effect

F.prototype is only read when new F() is called. The new object gets a snapshot of whatever F.prototype points to at that moment. Changing F.prototype afterwards only affects future objects.

function Rabbit(name) {
  this.name = name;
}

Rabbit.prototype = { eats: true }; // First template

let rabbit1 = new Rabbit("White"); // Gets animal as prototype

Rabbit.prototype = { jumps: true }; // Changed template!

let rabbit2 = new Rabbit("Black"); // Gets new prototype

alert(rabbit1.eats); // true (old prototype)
alert(rabbit1.jumps); // undefined (old prototype)
alert(rabbit2.jumps); // true (new prototype)
alert(rabbit2.eats); // undefined (new prototype)
Real-World Analogy

University Curriculum: If you enroll in 2023, you follow the 2023 curriculum. If the university changes the curriculum in 2024, new students follow the new one, but you still follow the 2023 version. Your [[Prototype]] was "photographed" at enrollment time.

Default F.prototype
Every function already has a prototype — with a constructor inside

What's There by Default?

We don't need to set F.prototype manually. Every function in JavaScript automatically gets a prototype property — an object with a single property called constructor that points back to the function itself.

function Rabbit() {}

// Default behind the scenes:
// Rabbit.prototype = { constructor: Rabbit }

alert(Rabbit.prototype.constructor === Rabbit); // true

Inherited by New Objects

Because constructor lives on Rabbit.prototype, it's inherited by every rabbit created with new Rabbit():

let rabbit = new Rabbit();

alert(rabbit.constructor === Rabbit); // true (from prototype)
Real-World Analogy

"Made in" Label: Every product from a factory comes with a "Made by Acme Corp" label (constructor). The factory doesn't stamp each product individually — it's built into the template. You can always trace back which factory made the product.

Using the constructor Property
Creating new objects of the same type without knowing the original constructor

Why Does This Matter?

If we have an object but don't know which constructor made it (e.g., it came from a library), we can use constructor to create another one of the same type.

function Rabbit(name) {
  this.name = name;
}

let rabbit = new Rabbit("White Rabbit");

// We don't know Rabbit directly, but we have rabbit:
let rabbit2 = new rabbit.constructor("Black Rabbit");

alert(rabbit2.name); // Black Rabbit
alert(rabbit2 instanceof Rabbit); // true
Practical Use: Imagine receiving an object from a third-party library. You want to create another object of the same type. Instead of digging through the library's documentation, just use new obj.constructor().
Real-World Analogy

Returning to the Same Builder: You bought a house from a builder but lost their contact info. However, the house has a "Built by ABC Construction" plaque (constructor) on it. You look up ABC Construction and hire them to build your next house too.

Losing the Constructor
The danger of overwriting F.prototype entirely

The Problem

JavaScript doesn't guarantee the constructor property stays correct. If we replace the default prototype as a whole, the constructor is lost!

Overwriting (Loses constructor)

function Rabbit() {}

Rabbit.prototype = {
  jumps: true
};

let rabbit = new Rabbit();

alert(rabbit.constructor === Rabbit);
// false! Lost!

Fix 1: Add Properties Instead

function Rabbit() {}

// Don't overwrite, just add:
Rabbit.prototype.jumps = true;

let rabbit = new Rabbit();

alert(rabbit.constructor === Rabbit);
// true ✅ Preserved!

Fix 2: Recreate the Constructor Manually

If you must overwrite, add the constructor back yourself:

Rabbit.prototype = {
  jumps: true,
  constructor: Rabbit // Add it back!
};

// Now rabbit.constructor === Rabbit is true again ✅
Remember: JavaScript itself does not ensure the right constructor value. It exists in the default prototype, but what happens with it later is totally on us.

Summary
Everything you need to remember about F.prototype

Key Rules

  • F.prototype is a regular property on constructor functions
  • It sets [[Prototype]] for objects created with new F()
  • Only used at creation time — changes don't affect existing objects
  • Must be an object or null; other values are ignored
  • Only works with new — regular objects with prototype property have no magic

The Constructor Property

  • Default F.prototype = { constructor: F }
  • Inherited by all objects made from F
  • Useful for creating new objects of the same type
  • Overwriting F.prototype loses constructor
  • Fix: add properties individually or recreate constructor
