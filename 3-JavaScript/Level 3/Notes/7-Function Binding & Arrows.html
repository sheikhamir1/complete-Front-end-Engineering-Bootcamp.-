Losing this
Why object methods break when passed as callbacks

The Problem

Once a method is passed somewhere separately from the object — like to setTimeout — this is lost.

let user = {
  firstName: "John",
  sayHi() {
    alert(`Hello, ${this.firstName}!`);
  }
};

setTimeout(user.sayHi, 1000); // Hello, undefined!

Why Does This Happen?

1
setTimeout gets the function user.sayHi separately from the object.
2
The last line is essentially like doing: let f = user.sayHi; setTimeout(f, 1000);
3
When setTimeout calls f(), it runs without an object, so this becomes undefined (or window in non-strict mode).
Real-World Analogy

Detached Car Engine: A car engine (sayHi) needs the car's battery (this.firstName) to start. If you take the engine out of the car and put it in a separate workshop (setTimeout), it can't find the battery anymore.

2 / 10
Solution 1: Wrapper Function
The simplest fix — but it comes with a vulnerability

The Fix

Wrap the call in an arrow function. It receives user from the outer lexical environment.

setTimeout(() => user.sayHi(), 1000);
// Hello, John! ✅

The Vulnerability

What if user changes before the timeout fires? The wrapper reads the current value!

setTimeout(() => user.sayHi(), 1000);

// ... within 1 second ...
user = { sayHi() { alert("Another!"); } };

// Output: "Another!" 😱
The Risk: With a wrapper, the function doesn't lock in the object. It looks up user at the time it actually runs, not when it was scheduled. If the variable changes, you get unexpected results.
Real-World Analogy

Looking at a Name Tag: The wrapper approach is like telling someone "Go look at the name tag on the desk." If someone swaps the name tag before they look, they read the wrong name. We need a way to permanently write the name down.

3 / 10
Solution 2: bind()
The bulletproof way to permanently fix this

The Syntax

Functions provide a built-in method bind that permanently fixes this.

let boundFunc = func.bind(context);

The Bulletproof Fix

let user = {
  firstName: "John",
  sayHi() { alert(`Hello, ${this.firstName}!`); }
};

let sayHi = user.sayHi.bind(user); // (*) Bind it!

setTimeout(sayHi, 1000); // Hello, John! ✅

// Even if user changes, sayHi uses the pre-bound object
user = { sayHi() { alert("Another!"); } };
// sayHi still says "Hello, John!"
How it works: func.bind(context) returns a special "exotic object" that is callable as a function and transparently passes the call to func with this=context. All arguments are passed "as is".
Real-World Analogy

Super Glue: If the wrapper approach is "go look at the name tag," bind() is like permanently engraving "John" onto the function. No matter what happens to the original user object later, the bound function always remembers its original context.

Partial Functions
Using bind() to pre-fill arguments, not just this

The Full bind Syntax

We can bind not only this, but also arguments. This creates a "partially applied" function — a new function with some parameters pre-set.

let bound = func.bind(context, [arg1], [arg2], ...);

Example: double

function mul(a, b) {
  return a * b;
}

let double = mul.bind(null, 2);

alert( double(3) ); // = mul(2, 3) = 6
alert( double(4) ); // = mul(2, 4) = 8
alert( double(5) ); // = mul(2, 5) = 10

Example: triple

let triple = mul.bind(null, 3);

alert( triple(3) ); // = mul(3, 3) = 9
alert( triple(4) ); // = mul(3, 4) = 12
alert( triple(< class="number">5) ); // = mul(3, 5) = 15

Practical Example

Imagine a generic send(from, to, text) function. Inside a user object, we can create a partial variant that always sends from the current user:

// We want: sendTo(to, text) that always sends from current user
let sendTo = send.bind(null, currentUser);
Real-World Analogy

Pre-set Oven: A partial function is like an oven with the temperature already dialed in to 350°F. You still need to put the food in (the remaining argument), but the first step (setting the temperature) is already done for you.

Going Partial Without Context
When you only want to bind arguments, not this

The Problem with Native bind

The native bind requires a context as the first argument. If we only want to bind arguments for an object method, we can't just skip this. We need a custom helper.

Custom partial Helper

function partial(func, ...argsBound) {
  return function(...args) { // (*)
    return func.call(this, ...argsBound, ...args);
  }
}

// Usage:
let user = {
  firstName: "John",
  say(time, phrase) {
    alert(`[${time}] ${this.firstName}: ${phrase}!`);
  }
};

// Add a partial method with fixed time
user.sayNow = partial(user.say, new Date().getHours() + ':' + new Date().getMinutes());

user.sayNow("Hello");
// [10:00] John: Hello!
How it works: The wrapper (*) gets the current this from the call (e.g., user), then calls func with that this, followed by the pre-bound args (...argsBound) and then the new args (...args).
Real-World Analogy

Pre-filled Form: It's like a partially filled-out form where the date is already stamped at the top. When you get the form, you fill in your name and details. The date was pre-filled (partial args), but the form still belongs to whoever is holding it (this).

Arrow Functions: No this
Arrows don't have their own this — they borrow it from the outside

The Key Feature

Arrow functions are not just shorthand. If this is accessed inside an arrow, it is taken from the outer lexical environment. This makes them perfect for callbacks inside object methods.

Arrow Function (Works)

let group = {
  title: "Our Group",
  students: ["John", "Pete"],

  showList() {
    this.students.forEach(
      student => alert(this.title + ': ' + student)
    );
  }
};
group.showList(); // ✅

Regular Function (Error)

let group = {
  title: "Our Group",
  students: ["John", "Pete"],

  showList() {
    this.students.forEach(function(student) {
      // Error: this.title is undefined
      alert(this.title + ': ' + student);
    });
  }
};
Real-World Analogy

Mirror vs. Window: A regular function has its own this — like a room with a mirror (you see yourself). An arrow function has no mirror, only a window — it looks outward into the next room to find this.

Arrow vs bind & No arguments
Understanding the subtle difference and why arrows have no arguments

Arrow vs .bind(this)

  • .bind(this) creates a "bound version" with a fixed this value.
  • => doesn't create any binding. The function simply doesn't have this. The lookup happens via the normal variable search in the outer lexical environment.

Arrows Have No arguments

Arrow functions don't have their own arguments object. This is great for decorators where we need to forward the outer function's arguments!

With Arrow (Clean)

function defer(f, ms) {
  return function() {
    setTimeout(() =>
      f.apply(this, arguments), ms);
  };
}

Without Arrow (Messy)

function defer(f, ms) {
  return function(...args) {
    let ctx = this; // save context
    setTimeout(function() {
      return f.apply(ctx, args);
    }, ms);
  };
}
Why it works: The arrow function in setTimeout doesn't have its own this or arguments, so it uses the this and arguments from the enclosing wrapper function. No extra variables needed!

Arrow Function Limitations
When NOT to use arrow functions

Things Arrows Cannot Do

Because arrow functions don't have their own context, they can't be used in situations that require this to be dynamically assigned.

Feature Arrow Function Regular Function
Has own this ❌ No (takes from outer) ✅ Yes
Has arguments ❌ No ✅ Yes
Can be called with new ❌ No (TypeError) ✅ Yes (constructors)
Has super ❌ No (covered later) ✅ Yes

Don't Use Arrows For:

  • Object methods: let obj = { sayHi: () => alert(this.name) } — this will be window or undefined, not obj.
  • Constructors: new (() => {}) — throws a TypeError.
  • Event handlers that need this: button.addEventListener('click', () => ...) — if you need this to be the button element.
Real-World Analogy

Single-Purpose Tool: Arrow functions are like a simple screwdriver — great for one job (callbacks), but you can't use them as a hammer (constructor) or a Swiss Army knife (methods that need their own this). For those, you need the full toolbox (regular functions).

Summary
Everything you need to remember about Function Binding & Arrows

Function Binding

  • Passing a method detached from its object loses this
  • Wrapper fixes it, but vulnerable to variable changes
  • bind(context) permanently fixes this
  • Partial application: bind(context, arg1, ...) pre-fills arguments
  • Custom partial() helper binds args but keeps this dynamic

Arrow Functions

  • Do not have their own this (borrow from outer)
  • Do not have arguments (great for forwarding)
  • Cannot be called with new
  • Not for object methods or constructors
  • Perfect for callbacks inside methods
