What is a Decorator?
A wrapper that alters or enhances a function's behavior without changing its code

Transparent Caching

Imagine a CPU-heavy function slow(x) that always returns the same result for the same input. Instead of modifying slow() to add caching, we create a decorator that wraps it.

function cachingDecorator(func) {
  let cache = new Map();

  return function(x) {
    if (cache.has(x)) { // If we've seen this input before
      return cache.get(x); // Return cached result
    }

    let result = func(x); // Otherwise, call the original
    cache.set(x, result); // And cache the result
    return result;
  };
}

slow = cachingDecorator(slow); // Wrap it!

Benefits of Separate Decorators

  • Reusable: Apply cachingDecorator to any function, not just slow.
  • Clean code: The main function stays simple; caching logic is separate.
  • Composable: Stack multiple decorators (e.g., caching + logging) if needed.
Real-World Analogy

Student's Notebook: A student solving math problems. The first time they see a problem, they work it out from scratch and write the answer in their notebook (cache). The next time they see the same problem, they just look at the notebook instead of doing the work again.

The Context Problem
Why decorators break object methods — losing this

When Decorators Fail

Our cachingDecorator works for standalone functions, but fails for object methods. Why? When the wrapper calls func(x), it loses the object context (this).

let worker = {
  someMethod() { return 1; },

  slow(x) {
    alert("Called with " + x);
    return x * this.someMethod(); // (*) Needs 'this'
  }
};

worker.slow = cachingDecorator(worker.slow);

worker.slow(2); // Error: Cannot read property 'someMethod' of undefined

What Went Wrong?

1
We call worker.slow(2). The wrapper gets this = worker and x = 2.
2
Inside the wrapper, it calls func(x). This is like doing let func = worker.slow; func(2);
3
When func runs without an object, this becomes undefined (in strict mode).
!
this.someMethod() fails because this is undefined.
Real-World Analogy

Car Engine: Imagine taking a car engine out of the car. The engine might try to access the car's battery (this.someMethod()), but since it's no longer inside the car, it can't find it. We need a way to tell the engine "you still belong to this car" when we run it.

func.call()
Setting the context explicitly when calling a function

The Syntax

JavaScript provides a built-in method to call a function while explicitly setting this.

func.call(context, arg1, arg2, ...)

Simple Context Example

function sayHi() {
  alert(this.name);
}

let user = { name: "John" };
let admin = { name: "Admin" };

sayHi.call(user); // John
sayHi.call(admin); // Admin

With Arguments

function say(phrase) {
  alert(this.name + ': ' + phrase);
}

let user = { name: "John" };

say.call(user, "Hello");
// John: Hello

Fixing the Decorator

Now we can fix cachingDecorator by using func.call(this, x) to pass the correct context:

function cachingDecorator(func) {
  let cache = new Map();
  return function(x) {
    if (cache.has(x)) return cache.get(x);

    let result = func.call(this, x); // "this" is passed correctly now!
    cache.set(x, result);
    return result;
  };
}

Going Multi-Argument
Handling multiple arguments with hashing and spread

Two Problems to Solve

Our decorator only works for single-argument functions. To handle multiple arguments like worker.slow(min, max), we need to fix caching and argument passing.

Problem 1: Cache Key

Map only accepts one key. For (3, 5), we need a single key like "3,5".

Solution: A hash function that combines arguments into one string.

function hash(args) {
  return args[0] + ',' + args[1];
}

Problem 2: Passing All Args

func.call(this, x) only passes one argument.

Solution: Use the special arguments object and spread syntax.

func.call(this, ...arguments);
// Passes ALL arguments along!

The Universal Decorator

function cachingDecorator(func, hash) {
  let cache = new Map();
  return function() {
    let key = hash(arguments); // (*) Create single key
    if (cache.has(key)) return cache.get(key);

    let result = func.call(this, ...arguments); // (**) Forward all args

    cache.set(key, result);
    return result;
  };
}
Real-World Analogy

Locker Combination: You can't open a locker with just one number when it requires two. The hash function is like combining (3, 5) into a single combo code "3,5" so the locker knows exactly which result to give you.

func.apply()
An alternative to call that accepts an array-like object of arguments

The Syntax

Instead of spreading arguments with call, we can use apply, which takes an array-like object as the second parameter.

func.apply(context, args)
Method Arguments Format Example
func.call List of arguments func.call(ctx, arg1, arg2, ...)
func.apply Array-like object func.apply(ctx, [arg1, arg2])
Performance Tip: These two calls are almost equivalent, but func.apply(this, arguments) is often slightly faster than func.call(this, ...arguments) because JavaScript engines internally optimize apply better for array-like objects.

Call Forwarding

Passing all arguments and the context to another function is called call forwarding. The simplest, most universal way to do it is with apply:

let wrapper = function() {
  return original.apply(this, arguments);
};

This makes the wrapper indistinguishable from the original function.

Method Borrowing
Taking a method from one object and using it on another

The Hash Function Problem

We want to improve our hash function to join any number of arguments. The natural solution is args.join(), but there's a catch!

Doesn't Work

function hash() {
  alert( arguments.join() );
  // Error: arguments.join is not a function
}

hash(1, 2);

arguments is array-like (has indices and length) but is not a real array, so it doesn't have array methods.

Method Borrowing

function hash() {
  alert( [].join.call(arguments) );
  // 1,2 ✅ Works!
}

hash(1, 2);

We borrow the .join() method from a real array and use call to run it on arguments.

Why Does This Work?

Internally, the native arr.join(glue) algorithm is very simple:

  1. Take this[0]
  2. Add glue + this[1]
  3. Add glue + this[2] ... until this.length

It only needs this to have indices and a .length — which arguments has! Many native array methods are intentionally written this way.

Real-World Analogy

Borrowing a Lawnmower: Your neighbor has a lawnmower. Your yard doesn't own one, but your yard has grass (indices) and a yard size (length). You borrow their mower and use it on your yard. The mower doesn't care whose yard it is, as long as there's grass to cut.

Decorators & Function Properties
One important caveat when replacing functions with wrappers

The Lost Properties Problem

If the original function had custom properties (like func.calledCount), the decorated wrapper will not have them. The wrapper is a brand new function object.

function slow(x) {
  return x;
}

slow.customProp = "I am original";

slow = cachingDecorator(slow);

alert(slow.customProp); // undefined
// The wrapper doesn't have the original's properties!
Important: Some decorators may provide their own properties (e.g., counting how many times the wrapper was called). But if you rely on the original function's properties, a simple wrapper will lose them.

The Solution: Proxy

There exists a way to create decorators that keep access to function properties, but it requires using a special Proxy object to wrap the function instead of a simple wrapper function. We'll cover this in a future chapter on Proxy and Reflect.

Real-World Analogy

Moving to a New House: When you move, you take your furniture (function logic) with you. But if you had sticky notes on the fridge (custom properties), they might not make it to the new fridge. A simple move loses them. A careful move (Proxy) would copy every sticky note perfectly.

Deep Dive: How this is Passed Along
Tracing the context through the decorator step by step

Step-by-Step Trace

Let's see exactly how func.call(this, x) preserves the context when we call worker.slow(2):

1
We call worker.slow(2)

After decoration, worker.slow is now the wrapper function. Because it's called as worker.slow, the wrapper receives this = worker and x = 2.

2
Wrapper checks the cache

Assuming it's a new call, the cache is empty. It needs to call the original function.

3
Wrapper calls func.call(this, x)

Here, this is worker and x is 2. So this becomes originalSlow.call(worker, 2). The original function now correctly gets this = worker!

4
Original function runs

Inside the original, this.someMethod() works because this points to worker as intended. The result is cached and returned.

Key Insight: Without .call(), step 3 would be just func(x). This is like calling originalSlow(2) without any object, making this = undefined. The .call(this, ...) pattern is what "forwards" the context properly.

Summary
Everything you need to remember about Decorators & Forwarding

Decorators

  • A wrapper that alters behavior without changing code
  • Reusable, keeps main code clean, composable
  • Lose original function's custom properties
  • Use Proxy to preserve properties (future topic)

call / apply

  • func.call(ctx, arg1, arg2...): list of args
  • func.apply(ctx, args): array-like args
  • Both set this explicitly
  • apply is often faster for forwarding
