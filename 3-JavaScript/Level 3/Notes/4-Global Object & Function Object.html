The Global Object
The universal container that holds variables and functions available anywhere

What is it?

The global object provides variables and functions available anywhere in your code. It holds built-in language features (like Array) and environment-specific values (like window.innerHeight).

In the Browser

The global object is called window.

alert("Hello");
// is exactly the same as:
window.alert("Hello");

In Node.js

The global object is called global.

// In Node.js terminal:
global.setTimeout(...);
// same as just setTimeout(...)

The Universal Name: globalThis

Recently, JavaScript introduced globalThis — a standardized name that works across all environments (browsers, Node.js, etc.). If your code might run outside a browser, prefer globalThis.

Real-World Analogy

Town Square: The global object is like the town square. A public bulletin board that everyone in the town (your script) can see and access. Different towns might call it "Plaza" (browser) or "Commons" (Node.js), but globalThis is like a universal GPS coordinate that always points to it.

Variables on the Global Object
Why var and let/const behave differently at the top level

var Goes Global

Variables declared with var (and Function Declarations) at the top level become properties of the global object.

var gVar = 5;

alert(window.gVar); // 5
Don't rely on this! This exists for old compatibility. Modern JavaScript modules don't do this.

let / const Stay Separate

Modern let and const do not become properties of the global object, even at the top level.

let gLet = 5;

alert(window.gLet); // undefined

Explicitly Adding to the Global Object

If a value truly needs to be global, write it directly as a property:

// Make current user info global for all scripts
window.currentUser = { name: "John" };

// Access it anywhere
alert(currentUser.name); // John

// Safe access if a local 'currentUser' variable exists
alert(window.currentUser.name); // John
Best Practice: Keep global variables to an absolute minimum. The code design where a function gets "input" and produces "outcome" is clearer, less prone to errors, and easier to test than if it uses global variables.

Using the Global Object for Polyfills
How we check for and add missing modern features

What is a Polyfill?

A polyfill is a piece of code that implements a feature that your browser/environment doesn't support natively. We use the global object to check if a feature exists and add it if it doesn't.

Step 1: Check if it exists

if (!window.Promise) {
  alert("Your browser is really old!");
}

Step 2: Add the Polyfill

if (!window.Promise) {
  window.Promise = /* custom implementation */;
}
Real-World Analogy

Hotel Room Amenities: You walk into a hotel room and check if there's a hairdryer (if (!window.hairdryer)). If it's missing, you pull out your own travel hairdryer and plug it in for anyone else in the room to use (window.hairdryer = myTravelDryer). Now the feature exists for everyone!

Functions are Objects
In JavaScript, functions are callable "action objects"

The Big Idea

Every value in JavaScript has a type. What type is a function? It's an object. We can not only call them, but also treat them like objects: add/remove properties, pass by reference, and read built-in properties.

Built-in Property: name

Functions know their own name. The JavaScript engine is smart — it even figures out names for functions assigned to variables!

function sayHi() { alert("Hi"); }
alert(sayHi.name); // "sayHi"

let sayHi = function() { alert("Hi"); };
alert(sayHi.name); // "sayHi" (guessed from variable!)

let user = {
  sayBye() {}
};
alert(user.sayBye.name); // "sayBye"
Exception: If a function is created inside an array or a context where the engine can't guess the name, it will be an empty string: let arr = [function() {}]; alert(arr[0].name); // ""
Real-World Analogy

Name Tags: Even if you hand someone a name tag that says "John" (a variable), the person still knows their real name. JavaScript functions always try to wear a name tag — either the one they were born with, or one inferred from where they're standing.

The length Property
How a function knows how many arguments it expects

What does it count?

The length property returns the number of function parameters. Rest parameters are not counted.

function f1(a) {}
function f2(a, b) {}
function many(a, b, ...more) {}

alert(f1.length); // 1
alert(f2.length); // 2
alert(many.length); // 2 (rest params not counted)

Practical Use: Polymorphism

We can treat handlers differently based on their length. Zero-argument functions get special treatment!

function ask(question, ...handlers) {
  let isYes = confirm(question);

  for(let handler of handlers) {
    if (handler.length == 0) {
      if (isYes) handler(); // Only call if YES
    } else {
      handler(isYes); // Always call with result
    }
  }
}

ask("Question?", () => alert('You said yes'), result => alert(result));
Real-World Analogy

Plug Adapters: A 2-prong plug and a 3-prong plug need different sockets. By checking length (the number of prongs), the socket knows which type of connection to offer. The 0-argument function is like a simple on/off switch; the 1-argument function is like a dial that needs input.

Custom Properties
Adding your own data to function objects

Functions Can Carry Data

Since functions are objects, we can add properties to them just like any other object.

Example: Call Counter

function sayHi() {
  alert("Hi");
  sayHi.counter++; // count calls
}

sayHi.counter = 0; // initial value

sayHi();
sayHi();

alert(`Called ${sayHi.counter} times`);
// Called 2 times

Property ≠ Variable

A property like sayHi.counter = 0 does NOT create a local variable inside the function.

function sayHi() {
  // sayHi.counter is NOT a variable
  // you can't just say 'counter' here
  let counter = 5; // unrelated!
}

Properties and variables live in parallel worlds.

Real-World Analogy

Sticky Notes on a Box: A custom property is like putting a sticky note on the outside of a box. Anyone can read or write it. A local variable is like something locked inside the box — only the code inside the function can touch it.

Properties vs Closures
Two ways to store state — which should you choose?

Replacing Closures with Properties

Previously, we used a closure to store count. We can rewrite it using a function property instead.

Using a Closure (Hidden)

function makeCounter() {
  let count = 0; // in LE

  return function() {
    return count++;
  };
}

Private: No one outside can read or change count.

Using a Property (Exposed)

function makeCounter() {
  function counter() {
    return counter.count++;
  };
  counter.count = 0; // on function
  return counter;
}

Public: Anyone can read or set counter.count = 10.

The Exposed Property in Action

let counter = makeCounter();

counter.count = 10; // We can set it externally!
alert( counter() ); // 10
alert( counter() ); // 11
Which is better? It depends on your goals! Use a closure if the data should be private and protected. Use a function property if external code should be allowed to read or modify it.

Named Function Expression (NFE)
Giving a function expression an internal name for reliable self-reference

What is an NFE?

A Named Function Expression is simply a Function Expression that has a name added after the function keyword. It still gets assigned to a variable, but now it has an internal name.

// Regular Function Expression
let sayHi = function(who) { ... };

// Named Function Expression
let sayHi = function func(who) { ... };

Two Special Things About "func"

  1. It allows the function to reference itself internally (for recursion).
  2. It is NOT visible outside the function.

The Problem It Solves

let sayHi = function(who) {
  if (who) {
    alert(`Hello, ${who}`);
  } else {
    sayHi("Guest"); // Uses outer var
  }
};

let welcome = sayHi;
sayHi = null;
welcome(); // Error! sayHi is null
Real-World Analogy

Walkie-Talkie vs Phone Number: Calling sayHi("Guest") is like looking up someone's phone number in a book. If they change their number (sayHi = null), the book is outdated and the call fails. Using func("Guest") is like using a direct walkie-talkie frequency — it's an internal, reliable connection that never changes, no matter what happens outside.

NFE Fix & Summary
How NFE makes self-reference reliable, plus wrapping it all up

The NFE Fix

let sayHi = function func(who) {
  if (who) {
    alert(`Hello, ${who}`);
  } else {
    func("Guest"); // Uses internal name!
  }
};

let welcome = sayHi;
sayHi = null;

welcome(); // Hello, Guest ✅ Works!
func(); // Error: func is not defined // Not visible outside
Note: The "internal name" feature is only available for Function Expressions. Function Declarations don't have (or need) this syntax because their name is already reliable within their scope.

Key Takeaways

Global Object

  • Universal container: window, global, or globalThis
  • var creates global properties; let/const don't
  • Use it to check/add polyfills
  • Minimize global variables!

Function Object

  • Functions are callable objects
  • name: the function's name (often guessed)
  • length: number of parameters (no rest)
  • Can add custom properties (parallel to variables)

NFE

  • Named Function Expression: let f = function name() {}
  • Internal name is visible only inside
  • Reliable self-reference (survives reassignment)
  • Libraries use this pattern to organize helpers
