Mouse Events & Drag'n'Drop

Tracking clicks, movements, and building drag interactions

Mouse events are the backbone of interactive web pages. They let us know exactly when a user clicks, moves, or drags. Let's explore the different types and how to use them to build cool features like Drag'n'Drop.

Real-World Analogy: Mouse events are like a security camera for your desk. It tells you exactly where a hand touched the desk, which finger it used, and where it moved next.

Mouse Event Types & Order

What happens when you click?

A single user action can trigger multiple events in a very specific order.

The Click Sequence

When you press and release the left mouse button, three events fire in this exact order:

  1. mousedown: The button is pressed down.
  2. mouseup: The button is released.
  3. click: A full click (press + release) is completed.

Other Common Events

  • dblclick – Double-clicking.
  • contextmenu – Right-clicking (opens the context menu).
  • mousemove – Moving the mouse over an element.
  • mouseover / mouseout – Entering/leaving an element.
Why does order matter? If you are listening for a mouseup to close a menu, but a click on a button opens it, understanding the sequence prevents the menu from instantly closing the moment it opens!

Which Button? Which Keys?

event.button & Modifier Keys

Click events usually imply the left button, but mousedown and mouseup happen for any button. Use event.button to tell them apart.

event.button Values

Button Value
Left button (primary) 0
Middle button (auxiliary) 1
Right button (secondary) 2

Modifier Keys

Mouse events also tell you if modifier keys were held down during the click.

// Shift, Alt, Ctrl, Cmd (Mac) event.shiftKey event.altKey event.ctrlKey event.metaKey // Cmd key on Mac // Example: Alt+Shift+Click button.onclick = function(event) { if (event.altKey && event.shiftKey) { alert('Hooray!'); } };
⚠️ Mac vs. Windows: Windows uses Ctrl, Mac uses Cmd (metaKey). To support both, check: if (event.ctrlKey || event.metaKey).

Mouse Coordinates

Where did the click happen?

All mouse events provide two sets of coordinates: where the mouse is relative to the window, and where it is relative to the document.

Window-relative: clientX / clientY

Measured from the top-left corner of the visible browser window. If you scroll down, the Y value resets. Like sticking a piece of tape on your screen.

Document-relative: pageX / pageY

Measured from the top-left corner of the entire HTML document. Includes scroll distance. Like putting a pin on a physical map.

// Example usage input.onmousemove = function(event) { this.value = `X: ${event.clientX}, Y: ${event.clientY}`; };
When to use which? Use clientX/Y when positioning something relative to the screen (like a popup menu). Use pageX/Y when positioning something on the page itself (like a Drag'n'Drop element).

Moving the Mouse: over/out

Hovering and the relatedTarget

mouseover fires when the pointer enters an element. mouseout fires when it leaves. These events have a special partner: relatedTarget.

The relatedTarget Property

For mouseover: event.target is where the mouse went to, and event.relatedTarget is where it came from.

For mouseout: event.target is where the mouse left, and event.relatedTarget is where it went to.

Skipping Elements

The browser doesn't fire events for every single pixel. If you move the mouse very fast, it might "jump" over intermediate elements. The browser just fires mouseover on the final destination.

⚠️ The Child Problem: If you move from a parent element to a child element inside it, the parent fires mouseout! The browser thinks the mouse "left" the parent because it's now technically over the child. This can cause annoying flickering effects.

Moving the Mouse: enter/leave

The simple, no-fuss hover events

To avoid the "child problem" of mouseover/out, use mouseenter and mouseleave.

Key Differences

Feature mouseover / mouseout mouseenter / mouseleave
Trigger on child transition? Yes (Triggers on parent when entering child) No (Ignores children)
Do they bubble? Yes No
Has relatedTarget? Yes No
Analogy: mouseenter is like entering a house. Once you are in the house, it doesn't matter which room you walk into; you are still inside the house. You only trigger "leave" when you walk out the front door.

Event Delegation Limitation

Because mouseenter/leave do not bubble, you cannot use event delegation with them. If you need to handle hover events for hundreds of table cells using a single table handler, you must use mouseover/out and filter the events manually.

Drag'n'Drop Basics

Building drag from scratch using mouse events

While HTML has a native Drag API, it has limitations (like poor mobile support). Building it with mouse events gives you total control.

The 3-Step Algorithm

  1. mousedown: Prepare the element. Set it to position: absolute and a high z-index.
  2. mousemove: Change the element's left and top styles based on mouse coordinates.
  3. mouseup: Drop the element. Remove the mousemove listener.

Basic Code Structure

ball.onmousedown = function(event) { ball.style.position = 'absolute'; ball.style.zIndex = 1000; document.body.append(ball); function moveAt(pageX, pageY) { ball.style.left = pageX + 'px'; ball.style.top = pageY + 'px'; } moveAt(event.pageX, event.pageY); function onMouseMove(event) { moveAt(event.pageX, event.pageY); } // Listen on DOCUMENT to catch fast moves document.addEventListener('mousemove', onMouseMove); ball.onmouseup = function() { document.removeEventListener('mousemove', onMouseMove); ball.onmouseup = null; }; }; // Disable browser's native drag ball.ondragstart = function() { return false; };

Correct Drag Positioning

Preventing the "jump" on click

If you use the basic code, clicking the bottom-right corner of the ball makes it instantly "jump" so its top-left corner is under the cursor. This feels unnatural. We want to drag it from the exact point we clicked.

The Shift Solution

When mousedown happens, calculate the distance between the click and the element's top-left corner. Keep this "shift" while moving.

ball.onmousedown = function(event) { // 1. Calculate the initial shift let shiftX = event.clientX - ball.getBoundingClientRect().left; let shiftY = event.clientY - ball.getBoundingClientRect().top; ball.style.position = 'absolute'; document.body.append(ball); function moveAt(pageX, pageY) { // 2. Apply the shift while moving ball.style.left = pageX - shiftX + 'px'; ball.style.top = pageY - shiftY + 'px'; } moveAt(event.pageX, event.pageY); // ... mousemove and mouseup logic same as before };
Why listen on document? If you move the mouse too fast, the cursor can slip off the ball. If the listener was on the ball, it would stop moving. Listening on document ensures we catch the movement no matter how fast the mouse goes.

Finding Drop Targets

What is underneath the dragged item?

In real apps, you drag an element onto a specific "drop zone" (like a folder). But how do we know what's under the ball if the ball itself is blocking the view?

The elementFromPoint Trick

We can temporarily hide the dragged element, ask the browser what element is at those coordinates, and then show the dragged element again. This happens instantly, so the user never sees it disappear.

function onMouseMove(event) { moveAt(event.pageX, event.pageY); // 1. Hide the ball ball.hidden = true; // 2. Find the element underneath let elemBelow = document.elementFromPoint(event.clientX, event.clientY); // 3. Show the ball again ball.hidden = false; if (!elemBelow) return; // Is it a droppable zone? let droppableBelow = elemBelow.closest('.droppable'); // ... handle highlighting/leaving }
Why closest('.droppable')? The element directly under the cursor might be a tiny text node inside the drop zone. Using closest() looks up the DOM tree to see if that element, or any of its parents, is the actual drop zone container.

Summary

Key takeaways for Mouse Events & DnD

Mouse Events

  • Order: mousedown → mouseup → click.
  • Button: Use event.button (0=left, 2=right).
  • Modifiers: ctrlKey, shiftKey, altKey, metaKey (Cmd). Always check ctrlKey || metaKey to support Macs.
  • Coords: clientX/Y (window) vs pageX/Y (document).

Hover Events

  • mouseover/out: Bubble, trigger on child transitions. Use for delegation. Have relatedTarget.
  • mouseenter/leave: Do NOT bubble, ignore children. Simpler, but no delegation.

Drag'n'Drop

  • Algorithm: mousedown → mousemove (on document) → mouseup.
  • Remember the shiftX/Y to prevent the element from "jumping" to the cursor.
  • Always disable native drag: ondragstart = () => false.
  • Use document.elementFromPoint to find drop targets under the dragged item.
