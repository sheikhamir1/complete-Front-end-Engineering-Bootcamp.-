Geometry, Scrolling & Coordinates

Measuring and moving elements on the page

To move, position, or read the size of elements, JavaScript provides special geometry properties. We need these to figure out where an element is, how big it is, and how to scroll to it.

Real-World Analogy: Think of an element like a framed painting. The border is the wooden frame, the padding is the matte board inside, and the content is the actual painting. Geometry properties let you measure the frame, the matte, or the canvas!

Outer Sizes: offsetWidth & offsetHeight

Measuring the whole framed picture

The "Outer" Measurement

offsetWidth and offsetHeight give you the full size of the element, including borders, padding, and the content itself.

Calculation

// For an element with CSS width: 300px, padding: 20px, border: 25px offsetWidth = 300 + (20 * 2) + (25 * 2) = 390px offsetHeight = 200 + (20 * 2) + (25 * 2) = 290px

offsetParent & offsetLeft/Top

Sometimes you need to know where the element is relative to its positioned ancestor (its offsetParent). offsetLeft and offsetTop give you the x/y distance from the upper-left corner of that parent.

alert(example.offsetParent.id); // "main" alert(example.offsetLeft); // 180 (distance from left)
⚠️ Zero for Hidden Elements: If an element (or its parent) has display: none, all geometry properties are 0. You can use this to check if an element is hidden: function isHidden(elem) { return !elem.offsetWidth && !elem.offsetHeight; }

Inner Sizes: clientWidth & clientHeight

Measuring inside the frame

clientWidth and clientHeight measure the space inside the borders. They include the padding and the content, but exclude the borders and the scrollbar.

Calculation (With Scrollbar)

If a scrollbar takes up 16px, that space is taken from the content width.

// CSS width: 300px, Padding: 20px, Scrollbar: 16px clientWidth = (300 - 16) + (20 * 2) = 324px // CSS height: 200px, Padding: 20px, No vertical scrollbar clientHeight = 200 + (20 * 2) = 240px

clientTop & clientLeft

These simply give you the thickness of the top and left borders. In left-to-right languages, they are exactly the border width. In right-to-left languages, clientLeft also includes the scrollbar width!

clientLeft = 25 // Left border width clientTop = 25 // Top border width

Scrolled Sizes: scrollWidth & scrollHeight

Measuring the hidden content

What if the content inside overflows and is hidden by a scrollbar? scrollWidth and scrollHeight measure the total size of the content, including the parts scrolled out of view.

Real-World Analogy: Imagine a rolled-up poster inside a tube. clientHeight only measures the visible part sticking out. scrollHeight measures the entire length of the poster if you unrolled it completely.

Expanding an Element

A common trick is to use scrollHeight to expand an element to fit all its content dynamically.

// Expand the element to its full content height element.style.height = `${element.scrollHeight}px`;

scrollLeft & scrollTop

These tell you "how much" the user has scrolled. scrollTop is how many pixels are hidden above the visible area. Unlike other geometry properties, these are writable—you can change them to force the element to scroll!

// Read how far scrolled alert(elem.scrollTop); // Force scroll down by 10px elem.scrollTop += 10; // Scroll to the very top elem.scrollTop = 0;

Why Not Use getComputedStyle?

Why geometry properties are better

You might wonder, "Why not just use getComputedStyle(elem).width to get the size?" There are three major reasons why DOM geometry is better:

1. box-sizing Complications

CSS box-sizing changes whether width includes padding and borders or not. Geometry properties (offsetWidth, clientWidth) are always predictable and ignore box-sizing.

2. The "auto" Problem

For inline elements, CSS width is often auto. You can't do math with auto in JavaScript! Geometry properties always return exact pixel numbers.

3. The Scrollbar Inconsistency

Browsers disagree on what getComputedStyle().width returns when a scrollbar exists. Firefox returns the full CSS width, while Chrome returns the width minus the scrollbar. clientWidth always returns the true usable width minus the scrollbar.

Window Sizes

Measuring the browser viewport

How do we find the width and height of the browser window? We use document.documentElement (the <html> tag).

Visible Area (Without Scrollbar)

This gives you the actual space available for your content.

let width = document.documentElement.clientWidth; let height = document.documentElement.clientHeight;
⚠️ Avoid window.innerWidth/innerHeight: While these exist, they include the width of the scrollbar. If a scrollbar is present, innerWidth will be slightly larger than clientWidth. Usually, you want the usable space (clientWidth).

Full Document Height

To get the full height of the page (including the scrolled out parts), you have to take the maximum of a few properties due to browser inconsistencies:

let scrollHeight = Math.max( document.body.scrollHeight, document.documentElement.scrollHeight, document.body.offsetHeight, document.documentElement.offsetHeight, document.body.clientHeight, document.documentElement.clientHeight );

Window Scrolling

Reading and controlling the page scroll

Reading the Scroll

How far down has the user scrolled? Use window.pageYOffset (or window.scrollY).

alert('Current scroll from the top: ' + window.pageYOffset);

Changing the Scroll

You can scroll the page programmatically using these methods:

1. window.scrollTo(pageX, pageY)

Scrolls to absolute coordinates. Like typing a specific page number in a book.

window.scrollTo(0, 0); // Scroll to the very top

2. window.scrollBy(x, y)

Scrolls relative to the current position. Like turning forward 2 pages.

window.scrollBy(0, 10); // Scroll 10px down from current spot

3. elem.scrollIntoView(top)

Makes a specific element visible. If top=true, it aligns with the window top. If top=false, it aligns with the bottom.

document.querySelector('#footer').scrollIntoView(true);

Coordinate Systems

Window vs. Document

When moving elements, we need to know exactly where they are. There are two coordinate systems in the browser:

1. Window Coordinates

Similar to CSS position: fixed. Calculated from the top-left corner of the browser window.

Denoted as clientX / clientY.

Analogy: Like smudging a finger on the glass of your monitor. The position on the glass doesn't change even if you scroll the page behind it.

2. Document Coordinates

Similar to CSS position: absolute. Calculated from the top-left corner of the document itself.

Denoted as pageX / pageY.

Analogy: Like a GPS coordinate on a map. Even if you fold the map, the coordinate stays fixed to that spot on the paper.

When the page is scrolled, an element's Document coordinates stay the same, but its Window coordinates change (because it moves closer to or further from the top of the visible glass).

Element Coordinates

elem.getBoundingClientRect()

The method elem.getBoundingClientRect() returns the window coordinates for the smallest rectangle that fits around the element. It returns an object with these properties:

DOMRect Properties

{ x: 100, // X coordinate of the rectangle origin y: 150, // Y coordinate of the rectangle origin width: 300, // Width of the rectangle (always positive here) height: 200, // Height of the rectangle // Derived (calculated from x, y, width, height): top: 150, // Y-coordinate of the top edge bottom: 350, // Y-coordinate of the bottom edge (y + height) left: 100, // X-coordinate of the left edge right: 400 // X-coordinate of the right edge (x + width) }
Remember: These coordinates are relative to the window, not the document. If you scroll the page, top and bottom will change. Also, coordinates can be negative if the element is scrolled above the window!

Finding & Positioning Elements

elementFromPoint & Document Coords

Finding Elements by Coordinate

document.elementFromPoint(x, y) does the reverse of getBoundingClientRect. You give it window coordinates, and it returns the topmost element at that spot.

// What element is in the middle of the screen? let centerX = document.documentElement.clientWidth / 2; let centerY = document.documentElement.clientHeight / 2; let elem = document.elementFromPoint(centerX, centerY); elem.style.background = "red";

Document Coordinates

There's no built-in method for document coordinates, but they are easy to calculate. Just add the current scroll position to the window coordinates!

function getCoords(elem) { let box = elem.getBoundingClientRect(); return { top: box.top + window.pageYOffset, left: box.left + window.pageXOffset }; }

Positioning Use Case

Use Window coordinates with position: fixed if you want an element (like a tooltip) to stay in place while the user scrolls.

Use Document coordinates with position: absolute if you want an element to stay attached to a specific part of the document as the user scrolls.
