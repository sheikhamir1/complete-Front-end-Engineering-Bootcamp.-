Default Actions & Custom Events

Controlling the browser and creating your own signals

Sometimes the browser automatically does things we don't want, like navigating to a new page when a link is clicked. Other times, we want to create our own unique signals to tell the rest of our code that something happened.

Real-World Analogy: Default actions are like a restaurant automatically bringing you a glass of water. You can say "No water, please" (preventDefault). Custom events are like hitting a custom buzzer at your table to say "Ready for dessert!" instead of waiting for the waiter to check on you.

Browser Default Actions

What the browser does automatically

Many events automatically trigger built-in browser behaviors.

Common Default Actions

  • Clicking a link (<a>): Navigates to the href URL.
  • Clicking a submit button: Submits the form to the server.
  • Mouse drag over text: Selects the text.
  • Right-click: Opens the browser's context menu.
  • Pressing a key in an input: Types the character.

If we want to handle these events with JavaScript instead, we need to tell the browser: "Stop! Don't do your default thing, let me handle it."

Preventing Default Actions

Saying "No thank you" to the browser

There are two ways to stop the browser's default behavior:

1. event.preventDefault()

The standard, modern way. You call this method on the event object inside your handler.

<a href="/" onclick="event.preventDefault()"> Clicking me does nothing! </a>

2. return false

An older shortcut that only works if you assigned the handler using the on<event> HTML attribute or DOM property. It does NOT work with addEventListener.

<a href="/" onclick="return false"> Also does nothing! </a>
⚠️ Don't mix them up! Returning false from an addEventListener handler will not prevent the default action. Always use event.preventDefault() for modern code.

Example: The JavaScript Menu

Using links without navigating

Web menus often use <a> tags for accessibility and SEO, but we want clicks to open a menu tab, not navigate to a new page.

The Solution

Use event delegation on the menu, and prevent the default action.

menu.onclick = function(event) { if (event.target.nodeName != 'A') return; let href = event.target.getAttribute('href'); alert( 'Loading: ' + href ); // JS logic here return false; // Prevent browser navigation! };
Follow-up Events: Preventing an early event can stop later events. For example, if you preventDefault() on mousedown for an input field, the browser won't focus it (the focus event won't fire).

The passive Option

Optimizing mobile scrolling

On mobile, the touchmove event is used to scroll the page. However, the browser has to wait to see if your JavaScript calls preventDefault() before it starts scrolling. This waiting causes a slight delay or "jitter".

Solution: passive: true

If you add {passive: true} to your event listener, you are promising the browser: "I will NOT call preventDefault()". The browser can then start scrolling immediately without waiting for your code to finish.

elem.addEventListener('touchmove', handler, {passive: true});
Good to know: In modern browsers, touchstart and touchmove are set to passive: true by default to ensure smooth scrolling!

event.defaultPrevented

The smart alternative to stopPropagation

Imagine a button with its own custom right-click menu, sitting inside a document that also has a custom right-click menu. If you right-click the button, both menus will open because of bubbling!

❌ Bad Way: stopPropagation()

Stopping the bubble blocks ALL outer code from knowing the event happened (even analytics trackers). It's like locking the door.

✅ Good Way: defaultPrevented

The inner handler calls preventDefault(). The outer handler checks event.defaultPrevented. If true, it steps aside. It's like leaving a note on the door saying "Already handled!"

Code Example

// Inner Button Handler button.oncontextmenu = function(event) { event.preventDefault(); alert("Button menu"); }; // Outer Document Handler document.oncontextmenu = function(event) { if (event.defaultPrevented) return; // Note left! event.preventDefault(); alert("Document menu"); };

Dispatching Custom Events

Creating your own signals

We aren't limited to browser events; we can create our own! This is great for building UI components that need to talk to the rest of the app.

1. Create the Event

Use the Event constructor. You can define if it bubbles and if it is cancelable.

let event = new Event("my-event", { bubbles: true, cancelable: true });

2. Dispatch the Event

Fire it on an element using elem.dispatchEvent(event).

let elem = document.getElementById("myElem"); elem.dispatchEvent(event); // Any listener on elem (or its parents if bubbles=true) will run.
Is it a real user? You can tell the difference between a script-fired event and a real user action using event.isTrusted. It is true for real actions and false for script-generated ones.

CustomEvent & Detail

Passing data with your events

While new Event() works, new CustomEvent() is specifically designed for developer-defined events. It has a special detail property where you can pass any data you want.

Using the detail property

// Dispatch elem.dispatchEvent(new CustomEvent("user-logged-in", { detail: { username: "John", role: "Admin" }, bubbles: true })); // Listen elem.addEventListener("user-logged-in", function(event) { alert(`Welcome ${event.detail.username}!`); });

Built-in Event Types

If you want to fake a mouse click, you should use new MouseEvent("click") instead of new Event("click"). This allows you to set specific properties like clientX and clientY.

let event = new MouseEvent("click", { bubbles: true, clientX: 100, clientY: 100 });

Preventing Custom Events

Canceling the action after the signal

Custom events don't have browser default actions, but the code that dispatches them might want to know if a handler canceled the process.

If a handler calls event.preventDefault() on a custom event, dispatchEvent() will return false.

Example: The Hiding Rabbit

rabbit.addEventListener('hide', function(event) { if (confirm("Prevent hiding?")) { event.preventDefault(); } }); function hideRabbit() { let event = new CustomEvent("hide", { cancelable: true // REQUIRED for preventDefault to work! }); if (!rabbit.dispatchEvent(event)) { alert('Action was prevented!'); } else { rabbit.hidden = true; } }

Events-in-Events (Synchronous)

Handling nested event timing

When an event is dispatched from inside another event's handler, the new event is processed immediately (synchronously). The outer handler pauses, the inner event runs, and then the outer handler resumes.

Example Output Order

menu.onclick = function() { alert(1); menu.dispatchEvent(new CustomEvent("menu-open", {bubbles:true})); alert(2); }; document.addEventListener('menu-open', () => alert('nested')); // Output order: 1 -> nested -> 2

Making it Asynchronous

If you want the outer event to finish completely before the inner event runs, wrap the dispatch in a zero-delay setTimeout.

menu.onclick = function() { alert(1); setTimeout(() => menu.dispatchEvent(new CustomEvent("menu-open"))); alert(2); }; // Output order: 1 -> 2 -> nested
