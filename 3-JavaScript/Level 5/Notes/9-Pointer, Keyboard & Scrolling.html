Pointer, Keyboard & Scrolling

Modern input handling for every device

The web isn't just for mice anymore. Users interact with phones, tablets, styluses, and keyboards. Modern JavaScript provides Pointer Events to handle all pointing devices uniformly, Keyboard Events for physical keys, and Scroll Events for page navigation.

Real-World Analogy: Instead of learning a different language for every remote control in your house (mouse, touch, pen), Pointer Events give you a "Universal Remote" that works for all of them.

Pointer Events

The Universal Input API

In the past, we used Mouse Events. Then touch screens arrived, and we had Touch Events. Now we have pens! Writing code for all of them was a nightmare. Pointer Events solve this by combining them into one system.

Event Mapping

For every mouse event, there is a matching pointer event. You can literally swap "mouse" for "pointer" in your code!

Mouse Event Pointer Event
mousedown pointerdown
mousemove pointermove
mouseup pointerup
mouseover pointerover
mouseout pointerout
mouseenter pointerenter
mouseleave pointerleave
Pro Tip: Unless you are supporting very old browsers (like IE 10 or Safari 12), you should switch from mouse events to pointer events. Your code will automatically work with touch and pens!

Pointer Event Properties

Identifying the input source

Pointer events include all standard mouse properties (like clientX), but add new ones specifically for multi-device support.

Key Properties

  • pointerId – A unique ID for the pointer causing the event. Essential for tracking multiple fingers.
  • pointerType – What kind of device? Returns "mouse", "pen", or "touch".
  • isPrimary – Is this the primary pointer? (e.g., the first finger in a multi-touch gesture).

Multi-touch Support

When a user touches a screen with one finger, pointerdown fires with isPrimary=true. If they add a second finger, another pointerdown fires with a new pointerId and isPrimary=false.

Analogy: Think of pointerId like a name tag. If 5 fingers touch the screen, the browser hands out 5 name tags. You can track each finger individually as it moves and lifts.

The pointercancel Event

When the browser hijacks your interaction

Sometimes, you start a pointer interaction (like dragging an item), but the browser decides to take over. When this happens, the pointercancel event fires, and you stop getting pointermove events.

Why does the browser hijack it?

  • The device orientation changed (tablet was rotated).
  • The browser interpreted the action as a native gesture (like scrolling or zooming).
  • The browser started its own native drag-and-drop for an image.

⚠️ How to prevent it

To keep control and stop pointercancel, you must disable the browser's default actions.

  1. Disable native drag: ball.ondragstart = () => false;
  2. Disable touch gestures (like scroll/zoom): Add CSS touch-action: none; to the dragged element.
/* CSS */ #ball { touch-action: none; }

Pointer Capturing

Locking the pointer to an element

Imagine building a custom slider. The user presses the slider thumb and drags it. But if they move their finger too fast, the pointer might leave the thumb element, breaking the interaction.

The Solution: elem.setPointerCapture(pointerId). This acts like a leash. Once set, all future pointer events (until pointerup) are redirected to that element, no matter where the mouse/finger actually is on the screen.

Slider Example Code

thumb.onpointerdown = function(event) { // 1. Put a leash on the pointer thumb.setPointerCapture(event.pointerId); thumb.onpointermove = function(event) { // 2. Move slider (events are caught here even if pointer leaves thumb) let newLeft = event.clientX - slider.getBoundingClientRect().left; thumb.style.left = newLeft + 'px'; }; thumb.onpointerup = function(event) { // 3. Leash is automatically removed on pointerup thumb.onpointermove = null; thumb.onpointerup = null; }; };

Benefits: You no longer need to attach mousemove to the whole document, and you won't accidentally trigger hover effects on other elements while dragging.

Keyboard Events

keydown and keyup

Keyboard events trigger when a user presses a physical key. Use these for game controls or keyboard shortcuts (hotkeys). Do not use them to track text input—use the input event instead, because users can paste text or use voice-to-text.

Event Sequence

  • keydown – Fires when a key is pressed down. Repeats if held down.
  • keyup – Fires when the key is released.

Auto-repeat

If a key is held down, keydown fires repeatedly. You can check if an event is an auto-repeat by checking event.repeat (it will be true).

⚠️ Don't use keypress! The old keypress event is deprecated. It was buggy and didn't work for special keys. Always use keydown/keyup.

event.key vs event.code

The character vs. the physical button

Keyboard events provide two main properties that often confuse developers. Understanding the difference is crucial for handling international keyboards correctly.

Comparison

Property What it means Example
event.key The character produced. Changes based on language/layout and Shift key. "z", "Z", "1", "!"
event.code The physical key on the keyboard. Always the same location. "KeyZ", "Digit1"

The Layout Problem

On a US QWERTY keyboard, the bottom-left letter key is "Z". On a German QWERTZ keyboard, that exact same physical key types "Y".

  • If you press that key on a German keyboard: event.key is "Y", but event.code is still "KeyZ".
Which should you use?
  • Want to react to the character typed? Use event.key.
  • Want a hotkey (like Ctrl+Z) that works regardless of language? Use event.code.

Keyboard Default Actions

Filtering input safely

Pressing a key usually does something (like typing a letter or scrolling down). You can prevent these default actions by calling event.preventDefault() in the keydown handler.

Example: Phone Number Input

We only want numbers, +, (, ), or -. We can prevent all other keys from doing anything.

function checkPhoneKey(key) { return (key >= '0' && key <= '9') || ['+','(',')','-','ArrowLeft','ArrowRight','Delete','Backspace'].includes(key); } <input onkeydown="return checkPhoneKey(event.key)" placeholder="Phone" type="tel">
⚠️ Don't forget navigation keys! If you filter strictly for numbers, you might accidentally block the Backspace, Delete, and Arrow keys. Always allow them in your filter! Also, remember this won't stop users from pasting invalid text—handle that with the input event.

Scrolling Events

Reacting to page movement

The scroll event fires whenever an element or the window is scrolled. This is perfect for features like "Back to Top" buttons or infinite scrolling feeds.

Basic Usage

window.addEventListener('scroll', function() { document.getElementById('showScroll').innerHTML = window.pageYOffset + 'px'; });

Preventing Scrolling

You cannot prevent scrolling by calling preventDefault() inside the scroll event listener, because the scroll has already happened by the time the event fires!

How to actually prevent scrolling:
  • CSS: Use overflow: hidden; on the element or body.
  • JavaScript: Call event.preventDefault() on the events that cause the scroll, like keydown (for PageDown/Space) or wheel (for mouse scroll).

Summary

Key takeaways

Pointer Events

  • Replace mouse* events with pointer* events to support mouse, touch, and pens.
  • Track multiple touches using pointerId and isPrimary.
  • Prevent browser hijacking with touch-action: none CSS and ondragstart = () => false.
  • Use setPointerCapture to lock pointer events to an element (great for sliders).

Keyboard Events

  • Use keydown/keyup for hotkeys and game controls, not for text input tracking.
  • event.key = the character ("A"). Changes with language.
  • event.code = the physical key ("KeyA"). Stays the same globally.

Scrolling Events

  • scroll event fires after the scroll happens.
  • Prevent scrolling using CSS (overflow: hidden) or by preventing the events that cause it.
