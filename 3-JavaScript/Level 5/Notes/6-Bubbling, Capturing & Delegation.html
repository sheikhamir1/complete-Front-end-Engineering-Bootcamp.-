Bubbling, Capturing & Delegation

How events travel through the DOM

When an event happens on an element, it doesn't just stay there. It travels. Understanding how events travel through the DOM is the key to writing efficient, clean JavaScript.

Real-World Analogy: Imagine a company. If a problem happens in a specific department (the target), the local manager handles it first. If they can't, it escalates to the general manager, and finally to the CEO. Events in the DOM work exactly the same way!

Bubbling

Events rise up like a bubble

The Bubbling Principle

When an event happens on an element, it first runs the handlers on that element, then on its parent, then on its grandparent, and all the way up to the document.

Example: Nested Elements

<form onclick="alert('form')"> FORM <div onclick="alert('div')"> DIV <p onclick="alert('p')"> P </p> </div> </form>

If you click on <p>, the alerts will fire in this order: p → div → form. The event "bubbles" up from the inside out.

Almost all events bubble. There are a few exceptions (like focus), but generally, if an event happens to a child, the parents will hear about it.

Target vs. CurrentTarget

Who started it vs. Who is handling it

A parent's event handler can always find out exactly which child element originally triggered the event.

The Two Key Properties

Property What it means Analogy
event.target The actual element that triggered the event. Does not change as it bubbles. The employee who reported the problem.
this (or event.currentTarget) The element that is currently handling the event right now. The manager currently looking at the problem.

Example

form.onclick = function(event) { // 'this' is the <form> alert("Handler is on: " + this.tagName); // event.target is the clicked element inside alert("Actual click was on: " + event.target.tagName); };

Stopping Bubbling

Putting a lid on the pot

Sometimes, you don't want the event to reach the parent. You can stop the bubbling process using event.stopPropagation().

Usage

<body onclick="alert('Bubbling reached body!')"> <button onclick="event.stopPropagation()"> Click me </button> </body> // Clicking the button stops here. The body won't alert.

⚠️ Don't stop bubbling without a need!

Bubbling is extremely useful. If you stop it unnecessarily, you create "dead zones" where higher-level analytics or features can't track user clicks. Only use stopPropagation() when you have a well-thought-out architectural reason.

stopImmediatePropagation()

If an element has multiple handlers on the same event, stopPropagation stops the parent, but the other handlers on the same element still run. stopImmediatePropagation() stops everything—no other handlers run at all.

Capturing

The dive down

Before an event bubbles up, it actually travels down first. This is called the Capturing Phase. The DOM event standard describes 3 phases:

The 3 Phases of an Event

  1. Capturing Phase: The event travels down from the document root to the target element.
  2. Target Phase: The event reaches the actual element that was clicked.
  3. Bubbling Phase: The event bubbles back up to the root.
Analogy: A submarine diving down (Capturing), hitting the ocean floor (Target), and then releasing a bubble that rises back up (Bubbling).

How to catch Capturing Events

By default, handlers only listen to the Target and Bubbling phases. To catch an event on its way down, you must set the capture option to true.

elem.addEventListener("click", handler, {capture: true}); // Or simply pass true as the 3rd argument (shorthand) elem.addEventListener("click", handler, true);

Event Delegation

The most powerful event pattern

The Core Idea

If you have many elements that need the same event handler, don't assign a handler to each one. Instead, assign a single handler to their common parent, and use event.target to figure out which child was clicked.

Real-World Analogy: Instead of giving every employee in a company their own direct phone line, you have one receptionist (the parent handler). The receptionist looks at who the call is for (event.target) and routes it correctly.

Example: Table Highlighting

Imagine a table with 9,000 cells. Instead of 9,000 handlers, we put 1 on the <table>.

table.onclick = function(event) { let target = event.target; // Where was the click? if (target.tagName != 'TD') return; // Not on a cell? Ignore. highlight(target); // Highlight it! };

Delegation & The closest() Method

Handling nested elements safely

There is a problem with simple delegation. What if your <td> has a <strong> tag inside it? If the user clicks the text inside <strong>, event.target will be the <strong>, not the <td>!

The Solution: elem.closest()

We use closest() to search upwards from the target to find the nearest element that matches our selector.

table.onclick = function(event) { // Find the closest TD to where the click happened let td = event.target.closest('td'); if (!td) return; // Click wasn't inside any TD if (!table.contains(td)) return; // Click was in another table highlight(td); // Safe to highlight! };
Why table.contains(td)? If your page has multiple tables, a click deep in Table B might bubble up to a <td> that belongs to Table B, but the handler is on Table A. contains() ensures the clicked element is actually inside our specific table.

Actions in Markup

Connecting HTML to JavaScript logic

We can use event delegation to map buttons to JavaScript methods dynamically using data- attributes.

The Pattern

1. Give elements a data-action attribute.
2. The parent handler reads the attribute and calls the matching method.

<div id="menu"> <button data-action="save">Save</button> <button data-action="load">Load</button> </div> <script> class Menu { constructor(elem) { this._elem = elem; elem.onclick = this.onClick.bind(this); } save() { alert('saving'); } load() { alert('loading'); } onClick(event) { let action = event.target.dataset.action; if (action) { this[action](); // Calls this.save() or this.load() } }; } new Menu(menu); </script>

The Behavior Pattern

Declaring actions directly in HTML

We can take delegation even further by adding "behaviors" declaratively. We set a document-wide handler that looks for elements with special attributes and performs actions automatically.

Behavior: Counter

Any element with data-counter will increase its value on click.

Counter: <input type="button" value="1" data-counter> <script> document.addEventListener('click', function(event) { if (event.target.dataset.counter != undefined) { event.target.value++; } }); </script>

Behavior: Toggler

Clicking an element with data-toggle-id will show/hide the element with that ID.

<button data-toggle-id="subscribe-mail"> Show form </button> <form id="subscribe-mail" hidden> Your mail: <input type="email"> </form> <script> document.addEventListener('click', function(event) { let id = event.target.dataset.toggleId; if (!id) return; document.getElementById(id).hidden = !document.getElementById(id).hidden; }); </script>
Always use addEventListener for document-level handlers! If you use document.onclick, you risk overwriting handlers set by other scripts. addEventListener allows multiple scripts to listen safely.

Summary

Benefits & Limitations of Delegation

The Delegation Algorithm

  1. Put a single handler on the container (parent).
  2. In the handler, check the source element using event.target (or closest()).
  3. If the event happened inside an element we care about, handle it.

✅ Benefits

  • Saves memory: No need to add hundreds of handlers.
  • Less code: No need to add/remove handlers when elements are added/removed dynamically.
  • DOM modifications: Works perfectly with innerHTML.

❌ Limitations

  • Events must bubble. (Some, like focus, do not).
  • Low-level handlers shouldn't use stopPropagation(), or the parent won't catch the event.
  • Slight CPU load: The container handler reacts to every click inside it, even if we don't care about it.
