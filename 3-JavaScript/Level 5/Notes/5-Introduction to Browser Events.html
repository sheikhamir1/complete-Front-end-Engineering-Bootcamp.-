Introduction to Browser Events

Making your page react to users

An event is a signal that something has happened. Every time a user clicks a button, types on a keyboard, or hovers over an element, the browser fires an event. Your JavaScript can "listen" for these events and react.

Real-World Analogy: Think of an event like a doorbell. When someone presses the doorbell (the event), you hear it and open the door (the handler). In JavaScript, the browser rings the doorbell, and your code decides what to do next.

Types of Events

What kind of doorbells do we have?

Mouse Events

  • click – A mouse click (or tap on mobile).
  • contextmenu – Right-click.
  • mouseover / mouseout – Cursor enters/leaves an element.
  • mousedown / mouseup – Pressing/releasing the mouse button.
  • mousemove – Moving the mouse.

Keyboard Events

  • keydown – Key is pressed.
  • keyup – Key is released.

Form & Document Events

  • submit – Form is submitted.
  • focus – Element gets focus.
  • DOMContentLoaded – HTML is fully loaded.

Way 1: HTML Attributes

onclick="..."

The simplest way to handle an event is right inside the HTML tag using an attribute named on<event>.

Example

<input value="Click me" onclick="alert('Click!')" type="button">
⚠️ Quote Trap! Because the HTML attribute uses double quotes "...", you must use single quotes '...' for the strings inside your JavaScript.

You can also call a predefined function. This keeps the HTML cleaner:

<script> function countRabbits() { for(let i=1; i<=3; i++) { alert("Rabbit " + i); } } </script> <input type="button" onclick="countRabbits()" value="Count!">

Way 2: DOM Properties

elem.onclick = function

Instead of putting JavaScript in HTML, we can assign a handler using a DOM property. This separates your HTML from your logic.

Example

<input id="elem" type="button" value="Click me"> <script> elem.onclick = function() { alert('Thank you'); }; </script>
Accessing the Element: Inside the handler, the keyword this refers to the element that triggered the event. For example: alert(this.innerHTML).
⚠️ Overwriting Danger: A DOM property is just a single variable. If you assign two handlers to onclick, the second one completely erases the first one!
input.onclick = function() { alert(1); } // Erased! input.onclick = function() { alert(2); } // Only this runs

Common Mistakes with Handlers

Passing the function vs. Calling the function

The most common mistake beginners make is adding parentheses when they shouldn't.

❌ Wrong

// This runs the function immediately! // It assigns undefined to onclick. button.onclick = sayThanks();

✅ Right

// This assigns the function to run LATER button.onclick = sayThanks;

Why the difference?

Adding () means "execute this code right now". Without (), you are passing a reference to the function, telling the browser: "Here is the recipe. Don't bake the cake now, bake it when the event happens."

The HTML Exception: In HTML attributes, you do need parentheses: onclick="sayThanks()". This is because the browser automatically wraps your string inside a function block.

Way 3: addEventListener

The modern, flexible way

Because HTML attributes and DOM properties can only hold one handler, modern JavaScript uses addEventListener. It's like a bulletin board where you can pin as many recipes as you want!

Syntax

element.addEventListener(event, handler[, options]); // Example elem.addEventListener("click", handler1); elem.addEventListener("click", handler2); // Both will run!

Removing Handlers

To remove a handler, you must pass the exact same function reference. Anonymous arrow functions won't work because they create new objects every time.

function handler() { alert('Thanks!'); } input.addEventListener("click", handler); // ... later ... input.removeEventListener("click", handler); // Works!

The Event Object

Getting the details of what happened

When an event happens, the browser creates an event object with all the details (where was the mouse? which key was pressed?) and passes it as the first argument to your handler.

Real-World Analogy: If the event is a doorbell ringing, the Event Object is the security camera showing you exactly who is at the door and what they are carrying.

Example Usage

elem.onclick = function(event) { // What type of event was it? alert(event.type); // "click" // Which element handled it? alert(event.currentTarget); // The element itself // Where did the click happen? alert("X: " + event.clientX + " Y: " + event.clientY); };

Important properties:

  • event.type – The name of the event (e.g., "click").
  • event.currentTarget – The element listening for the event (same as this).
  • event.clientX / clientY – Window-relative coordinates for mouse events.

Object Handlers: handleEvent

Passing an object instead of a function

Did you know addEventListener can accept an object instead of a function? When the event fires, the browser calls the object's handleEvent(event) method.

Basic Example

let obj = { handleEvent(event) { alert(event.type + " at " + event.currentTarget); } }; elem.addEventListener('click', obj); // Pass the whole object!

Smart Routing Pattern

You can use handleEvent as a router to call specific methods based on the event type.

class Menu { handleEvent(event) { // mousedown -> onMousedown let method = 'on' + event.type[0].toUpperCase() + event.type.slice(1); this[method](event); } onMousedown() { elem.innerHTML = "Pressed"; } onMouseup() { elem.innerHTML += "...and released."; } } let menu = new Menu(); elem.addEventListener('mousedown', menu); elem.addEventListener('mouseup', menu);

Summary

3 Ways to handle events

Comparison Table

Method Syntax Pros/Cons
HTML Attribute onclick="..." Quick, but mixes HTML and JS. Rarely used in modern code.
DOM Property elem.onclick = func Clean, but you can only assign one handler per event.
addEventListener elem.addEventListener(event, func) ✅ Multiple handlers! Removable. The modern standard.
Key Takeaways:
  • Always use addEventListener for modern applications.
  • Remember to pass the function reference (sayThanks), not the call (sayThanks()), unless inside an HTML attribute.
  • The event object is your best friend for finding out exactly what happened and where it happened.
