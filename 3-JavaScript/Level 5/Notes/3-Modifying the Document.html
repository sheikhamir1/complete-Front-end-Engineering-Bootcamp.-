Modifying the Document

Creating, Inserting, and Styling Elements

DOM modification is the key to creating "live" pages. This is how we add new elements on the fly, move them around, and apply styles dynamically to react to user actions.

Real-World Analogy: Think of the web page as a Lego castle. JavaScript gives you the power to snap new bricks onto the castle, take bricks away, or paint them different colors—without ever reloading the page.

Creating Elements

Building the bricks

The 3-Step Process

Creating an element doesn't automatically put it on the page. It exists only in JavaScript memory until you insert it. Here are the steps:

Step 1: Create the Node

Use document.createElement(tag) to create a new HTML element, or document.createTextNode(text) for plain text.

let div = document.createElement('div'); let textNode = document.createTextNode('Here I am');

Step 2: Configure it

Add classes, text, or inner HTML to your new element.

div.className = "alert"; div.innerHTML = "<strong>Hi there!</strong> You've read an important message.";

Step 3: Insert it

Append it to an existing element on the page (like document.body).

document.body.append(div); // Now it's visible!

Modern Insertion Methods

Where exactly should the brick go?

We don't always want to add elements at the very end. These modern methods let you insert nodes or text strings at specific locations relative to a reference element.

The Big Five Methods

Method Where does it go?
node.append(...) Inside node, at the end.
node.prepend(...) Inside node, at the beginning.
node.before(...) Before the node (outside).
node.after(...) After the node (outside).
node.replaceWith(...) Replaces the node entirely.
Safety Feature: If you pass a string into these methods (e.g., ol.before('before')), it is inserted as plain text, not HTML. This protects you from accidental XSS attacks.

Inserting HTML Strings

insertAdjacentHTML

If you do want to insert a string and have it parsed as HTML tags (like innerHTML does), use elem.insertAdjacentHTML(where, html).

The 4 Positions

// <p>Hello</p> // <div id="div"></div> // <p>Bye</p> div.insertAdjacentHTML('beforebegin', '<p>Hello</p>'); div.insertAdjacentHTML('afterend', '<p>Bye</p>'); // Inside the div: div.insertAdjacentHTML('afterbegin', '<span>Top</span>'); div.insertAdjacentHTML('beforeend', '<span>Bottom</span>');
Analogy: Think of beforebegin and afterend as placing furniture in the hallway outside a room. afterbegin and beforeend place furniture inside the room, either at the entrance or at the back.

Removal & Moving

Taking bricks away or moving them

Removing Elements

To remove a node, simply call node.remove().

setTimeout(() => div.remove(), 1000); // Disappears after 1 sec

Moving Elements

Here is a cool shortcut: if you want to move an element from one place to another, you don't need to remove it first! Insertion methods automatically remove the node from its old spot.

Swapping Elements

<div id="first">First</div> <div id="second">Second</div>

Cloning & DocumentFragment

Copying bricks and bulk shipments

Cloning Nodes

Sometimes you have a complex element and want an exact duplicate. Use cloneNode(true).

let div2 = div.cloneNode(true); // Deep clone // Change the clone's text div2.querySelector('strong').innerHTML = 'Bye!'; // Insert the clone div.after(div2);

Note: Passing false only clones the outer tag, without children.

DocumentFragment

A DocumentFragment is a lightweight wrapper. You can append nodes to it, and when you insert the fragment into the DOM, the wrapper disappears, and only its contents are inserted.

Analogy: Like a moving box. You pack multiple items into the box, move the box to the new room, and then take the items out. The box itself doesn't stay in the room.

Old School Methods & document.write

What to avoid in modern code

You might see these in legacy code, but modern methods (append, remove) are much better.

The "Old School" Methods

  • parent.appendChild(node) → Use append() instead.
  • parent.insertBefore(node, nextSibling) → Use before() instead.
  • parent.removeChild(node) → Use remove() instead.
  • parent.replaceChild(newElem, node) → Use replaceWith() instead.

⚠️ Beware of document.write()

document.write(html) writes HTML directly into the page as it's loading. It's blazing fast, but has a fatal flaw: if you call it after the page has already loaded, it completely erases the entire document! Never use this in modern, dynamic web applications.

Styles and Classes

Painting the bricks

The Golden Rule

There are two ways to style an element: CSS Classes and Inline Styles. Always prefer CSS classes. Only use inline styles if you are calculating dynamic values (like exact pixel coordinates).

className vs classList

Property What it does Best for...
elem.className Gets/sets the entire class string. Replaces all existing classes! Completely overwriting all classes.
elem.classList An object with methods to manage individual classes easily. Adding, removing, or toggling one class.

classList Methods

elem.classList.add("class") // Adds the class elem.classList.remove("class") // Removes the class elem.classList.toggle("class") // Adds if missing, removes if present elem.classList.contains("class") // Returns true/false

Element Style

elem.style & style.cssText

The elem.style object lets you read and write inline styles. Multi-word CSS properties are written in camelCase.

CSS to JS Translation

background-color => elem.style.backgroundColor z-index => elem.style.zIndex border-left-width => elem.style.borderLeftWidth // Example usage: document.body.style.backgroundColor = prompt('background color?', 'green');

Resetting & Rewriting

To remove a single inline style, set it to an empty string. To rewrite ALL inline styles at once, use style.cssText.

// Remove a style elem.style.display = ""; // Reverts to CSS default // Full rewrite (erases previous inline styles!) div.style.cssText = `color: red !important; background-color: yellow;`;
⚠️ Mind the Units! Don't forget to add "px" to numeric values. elem.style.top = 10 will NOT work. You must write elem.style.top = '10px'.

Computed Styles

getComputedStyle

The Problem with elem.style

elem.style only reads inline styles written in the style attribute. It knows nothing about styles coming from CSS classes in a <style> tag or external stylesheet.

Real-World Analogy: Checking elem.style is like checking what color you personally painted a house (inline). Checking getComputedStyle is like looking at the house to see the final color it actually is, including the builder's default paint (CSS classes).

getComputedStyle(element)

This method returns the resolved value of all CSS properties applied to an element, after all CSS rules and inheritance have been calculated.

<style> body { color: red; margin: 5px; } </style> let computedStyle = getComputedStyle(document.body); alert( computedStyle.marginTop ); // "5px" (Resolved value!) alert( computedStyle.color ); // "rgb(255, 0, 0)"

Note: getComputedStyle requires the full property name (like paddingLeft instead of just padding) to guarantee the correct result. Also, for security/privacy reasons, it cannot read the styles applied to :visited links.
