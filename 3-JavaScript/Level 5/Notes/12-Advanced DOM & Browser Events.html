Advanced DOM & Browser Events

Mutation Observer, Selection, and the Event Loop

As web applications get complex, we need to observe changes dynamically, handle user text selections, and ensure our code runs smoothly without freezing the browser.

Real-World Analogy: The Browser Kitchen 🍳
1. Mutation Observer: The security camera watching the fridge for missing items.
2. Selection/Range: A highlighter pen and scissors to mark and cut text.
3. Event Loop: The chef taking orders, cooking one at a time, while keeping the restaurant running.

Mutation Observer

Watching the DOM change in real-time

MutationObserver is a built-in object that watches a DOM element and fires a callback when it detects a change.

How it works (3 Steps)

// 1. Create the observer with a callback
let observer = new MutationObserver(callback);

// 2. Attach it to a DOM node
observer.observe(node, config);

// 3. Stop observing when done
observer.disconnect();

The Config Object

You tell the observer exactly what to watch for:

  • childList: Changes in direct children.
  • subtree: Changes in all descendants (deep watching).
  • attributes: Changes to element attributes (like class, id).
  • characterData: Changes to text content.
  • attributeOldValue / characterDataOldValue: Passes the old and new value to the callback.

Mutation Observer Use Cases

Why do we need a DOM security camera?

Integration: Blocking 3rd-Party Ads

Sometimes a 3rd-party script injects unwanted ads (<div class="ads">) into your page. You can use an observer to detect when that element appears and instantly remove it.

Architecture: Auto-Highlighting

If you dynamically load articles with code snippets, you need to run a syntax highlighter (like Prism.js). Instead of calling it manually every time you load content, the observer detects new <pre> tags and highlights them automatically.

Cleaning up: Always call observer.disconnect() when you're done to save memory. If you need to process any changes that happened right before you disconnected, use observer.takeRecords() to grab the final unprocessed list.

Range: The Invisible Highlighter

Before we can "select" text on screen, we need to understand Range. A Range is an invisible pair of boundary points (start and end) in the document.

Creating a Range

let range = new Range();
range.setStart(node, offset);
range.setEnd(node, offset);

How Offset Works:

  • If node is a Text Node, offset is the character number. (e.g., offset 2 in "Hello" starts at the first 'l').
  • If node is an Element Node, offset is the child number. (e.g., offset 0 selects the first child element).

Powerful Range Methods

  • deleteContents(): Removes the content from the DOM.
  • cloneContents() / extractContents(): Copies or cuts the selected content to use elsewhere.
  • insertNode(node): Inserts a new node at the start of the range.
  • surroundContents(node): Wraps the range in a new element (e.g., wrapping text in a <b> tag).

Selection: What the User Sees

The visible blue highlight on the screen

While Range is the underlying concept, Selection is the visible result. We get it using window.getSelection(). A selection can contain one or more Ranges (though most browsers only allow one).

Anchor vs Focus

Anchor: Where the selection started.
Focus: Where the selection ended.

Unlike Range, the Focus can be BEFORE the Anchor if the user dragged their mouse backwards!

Selection Events

onselectstart: Fires when the user starts selecting. (Prevent this to make text unselectable!).
onselectionchange: Fires whenever the selection changes. Must be attached to document.

Getting Selected Text: Use document.getSelection().toString() to get plain text, or selection.getRangeAt(0).cloneContents() to get the actual DOM nodes (to preserve formatting like bold/italics).

Selection in Form Controls

Handling text inputs and textareas

For <input> and <textarea>, the Selection API is much simpler because the content is just plain text, not HTML DOM nodes.

Property / Method What it does
input.selectionStart Position where selection starts (or cursor is).
input.selectionEnd Position where selection ends.
input.select() Selects all text in the input.
input.setSelectionRange(start, end) Selects text between start and end.
input.setRangeText(replacement) Replaces the currently selected text.
Moving the Cursor: If selectionStart equals selectionEnd, there is no selection—it's just the blinking cursor! You can programmatically move the cursor by setting these properties to the same number.

The Event Loop

How JavaScript multitasks with a single thread

JavaScript is single-threaded, meaning it can only do one thing at a time. The Event Loop is the mechanism that lets the browser handle user clicks, network requests, and timers without freezing.

The Loop Algorithm

1. Execute the oldest task in the queue.
2. Sleep and wait for a new task.
3. Repeat.

What is a Macrotask?

Almost everything is a macrotask: running a <script>, handling a click event, a setTimeout callback, etc.

Critical Rule: The browser NEVER renders changes to the screen while a macrotask is running. If a task takes 10 seconds, the page freezes for 10 seconds.

Analogy: A chef in a kitchen. If they take a 10-minute order, they can't serve other customers or answer questions until it's done.

Splitting CPU-Heavy Tasks

Keeping the UI responsive

If you have a heavy script (like highlighting 10,000 lines of code), it will block the event loop. The solution? Break it into chunks using setTimeout with zero delay.

Before (Freezes the browser):

function count() {
  for (let j = 0; j < 1e9; j++) { i++; }
  alert("Done!");
}

After (Allows UI updates between chunks):

let i = 0;
function count() {
  // Do a piece of the work
  do { i++; } while (i % 1e6 != 0);

  if (i == 1e9) {
    alert("Done!");
  } else {
    // Yield control back to browser
    setTimeout(count); 
  }
}
count();
Use Cases: Showing a progress bar that actually updates visually, or preventing the "Page Unresponsive" warning.

Microtasks vs Macrotasks

The VIP line of the Event Loop

Besides macrotasks, there are Microtasks. These come exclusively from our code (Promises, await, queueMicrotask()).

The Execution Order

1. Run the Macrotask.
2. Run ALL Microtasks until the queue is empty.
3. Render changes to the screen.
4. Take the next Macrotask.

Example Order:
setTimeout(() => alert("timeout")); (Macrotask)
Promise.resolve().then(() => alert("promise")); (Microtask)
alert("code"); (Synchronous)

Result: "code" → "promise" → "timeout". Microtasks always execute before the next macrotask!

Web Workers (For extreme heavy lifting)

If a task is too heavy even for chunking, use Web Workers. They run in a completely separate background thread. They can't touch the DOM, but they can crunch numbers and send messages back to the main thread.
