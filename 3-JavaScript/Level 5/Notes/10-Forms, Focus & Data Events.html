Forms, Focus & Data Events

Controlling user input in the browser

Forms are how we talk to the web. Whether it's a login screen, a search bar, or a checkout page, handling form data correctly is crucial. Let's learn how to navigate, validate, and submit forms using JavaScript.

Real-World Analogy: Think of a form like a physical clipboard at a doctor's office. Navigating it means knowing where the blanks are. Focus is picking up the pen to fill one in. Change/Input events are the act of writing. Submit is handing the clipboard back to the receptionist.

Form Navigation

Finding forms and their elements

Forms are so important that JavaScript gives us special, faster ways to find them and the inputs inside them, without using querySelector.

1. Finding the Form

Use document.forms. You can find a form by its index or its name attribute.

// Get the first form on the page let form1 = document.forms[0]; // Get a form with name="myForm" let form2 = document.forms.myForm;

2. Finding Elements inside a Form

Once you have the form, use form.elements to grab any input inside it by name.

let form = document.forms.myForm; // Get input with name="username" let usernameInput = form.elements.username; // Shortcut: form.username works too!
Backreference: Elements know their parent! Any input can find its form via input.form. This is super handy when passing inputs to functions.

Getting & Setting Values

Reading what the user typed

How you read a value depends on the type of input.

Text & Textarea

Use .value to get the text. Always use textarea.value, never innerHTML!

input.value = "New value"; textarea.value = "New text";

Checkboxes & Radio Buttons

Use .checked to see if they are selected. It returns a boolean (true/false).

if (checkbox.checked) { alert("It is checked!"); }

Select (Dropdowns)

You have three ways to set a dropdown's selection. All three lines below do the exact same thing:

select.options[2].selected = true; // By option index select.selectedIndex = 2; // By index shortcut select.value = 'banana'; // By the value attribute

Focus & Blur

When elements get (and lose) attention

Focus happens when you click or tab into an input (it's ready to type). Blur happens when you click away (you're done typing). These are perfect for live validation!

Validation Example

input.onblur = function() { if (!input.value.includes('@')) { input.classList.add('invalid'); error.innerHTML = 'Please enter a correct email.'; } }; input.onfocus = function() { // Hide the error when they try to fix it this.classList.remove('invalid'); error.innerHTML = ""; };
Programmatic Focus: You can force focus using elem.focus() or remove it with elem.blur(). For example, forcing focus back to an invalid email field so the user must fix it before moving on.

Making Things Focusable

The tabindex attribute

By default, things like <div> or <li> cannot be focused. You can't tab to them, and they don't fire focus/blur events. The tabindex attribute fixes this.

Tabindex Values

Value Effect
tabindex="0" Makes it focusable, and it follows the natural Tab order of the page. Most common use.
tabindex="-1" Makes it focusable via code (elem.focus()), but the Tab key will skip it.
tabindex="1+" Makes it focusable, and it jumps to the FRONT of the Tab line. (Rarely used, can confuse users).
⚠️ Delegation Warning: focus and blur do not bubble up. If you want to catch focus on any input inside a form, you must catch them during the "capturing" phase, or use the modern focusin / focusout events which do bubble.

Change vs. Input Events

When is a change actually a change?

The biggest mistake developers make with forms is using the wrong event for tracking typing. Here is the difference:

The input Event

Fires immediately every single time the value changes. Every keystroke, every paste, even speech-to-text triggers it.

input.oninput = function() { result.innerHTML = input.value; };

The change Event

Fires only after the user is finished and leaves the field (blur). For text inputs, this means it fires on blur. For checkboxes/selects, it fires right when you click them.

Analogy: input is like autocorrect—reacting to every letter. change is like hitting "Send"—only caring about the final message. Use input for live character counts, and change for saving data to a server when the user leaves the field.

Clipboard Events

cut, copy, and paste

You can intercept when a user copies, cuts, or pastes data. This is useful for logging, or preventing users from pasting invalid data (like in a password confirmation field).

Intercepting Paste

input.onpaste = function(event) { // Read what is being pasted let pastedText = event.clipboardData.getData('text/plain'); alert("Pasting: " + pastedText); // Prevent the paste entirely: event.preventDefault(); };
⚠️ Security Limits: The clipboard is an OS-level feature. Browsers restrict access to it. You can only read clipboard data safely inside the event handler itself. You can't save it and read it later, and you cannot generate "fake" clipboard events via code.

Form Submission

The submit event

When a user clicks a Submit button or presses Enter inside an input, the form tries to submit to the server. The submit event is your last chance to check the data!

Catching Submission

form.onsubmit = function(event) { if (!isValid) { alert("Form is invalid!"); event.preventDefault(); // STOP the submission! } }; <form onsubmit="return false"> // Quick HTML way to block
How forms submit: There are only two ways a form naturally submits: 1) Clicking <input type="submit">, or 2) Pressing Enter inside a text input. (Note: Pressing Enter actually triggers a "click" on the submit button behind the scenes!)

Programmatic Submission

form.submit()

Sometimes you want to send a form using JavaScript, without the user clicking a button. You can do this with form.submit().

Sending a form via code

let form = document.createElement('form'); form.action = 'https://google.com/search'; form.method = 'GET'; form.innerHTML = '<input name="q" value="test">'; // Form must be in the document to submit document.body.append(form); form.submit();
⚠️ Skip the Event: When you call form.submit(), the browser sends the data immediately. It does not fire the submit event! This is by design—because as the programmer, you are assumed to have already validated the data before calling it.

Summary

Key takeaways for Forms & Events

Navigation

  • document.forms[name/index] to find forms.
  • form.elements[name/index] to find inputs.
  • element.form to find the parent form.

Values

  • Text: input.value
  • Checkboxes/Radios: input.checked
  • Selects: select.value or select.selectedIndex

Events

  • focus/blur: Element gets/loses attention. Use tabindex for non-inputs.
  • input: Every character change (immediate).
  • change: After the change is committed (on blur).
  • submit: Form is being sent. Use preventDefault() to stop it.
