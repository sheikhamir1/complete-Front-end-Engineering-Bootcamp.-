The Browser Environment & DOM

How JavaScript talks to the Web Page

JavaScript was born in the browser, but it has grown to run on servers (Node.js) and even smart devices. Each place JS runs is called a Host Environment.

The host environment provides its own objects and functions. In the browser, the "root" object of everything is window.

Real-World Analogy: Think of the browser as a house. The window object is the master control panel of that house. It lets you control the global settings (global object) and open/close the windows (browser window controls).

The Three Pillars of the Browser

DOM, CSSOM, and BOM

The browser's functionality is split into three main areas. Here is how they break down:

1. DOM (Document Object Model)

Represents the page content. Everything inside the HTML is converted into objects that you can modify.

// Change the page background to red for 1 second document.body.style.background = "red"; setTimeout(() => document.body.style.background = "", 1000);

2. CSSOM (CSS Object Model)

Represents CSS rules and stylesheets. Used together with the DOM to modify styling. In practice, we rarely use it directly because we usually just add/remove CSS classes instead of rewriting CSS rules in JS.

3. BOM (Browser Object Model)

Represents everything else the browser provides besides the document. This includes the navigator (browser info), location (current URL), and user prompts.

// Redirect the browser location.href = "https://wikipedia.org"; // Browser info alert(navigator.userAgent);

The DOM Tree

How HTML becomes Objects

Tags become Nodes

According to the DOM, every HTML tag is an object. Nested tags are "children" of the enclosing one. Even the text inside a tag is an object! All of these objects form the "DOM Tree".

Real-World Analogy: A family tree. The <html> tag is the grandparent at the top. <head> and <body> are the parents, and the tags inside them are the children. The text inside the tags are the "leaves" of the tree.

The 4 Main Node Types

  • Document: The main "entry point" into the DOM.
  • Element nodes: HTML tags (<div>, <p>), the building blocks.
  • Text nodes: Contain the actual text. They cannot have children (they are leaves).
  • Comments: <!-- comment --> Even these become nodes in the tree!

Watch out for spaces! Spaces and line breaks between tags are valid characters and become #text nodes in the DOM. If you minify your HTML to one line, these empty text nodes disappear.

DOM Autocorrection

The browser fixes your mistakes

If the browser encounters malformed HTML, it automatically corrects it when building the DOM. The browser will always create a valid DOM tree.

Missing tags? Added.

If you just type "Hello" in an empty file, the browser wraps it in <html>, <head>, and <body>.

Unclosed tags? Closed.

Writing <p>Hello<li>Mom<li>Dad will automatically be fixed into properly closed <p> and <li> nodes in the DOM.

The Table Exception: Tables always have a <tbody> in the DOM. Even if you don't write it in your HTML, the browser will automatically insert it between <table> and <tr>. Keep this in mind when styling or navigating tables!

Walking the DOM: Top Level

Starting at the top of the tree

All operations on the DOM start with the document object. The topmost tree nodes are available directly as its properties.

The Big Three

Property Represents HTML Tag
document.documentElement The root element <html>
document.body The body element <body>
document.head The head element <head>
Important Catch: A script cannot access an element that doesn't exist yet! If your script is inside <head>, document.body will be null because the browser hasn't loaded the body yet. In the DOM world, null means "doesn't exist".

Children vs. Descendants

Direct kids vs. the whole family

Before we navigate, we must clarify two important terms:

  • Child Nodes (Children): Elements that are directly nested inside the given element. (e.g., <head> and <body> are children of <html>).
  • Descendants: ALL elements nested inside the given element, including children, their children, and so on. (e.g., <li> is a descendant of <body>).
Real-World Analogy: You are a direct child of your parents. You are a descendant of your grandparents. Children are immediate; descendants go on for generations.

Navigating All Children

These properties access all nodes, including text nodes (spaces) and comments:

// Collection of all direct children document.body.childNodes // Shortcuts to first and last child document.body.firstChild document.body.lastChild

DOM Collections

Array-like, but not Arrays

When you access something like childNodes, it returns a collection. Collections look like arrays, but they are special.

What you CAN do ✅

You can iterate over them using for..of.

for (let node of document.body.childNodes) { alert(node); }

What you CANNOT do ❌

You cannot use Array methods like filter(), map(), etc., because it's not a true Array.

document.body.childNodes.filter // undefined! // Fix: Convert to Array first let arr = Array.from(document.body.childNodes); arr.filter // function!

Two Golden Rules of Collections

  • They are Live: If you save elem.childNodes to a variable, and later add a new HTML element to the page, it automatically appears in your variable!
  • They are Read-Only: You cannot replace a child by doing childNodes[i] = .... Changing the DOM requires specific methods.

Element-Only Navigation

Ignoring the text and comment nodes

Navigating with childNodes is annoying because you have to skip over blank text nodes and comments. For real-world tasks, we usually only care about Element Nodes (HTML tags).

JavaScript provides a second set of navigation properties that ignores everything except elements!

Comparison Table

All Nodes (incl. text) Element Nodes Only
childNodes children
firstChild firstElementChild
lastChild lastElementChild
previousSibling previousElementSibling
nextSibling nextElementSibling
parentNode parentElement
parentNode vs parentElement: They are almost identical. The only difference is at the very top: document.documentElement.parentNode returns document, but document.documentElement.parentElement returns null (because document is not an Element node).

Special Table Navigation

Built-in shortcuts for tables

Tables are complex, so the DOM provides extra, convenient properties specifically for navigating <table> elements. These save you from writing long chains of children.

Table Properties

table.rows // Collection of all <tr> elements table.caption // Reference to <caption> table.tHead // Reference to <thead> table.tFoot // Reference to <tfoot> table.tBodies // Collection of <tbody> (always at least one!)

Row & Cell Properties

tbody.rows // Collection of <tr> inside a tbody/thead/tfoot tr.cells // Collection of all <td> and <th> in this row tr.sectionRowIndex // Position of this <tr> inside its section tr.rowIndex // Position of this <tr> in the whole table td.cellIndex // Position of this <td> inside its row
Quick Example: To highlight the second column of the first row, you can do: table.rows[0].cells[1].style.background = "red";
