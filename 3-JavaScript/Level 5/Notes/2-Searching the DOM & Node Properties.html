Searching the DOM & Node Properties

Finding elements and understanding what they are

Navigating the DOM with parent/children properties is great, but what if you need to find a specific element anywhere on the page? And once you find it, how do you read or change its contents?

Real-World Analogy: Think of an HTML page as a massive warehouse. Navigating the DOM is like walking aisle by aisle. Search methods are like using the warehouse computer to instantly locate a specific item by its barcode or description.

The Modern Search Methods

querySelector & querySelectorAll

1. document.getElementById('id')

The classic way. It finds exactly one element by its unique ID. It only works on the document object.

Don't use ID as a global variable! Browsers automatically create global variables from IDs (e.g., <div id="elem"> creates window.elem). This is a bad practice because it causes naming conflicts. Always use document.getElementById().

2. elem.querySelector(css)

The modern, powerful way. It searches inside elem and returns the first element that matches the CSS selector.

// Find the first
  • inside .menu
    •  let firstItem = document.querySelector('.menu li');

    3. elem.querySelectorAll(css)

    Returns a collection of ALL elements matching the CSS selector. You can loop over it with for..of.

    // Find all links inside the nav let navLinks = document.querySelectorAll('nav a'); for (let link of navLinks) { alert(link.href); }

    Special Search Helpers

    matches & closest

    elem.matches(css)

    This doesn't search the DOM. It just checks if the current element matches a specific CSS selector. It returns true or false.

    Analogy: Like a bouncer checking your ID against a rule. The bouncer doesn't search the street for you; they just check if YOU match the criteria.
    if (elem.matches('a[href$="zip"]')) { alert("It's a ZIP file link!"); }

    elem.closest(css)

    Searches upwards from the current element to find the nearest ancestor (parent, grandparent, etc.) that matches the CSS selector. The element itself is also checked.

    Analogy: Like asking "Who is the nearest manager above me in the company chain of command?"
    // Find the closest .book container let chapter = document.querySelector('.chapter'); let book = chapter.closest('.book'); // UL

    Old School vs. New School

    "getElementsBy*" vs "querySelector*"

    You might see older methods in legacy code. They return live collections instead of static ones.

    The Old Methods

    • getElementsByTagName('div') - Note the "s" in Elements!
    • getElementsByClassName('article')
    • getElementsByName('age')

    Live vs. Static Collections

    Feature getElementsBy* (Old) querySelectorAll (New)
    Collection Type Live (Auto-updates if DOM changes) Static (Frozen snapshot in time)
    Array Methods? No (Needs Array.from) No (Needs Array.from)
    Best Practice? Avoid in modern code ✅ Use this!
    The "Live" Trap: If you use getElementsByTagName and add a new element to the page, the collection's length magically increases. With querySelectorAll, the length stays the same as when you called it.

    Node Properties: Type & Tag

    What kind of node is this?

    Every DOM node belongs to a class in JavaScript (like HTMLInputElement, HTMLBodyElement). They all inherit from the base EventTarget -> Node -> Element -> HTMLElement chain.

    nodeType

    An old-school numeric way to check the type of node.

    // 1 = Element (e.g., <div>) // 3 = Text node (e.g., spaces/text) // 9 = Document object alert(elem.nodeType); // 1

    tagName vs nodeName

    Both return the tag name in UPPERCASE (e.g., "DIV").

    // tagName only works for Elements // nodeName works for ANY node // For a comment node: comment.tagName; // undefined comment.nodeName; // #comment
    Rule of Thumb: If you are only dealing with HTML elements, use tagName. If you might be dealing with text or comments, use nodeName.

    Contents: innerHTML & outerHTML

    Reading and replacing HTML

    innerHTML

    Gets or sets the HTML inside the element. It allows you to insert valid HTML tags.

    // Read contents alert(document.body.innerHTML); // Replace contents entirely document.body.innerHTML = 'The new BODY!';
    ⚠️ The innerHTML += Trap: Doing elem.innerHTML += "new" doesn't just append text. It erases the entire contents and rewrites them from scratch! This reloads all images and removes user input in forms.

    outerHTML

    Gets the full HTML of the element, including the element itself.

    let div = document.querySelector('div'); // Replaces the div in the DOM with a

    div.outerHTML = '<p>A new element</p>'; // BUT the old 'div' variable still references the old object! alert(div.outerHTML); // Shows the old div, not the new <p>

    Safe Text & Hiding Elements

    textContent, data, and hidden

    textContent

    Gets/sets the text inside an element. It strips out all HTML tags completely.

    Safety First! Always use textContent to insert user input. If you use innerHTML, a user could inject malicious scripts (XSS). textContent treats everything as plain text.
    let userInput = "<b>Bold</b>"; elem.innerHTML = userInput; // Shows: Bold elem.textContent = userInput; // Shows: <b>Bold</b>

    nodeValue / data

    Used to read the content of non-element nodes, like text nodes or comments.

    let textNode = document.body.firstChild; alert(textNode.data); // The text content let comment = textNode.nextSibling; alert(comment.data); // The comment content

    The "hidden" property

    The DOM property hidden acts just like display: none in CSS. It's a quick way to show/hide elements.

    // Hide the element elem.hidden = true; // Blinking element example setInterval(() => elem.hidden = !elem.hidden, 1000);

    Attributes vs. Properties

    The blueprint vs. the real object

    When the browser loads HTML, it reads the attributes (what's written in the HTML) and creates properties (what lives in the DOM object). They are usually synced, but not always!

    The Core Difference

    Feature HTML Attributes DOM Properties
    What is it? The value written in HTML The value in the JS object
    Data Type Always a String Can be Any type (String, Boolean, Object)
    Case Sensitive? No (ID is same as id) Yes (must use elem.id)
    The input.value Exception: If a user types into an input field, the DOM property input.value updates immediately. But the HTML attribute input.getAttribute('value') stays the original value from the HTML source! The attribute represents the "initial" value; the property represents the "current" value.

    Custom Data & dataset

    Passing data safely via HTML

    The Problem with Custom Attributes

    Sometimes we want to attach custom data to HTML elements for JavaScript to read. But making up our own attributes (like show-info="name") is risky because future HTML standards might use that name.

    The Solution: data-*

    Any attribute starting with data- is reserved for developers. It will never conflict with standard HTML. These are accessed cleanly via the dataset property.

    <div id="order" data-order-state="new" data-user-id="123"> let order = document.querySelector('#order'); // Read data attributes alert(order.dataset.orderState); // "new" (hyphens become camelCase) alert(order.dataset.userId); // "123" // Modify data attributes order.dataset.orderState = "pending"; // Updates the HTML instantly!
    Real-World Analogy: Think of data-* attributes like a secure luggage tag. You can attach any custom information you want to the element (the suitcase), and JavaScript can easily read it to know how to handle it. Plus, it can be used to trigger CSS styles!
