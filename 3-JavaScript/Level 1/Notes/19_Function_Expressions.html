JavaScript Function Expressions

Understanding the power and flexibility of functions as values in JavaScript

Introduction 👋

What are Function Expressions?

A way to create functions as part of expressions rather than standalone statements

Why are they important?

  • Functions as values
  • Flexible code organization
  • Essential for callbacks

Key Takeaway

"In JavaScript, functions are not just syntax - they're values that can be assigned, passed, and manipulated like any other value."

Function Declaration vs Expression ⚖️

Function Declaration

A function declared as a separate statement:
function sayHi() {
  alert("Hello");
}
Visible everywhere in the block
Can be called before declaration
More "eye-catching" in code

Function Expression

A function created inside an expression:
let sayHi = function() {
  alert("Hello");
};
Created when execution reaches it
Can be conditional
Useful for callbacks

Key Differences

Syntax
Declaration: function name() {...}
Expression: let name = function() {...}
Creation Time
Declaration: Before code execution
Expression: When execution reaches it
Use Case
Declaration: General purpose
Expression: Conditional, callbacks

Functions as Values 💎

Functions Are Special Values

Functions can be treated like any other value:
function sayHi() {
  alert("Hello");
}

// Display function code
alert(sayHi); // No parentheses!
Can be assigned to variables
Can be copied to other variables
Can be passed as arguments

Copying Functions

Functions can be copied between variables:
function sayHi() {
  alert("Hello");
}

// Copy the function
let func = sayHi;

// Both work identically
func(); // Hello
sayHi(); // Hello
Key Insight
No parentheses = function as value
With parentheses = function execution

Functions as Actions 🚀

Data Values
Strings, numbers, objects represent data
Function Values
Functions represent actions
Powerful Combination
Pass actions around like data for flexible code

Callback Functions 🔄

What Are Callbacks?

Functions passed as arguments to be called later:
function ask(question, yes, no) {
  if (confirm(question)) yes()
  else no();
}
Functions passed as arguments
"Called back" when needed
Essential for async operations

Using Callbacks

With Function Expressions:
ask(
  "Do you agree?",
  function() { alert("You agreed."); },
  function() { alert("You canceled."); }
);
Anonymous Functions
Callbacks are often anonymous (no name)
Created where needed, not stored in variables

Callback Flow 📊

1. Define
Create function expressions
2. Pass
Send as arguments
3. Store
Function holds reference
4. Execute
Call when needed

When to Choose 🤔

Use Function Declaration When:

Need visibility before declaration
Functions are hoisted and available throughout their scope
Better readability
Easier to spot in code with function name() {...} syntax
General purpose functions
Utility functions used throughout your code
// Good for:
function calculateTotal(items) {
  return items.reduce((sum, item) => sum + item.price, 0);
}

Use Function Expression When:

Conditional declaration
Need to define different functions based on conditions
Callbacks
Passing functions as arguments to other functions
Block scope needed
Function should only exist within a specific block
// Good for:
let welcome = (age < 18) ?
  function() { alert("Hello!"); } :
  function() { alert("Greetings!"); };

Decision Guide 📋

Function Declaration
Default choice for most functions
Function Expression
Special cases: callbacks, conditionals
Rule of thumb: Start with Function Declaration, switch to Expression when needed

Code Examples 💻

Basic Function Expression

Creating a function as a value:
// Function Expression
let greet = function(name) {
  return `Hello, ${name}!`;
};

// Using the function
console.log(greet("John")); // "Hello, John!"
The function is created at runtime when the execution reaches this line

Conditional Function

Creating functions based on conditions:
let age = 16;
let welcome;

if (age < 18) {
  welcome = function() {
    alert("Hello!");
  };
} else {
  welcome = function() {
    alert("Greetings!");
  };
}

welcome(); // "Hello!"
Function Expressions allow conditional function creation

Callback Function Example 🔄

Function that accepts callbacks:
function processArray(arr, callback) {
  const result = [];

  for (let i = 0; i < arr.length; i++) {
    result.push(callback(arr[i]));
  }

  return result;
}
Using the function with expressions:
const numbers = [1, 2, 3, 4];

// Double each number
const doubled = processArray(numbers, function(num) {
  return num * 2;
});

// Square each number
const squared = processArray(numbers, num => num * num);
Function Expressions are perfect for creating callbacks on the fly

Tips & Best Practices 💡

Best Practices

Use Function Declarations by default
They're hoisted and more readable
Use Expressions for callbacks
Perfect for anonymous functions
Remember the semicolon
Function Expressions are statements
Name your expressions when debugging
Improves stack traces

Common Mistakes

Calling before declaration
Function Expressions aren't hoisted
Forgetting semicolons
Can cause unexpected behavior
Using declarations conditionally
Different behavior across browsers
Confusing function vs function call
Missing parentheses when needed
