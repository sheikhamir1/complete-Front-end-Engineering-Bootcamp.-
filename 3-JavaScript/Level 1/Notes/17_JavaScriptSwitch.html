Introduction to Switch 🔀

What is Switch?

  • Replaces multiple if checks
  • More descriptive way to compare values
  • Uses strict equality (===) for comparison

Why Use Switch?

  • Cleaner code structure
  • Easier to read and maintain
  • Better for multiple value comparisons

When to Use Switch

Multiple Equality Checks

When comparing one value to many others

Menu Selection

For handling different user choices

State Machines

For managing different application states

Switch Syntax 📝

Basic Structure

switch(x) {
  case 'value1':  // if (x === 'value1')
    ...
    [break]
  case 'value2':  // if (x === 'value2')
    ...
    [break]
  default:
    ...
    [break]
}
switch(x) - expression to evaluate
case - possible values to match
default - executed if no match found

How It Works

1

Evaluate Expression

The value in switch() is evaluated once

2

Compare Cases

Value is compared to each case using strict equality (===)

3

Execute Code

When a match is found, code executes until break or end of switch

Key Points

Break is Important

Without break, execution continues to the next case

Strict Equality

Uses === comparison, so types must match

Any Expression

Both switch and case allow any valid expression

Switch Example 💻

With Break

let a = 2 + 2;
switch (a) {
  case 3:
    alert( 'Too small' );
    break;
  case 4:
    alert( 'Exactly!' );
    break;
  case 5:
    alert( 'Too big' );
    break;
  default:
    alert( "I don't know such values" );
}
a = 4, so it matches case 4
Only 'Exactly!' is displayed
Execution stops at break

Without Break

let a = 2 + 2;
switch (a) {
  case 3:
    alert( 'Too small' );
  case 4:
    alert( 'Exactly!' );
  case 5:
    alert( 'Too big' );
  default:
    alert( "I don't know such values" );
}
a = 4, matches case 4
All three alerts are shown:
'Exactly!', 'Too big', 'I don't know...'

Execution Flow

1

Match Found

Start executing code

2

Continue Until Break

Or end of switch

3

Exit Switch

Continue with rest of code

Expressions in Switch 🧮

Any Expression

let a = "1";
let b = 0;
switch (+a) {
  case b + 1:
    alert("this runs, because +a is 1, exactly equals b+1");
    break;
  default:
    alert("this doesn't run");
}
+a converts string to number
b + 1 evaluates to 1
Both expressions match, so case executes

Grouping Cases

let a = 3;
switch (a) {
  case 4:
    alert('Right!');
    break;
  case 3: // (*) grouped two cases
  case 5:
    alert('Wrong!');
    alert("Why don't you take a math class?");
    break;
  default:
    alert('The result is strange. Really.');
}
Both 3 and 5 execute same code
No break after case 3
Execution "falls through" to case 5

Advanced Techniques

Function Calls

You can use function calls in both switch and case expressions 

switch(getValue()) {
  case calculateResult():
    // code
}

Complex Logic

Combine multiple conditions using logical operators 

switch(true) {
  case x > 0 && x < 10:
    // code
}

Type Matters 🔍

Strict Equality

let arg = prompt("Enter a value?");
switch (arg) {
  case '0':
  case '1':
    alert( 'One or zero' );
    break;
  case '2':
    alert( 'Two' );
    break;
  case 3:
    alert( 'Never executes!' );
    break;
  default:
    alert( 'An unknown value' );
}
prompt returns a string
case 3 is a number
String "3" ≠ number 3

Type Conversion

To Make Types Match

// Convert to number
switch (+arg) {
  case 3:
    alert('Now it works!');
    break;
}

Or Convert in Cases

// Keep string, compare to strings
switch (arg) {
  case "3":
    alert('This works too!');
    break;
}

Common Type Pitfalls

String vs Number

"5" ≠ 5 in strict comparison

Boolean vs String

"true" ≠ true in strict comparison

Null vs Undefined

null ≠ undefined in strict comparison

Pro Tip: Always be mindful of data types when using switch. Convert values explicitly if needed to ensure proper matching.

Simple Calculator

function calculate(num1, num2, operator) {
  let result;
  
  switch (operator) {
    case '+':
      result = num1 + num2;
      break;
    case '-':
      result = num1 - num2;
      break;
    case '*':
      result = num1 * num2;
      break;
    case '/':
      result = num1 / num2;
      break;
    default:
      result = 'Invalid operator';
  }
  
  return result;
}

console.log(calculate(5, 3, '*')); // 15
Performing different operations based on operator

Tips & Best Practices 💡

Best Practices

Always Use Break

Unless you intentionally want fall-through behavior

Include Default Case

Handle unexpected values gracefully

Group Similar Cases

When they share the same code

Common Mistakes

Forgetting Break

Causing unintended fall-through behavior

Type Mismatch

Not accounting for strict equality comparison

Overusing Switch

When if-else or objects would be more appropriate

Performance Tips

Order Cases by Frequency

Put most common cases first for minor performance gain

Use for Simple Comparisons

Switch is optimized for simple value comparisons

Consider Alternatives

Objects or maps might be better for dynamic cases

Switch vs If-Else

// Switch: better for discrete values
switch (day) {
  case 0: // Sunday
    // code
}

// If-Else: better for ranges
if (score >= 90) {
  // A grade
} else if (score >= 80) {
  // B grade
}
