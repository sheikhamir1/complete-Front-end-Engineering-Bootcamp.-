Creating Variables

Using the 'let' keyword

let message; // declares a variable
message = 'Hello'; // stores a string
alert(message); // shows "Hello"

let - modern way to declare variables

= - assignment operator

let message = 'Hello!'; // declare & assign

Multiple Variables

Not Recommended
let user = 'John', age = 25, message = 'Hello';
Recommended
let user = 'John';
let age = 25;
let message = 'Hello';

A variable should be declared only once

Variable Analogy

Variables as "Boxes"

The Box Concept
  • Variable name = Label
  • Variable value = Contents
  • Assignment = Putting something in

You can change what's inside

You can copy contents to another box

let message; // create a box
message = 'Hello!'; // put "Hello!" in
message = 'World!'; // replace with "World!"
Copying Variables

When you copy a variable, you're creating a duplicate:

let hello = 'Hello world!';
let message;
message = hello; // copy value

'var' vs 'let'

let (Modern)

Modern way to declare variables

Block-scoped - visible within block

Cannot be redeclared in same scope

Recommended for modern JavaScript

let message = 'Hello';
// Works as expected

var (Old-school)

Old-school way to declare variables

Function-scoped - visible throughout function

Can be redeclared in same scope

Found in older scripts and legacy code

var message = 'Hello';
// Works but not recommended

Variable Naming Rules

Basic Rules

Allowed Characters
  • Letters (a-z, A-Z)
  • Digits (0-9)
  • Symbols $ and _
First Character

The first character cannot be a digit

Valid
let userName;
let _test;
let $value;
Invalid
let 1user;
let 123test;
let 7value;

Naming Conventions

camelCase

Multiple words joined together, each word (except first) starts with capital:

let myVariableName;
let shoppingCart;
let currentUser;

Reserved words cannot be used as variable names

let let = 5; // ERROR!
let return = 5; // ERROR!

Use English for international compatibility

Constants

Using 'const' Keyword

Immutable Variables

Constants declared using const cannot be reassigned

const myBirthday = '18.04.1982';
// Cannot be reassigned

Attempting to reassign causes an error

const myBirthday = '18.04.1982';
myBirthday = '01.01.2001'; // ERROR!

When to Use Constants

Uppercase Constants

Constants for hard-coded values use CAPITAL LETTERS:

const COLOR_RED = "#F00";
const COLOR_GREEN = "#0F0";
const COLOR_BLUE = "#00F";
Runtime Constants

Some constants calculated at runtime but don't change:

const pageLoadTime = /* time taken */;
// Named normally, not in uppercase

Best Practices

Naming Conventions

Descriptive Names

Variable names should have a clean, obvious meaning

Good
let userName;
let shoppingCart;
let currentPage;
Bad
let a;
let b;
let c;

Think before naming - good names save time later

Descriptive vs. Generic Names

Be specific - avoid generic names like "data" or "value"

Be concise - but not at the expense of clarity

Avoid ambiguity - names should be self-explanatory

Reuse or Create?

Create new variables for different values rather than reusing existing ones

An extra variable is good, not evil

Summary

Variable Declaration
  • let - Modern, block scope
  • var - Old-school, function scope
  • const - For unchanging values
Naming Rules
  • Use letters, digits, $, _
  • First character not a digit
  • camelCase for multi-word names
Best Practices
  • Use descriptive names
  • Maintain consistency
  • Create new variables rather than reusing
Key Concepts
  • Variables are named storage for data
  • Values can be changed (except constants)
  • Avoid reserved words as names

Variables are fundamental building blocks. Good naming and proper declaration make code more readable and maintainable.
