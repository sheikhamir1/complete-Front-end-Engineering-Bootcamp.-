Comparisons in JavaScript

Understanding equality and relational operators

Introduction 🔍

Comparison Operators

  • • Greater/less than: a > b, a < b
  • • Greater/less than or equals: a >= b, a <= b
  • • Equals: a == b (double equals)
  • • Not equals: a != b

Key Concepts

  • • Boolean results (true or false)
  • • String comparison (lexicographical order)
  • • Type conversion in comparisons
  • • Strict equality (===) vs loose equality (==)

Why This Matters 💡

Understanding comparison operators is essential for controlling program flow and making decisions in JavaScript. They form the foundation of conditional statements and loops.

Boolean Results ✅

True or False

All comparison operators return a boolean value:

true

"yes", "correct"

false

"no", "wrong"

Assignment to Variables

Comparison results can be assigned to variables:

let result = 5 > 4; // true
alert(result); // true

Examples

2 > 1 true
2 == 1 false
2 != 1 true

Use Cases

  • Conditional statements (if/else)
  • Loop conditions
  • Filtering data

String Comparison 🔤

Lexicographical Order

Strings are compared letter-by-letter using "dictionary" order:

alert('Z' > 'A'); // true
alert('Glow' > 'Glee'); // true
alert('Bee' > 'Be'); // true

Comparison Algorithm

  1. Compare first characters of both strings
  2. If different, the string with the greater character is greater
  3. If same, move to next character and repeat
  4. If one string ends, it's considered smaller
  5. If both end at same length, they're equal

Case Sensitivity

String comparison is case-sensitive due to Unicode encoding:

'a' > 'Z' true
'A' > 'a' false

Lowercase letters have higher Unicode values than uppercase letters.

Different Types Comparison 🔄

Type Conversion

When comparing different types, JavaScript converts values to numbers:

alert('2' > 1); // true
alert('01' == 1); // true

Boolean Conversion

Booleans are converted to numbers in comparisons:

true == 1 true
false == 0 true

true becomes 1, false becomes 0

Funny Consequence

Two values can be equal in comparison but have different boolean values:

let a = 0;
alert(Boolean(a)); // false

let b = "0";
alert(Boolean(b)); // true

alert(a == b); // true!

This happens because equality check uses numeric conversion, while explicit Boolean conversion uses different rules.

Conversion Rules

Value Numeric Boolean
"0" 0 true
"" 0 false
true 1 true
false 0 false

Strict Equality ⚖️

Problem with ==

Regular equality == can't differentiate between different types:

0 == false true
'' == false true

This happens because operands are converted to numbers before comparison.

Strict Equality ===

Strict equality checks both value and type without conversion:

alert(0 === false); // false
alert('' === false); // false

If types are different, === immediately returns false.

Strict Non-Equality !==

Similar to === but checks for non-equality:

alert(0 !== false); // true
alert('' !== false); // true

Use strict operators to avoid unexpected type coercion issues.

Comparison Table

Expression == Result === Result
0 == false true false
'' == false true false
null == undefined true false
'5' == 5 true false

Null & Undefined Comparison ❓

Strict Equality ===

null and undefined are different types:

alert(null === undefined); // false

Non-Strict Equality ==

null and undefined equal each other but nothing else:

alert(null == undefined); // true
alert(null == 0); // false
alert(undefined == 0); // false

Mathematical Comparisons

In comparisons, null becomes 0 and undefined becomes NaN:

alert(null > 0); // false
alert(null == 0); // false
alert(null >= 0); // true

The null vs 0 Paradox

Why these results seem contradictory:

null > 0 false

null converts to 0, which is not > 0

null == 0 false

Special rule: null only equals undefined

null >= 0 true

null converts to 0, which is >= 0

Incomparable undefined

undefined converts to NaN in comparisons:

alert(undefined > 0); // false
alert(undefined < 0); // false
alert(undefined == 0); // false

NaN returns false for all comparisons, including with itself!

Code Examples 💻

Basic Comparisons 

// Numeric comparisons
alert(5 > 3);        // true
alert(10 >= 10);     // true
alert(7 < 2);        // false

// String comparisons
alert('Apple' < 'Banana');  // true
alert('apple' > 'Banana');  // true (case-sensitive)

// Mixed type comparisons
alert('5' == 5);     // true
alert('5' === 5);    // false

Boolean Comparisons 

// Boolean to number conversion
alert(true == 1);    // true
alert(false == 0);   // true
alert(true === 1);   // false (different types)

// Boolean in expressions
let isActive = true;
alert(isActive == 1); // true
alert(isActive === 1); // false

Null & Undefined Comparisons 

// Null comparisons
alert(null == undefined);  // true
alert(null === undefined); // false
alert(null == 0);          // false
alert(null >= 0);          // true

// Undefined comparisons
alert(undefined == null);   // true
alert(undefined === null);  // false
alert(undefined > 0);       // false
alert(undefined < 0);       // false

Practical Example 

// Function to check if a value is "empty"
function isEmpty(value) {
  // Check for null, undefined, empty string, 0, false
  return value == null || value === '' || value === 0 || value === false;
}

// Test cases
alert(isEmpty(null));        // true
alert(isEmpty(undefined));   // true
alert(isEmpty(''));          // true
alert(isEmpty(0));           // true
alert(isEmpty(false));       // true
alert(isEmpty('hello'));     // false
alert(isEmpty(42));          // false

Best Practices & Summary ✨

Best Practices

  • Use strict equality (===) and strict inequality (!==) by default
  • Be cautious when comparing with null/undefined
  • Remember that string comparison is case-sensitive
  • Check for null/undefined separately when needed

Common Pitfalls

  • Forgetting that == converts types before comparison
  • Using > or < with variables that might be null/undefined
  • Assuming '0' is falsy in boolean context (it's truthy)
  • Forgetting that undefined converts to NaN in comparisons

Summary 📝

  • • Comparison operators return boolean values (true/false)
  • • Strings are compared lexicographically (dictionary order)
  • • Different types are converted to numbers in comparisons (except strict equality)
  • • null and undefined equal each other (==) but not other values
  • • Be cautious with comparisons involving null/undefined
