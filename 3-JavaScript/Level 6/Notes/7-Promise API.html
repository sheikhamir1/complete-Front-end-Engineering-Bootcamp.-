Promise API

Handling multiple promises simultaneously

Sometimes we need to execute many asynchronous tasks at once. The Promise class provides 6 static methods to handle multiple promises simultaneously.

Real-World Analogy: The Restaurant Kitchen 🍳
A chef has 5 dishes to prepare. They can start all 5 at the same time (parallel). Depending on the recipe, they might need all dishes ready before serving (Promise.all), or they might serve the first dish that's ready (Promise.race).

Promise.all

Wait for ALL to succeed

Promise.all takes an array of promises and returns a single new promise. This new promise resolves only when all the input promises resolve.

Example

Promise.all([
  new Promise(resolve => setTimeout(() => resolve(1), 3000)),
  new Promise(resolve => setTimeout(() => resolve(2), 2000)),
  new Promise(resolve => setTimeout(() => resolve(3), 1000))
]).then(alert); // After 3 seconds, alerts [1, 2, 3]
Key Details:
1. Order is preserved: Even though the 3rd promise resolves first, the result array order matches the input array order.
2. Regular values allowed: You can pass non-promise values directly. Promise.all([fetch(url), "Hello"]) works perfectly!
3. "All or Nothing": If even ONE promise rejects, the entire Promise.all immediately rejects.

Promise.all: Fails Fast

What happens when one fails?

If any promise in the array rejects, Promise.all immediately rejects with that error, and the results of the other promises are completely ignored.

Example: One rejection ruins it

Promise.all([
  new Promise((resolve, reject) => setTimeout(() => resolve(1), 1000)),
  new Promise((resolve, reject) => setTimeout(() => reject(new Error("Whoops!")), 2000)),
  new Promise((resolve, reject) => setTimeout(() => resolve(3), 3000))
]).catch(alert); // Alerts "Error: Whoops!" after 2 seconds

Are the other promises cancelled?

No. Promises don't have a "cancel" concept. The other promises will still run and settle in the background, but Promise.all simply stops watching them and ignores their results.

Promise.allSettled

Wait for ALL to finish (success or fail)

Sometimes we want the results of all promises, even if some fail. Promise.allSettled waits for every promise to finish (settle) and returns an array of objects describing the outcome.

Result Format

  • For success: {status: "fulfilled", value: result}
  • For failure: {status: "rejected", reason: error} 
Promise.allSettled([
  fetch('/user.json'),      // succeeds
  fetch('/no-such-url')     // fails
]).then(results => {
  results.forEach(result => {
    if (result.status == "fulfilled") {
      alert("Success: " + result.value);
    }
    if (result.status == "rejected") {
      alert("Failed: " + result.reason);
    }
  });
});
Analogy: Taking Attendance 📋
You need to know the status of everyone. If someone is absent (rejected), you mark them absent, but you don't cancel the whole class! You still record the present students (fulfilled) too.

Promise.race vs Promise.any

Waiting for the FIRST result

Promise.race

Waits for the first promise to settle, regardless of success or failure. If the fastest promise rejects, the whole race rejects. 

Promise.race([
  new Promise((resolve, reject) => 
    setTimeout(() => reject(new Error("Ouch!")), 1000)),
  new Promise(resolve => 
    setTimeout(() => resolve(1), 2000))
]).catch(alert); 
// Alerts "Ouch!" after 1s

Analogy: A sprint where the first person to cross the finish line OR trip and fall wins the race.

Promise.any

Waits for the first promise to fulfill (succeed). It ignores rejections until one succeeds. If ALL fail, it returns a special AggregateError. 

Promise.any([
  new Promise((resolve, reject) => 
    setTimeout(() => reject(new Error("Ouch!")), 1000)),
  new Promise(resolve => 
    setTimeout(() => resolve(1), 2000))
]).then(alert); 
// Alerts 1 after 2s

Analogy: Interviewing candidates. You ignore the rejects until you find the first successful hire.

Promise.resolve & Promise.reject

Creating already-settled promises

These methods create promises that are instantly resolved or rejected. They are rarely needed in modern code (thanks to async/await), but useful for compatibility when a function must return a Promise.

Promise.resolve(value)

// These two are identical:
let p1 = new Promise(resolve => resolve(123));
let p2 = Promise.resolve(123);

p2.then(alert); // 123

Promise.reject(error)

// These two are identical:
let p1 = new Promise((resolve, reject) => 
  reject(new Error("Fail")));
let p2 = Promise.reject(new Error("Fail"));

p2.catch(alert); // Error: Fail
Real-World Use Case: Caching 🗄️
If a function fetches a URL, it returns a Promise. But if the data is already cached, we can instantly return Promise.resolve(cachedData). This guarantees the function always returns a Promise, so the caller can always use .then()!

Summary

The 6 static methods of Promise

Method Waits for... Fails if...
Promise.all All promises to resolve Any promise rejects (ignores others)
Promise.allSettled All promises to settle Never fails; returns status for each
Promise.race First promise to settle Fails if the fastest promise rejects
Promise.any First promise to fulfill Fails only if ALL promises reject (AggregateError)
Promise.resolve N/A (instantly resolves) N/A
Promise.reject N/A (instantly rejects) N/A (always fails)
Most Common: In everyday development, Promise.all is by far the most frequently used method for running tasks in parallel!
