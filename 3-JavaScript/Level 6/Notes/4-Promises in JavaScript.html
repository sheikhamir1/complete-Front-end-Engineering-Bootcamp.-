Promises in JavaScript

The modern way to handle asynchronous results

A Promise is a special JavaScript object that links the "producing code" (which takes time) with the "consuming code" (which wants the result).

Real-World Analogy: The Singer & Fans 🎤
You’re a top singer. Fans ask day and night for your upcoming song. To get relief, you promise to send it when published. You give them a subscription list. When the song is ready, they all get it. Even if the studio burns down and you can't publish, they still get notified of the failure. The subscription list is the Promise.

The Promise Constructor

Creating a new promise

We create a Promise using the new Promise constructor, which takes a function called the executor. The executor runs automatically and contains the "producing code".

Syntax

let promise = new Promise(function(resolve, reject) {
  // Executor: The producing code (the "singer")
});

The Two Callbacks

The executor receives two arguments provided by JavaScript:

  • resolve(value): Call this when the job is finished successfully. The value is the result.
  • reject(error): Call this if an error occurs. The error is the error object.
Key Rule: The executor should call resolve OR reject. Only one! A job can only have one final result or one error. Any further calls are ignored.

Promise States

From pending to settled

A Promise object has internal properties: state and result. We can't access them directly, but they dictate how the promise behaves.

State Result When it happens
"pending" undefined Initial state. The executor is still working.
"fulfilled" value resolve(value) was called.
"rejected" error reject(error) was called.

Success vs Failure

// Fulfilled Promise
let promiseSuccess = new Promise(function(resolve, reject) {
  setTimeout(() => resolve("done!"), 1000);
});

// Rejected Promise
let promiseFail = new Promise(function(resolve, reject) {
  setTimeout(() => reject(new Error("Whoops!")), 1000);
});
Settled: A promise that is either "fulfilled" or "rejected" is called settled. Also, always reject with Error objects, not raw strings!

Consumers: then & catch

Subscribing to the result or error

State and result are internal. To actually use the outcome, we use the methods .then() and .catch().

.then() - The main handler

promise.then(
  function(result) { /* handle success */ },
  function(error) { /* handle error */ }
);

The first argument runs if resolved; the second runs if rejected. If you only care about success, just provide one argument.

.catch() - Shorthand for errors

// These two lines do the exact same thing:
promise.catch(alert); 
promise.then(null, alert);

If you only care about errors, use .catch(). It's cleaner than passing null to .then().

Cleanup: finally

Code that runs no matter what

Just like try...catch...finally, promises have a .finally() method. It runs when the promise is settled, regardless of success or failure.

Analogy: The Party Cleanup 🧹

Irrespective of whether the party was great (resolved) or a disaster (rejected), you still have to clean up the house afterward.

How it works

new Promise((resolve, reject) => {
  /* do time-consuming work */
})
  .finally(() => stopLoadingIndicator())
  .then(result => showResult, err => showError);
Important Differences:
1. A finally handler has NO arguments. It doesn't know if it was a success or error.
2. It "passes through" the result/error to the next handler.
3. If it returns anything, it's ignored (unless it throws an error).

Late Subscriptions

Adding handlers to already settled promises

What if you add a .then() handler after the promise has already resolved? It runs immediately!

Immediate Execution

// The promise resolves immediately
let promise = new Promise(resolve => resolve("done!"));

// This runs right now, even though it's "late"
promise.then(alert); // done!
Promises vs Real Life: In real life, if you subscribe to a singer's list after the song is released, you miss it. In JavaScript, Promises are more flexible! If you subscribe (using .then) after the result is already there, your handler just executes immediately. You never miss the result.

Real-World Example: loadScript

Converting callbacks to Promises

Remember our callback-based loadScript function? Let's rewrite it to return a Promise. Instead of taking a callback, it resolves or rejects based on the script loading. 

function loadScript(src) {
  return new Promise(function(resolve, reject) {
    let script = document.createElement('script');
    script.src = src;

    script.onload = () => resolve(script);
    script.onerror = () => reject(new Error(`Load error for ${src}`));

    document.head.append(script);
  });
}

// Usage is much cleaner!
let promise = loadScript("my.js");
promise.then(script => alert('Loaded!'));
promise.catch(err => alert(err));
Feature Promises Callbacks
Order Natural order: call function, then write what to do with result. Must pass callback before you know the result.
Multiple Listeners Can call .then() multiple times on same promise. Only one callback allowed.
