Promises Chaining

Executing asynchronous tasks in sequence

We often need to execute a sequence of asynchronous tasks one after another—like loading scripts one by one. Promises provide an elegant way to do this called chaining.

Real-World Analogy: The Relay Race 🏃‍♂️
In a relay race, Runner 1 finishes their leg and passes the baton (result) to Runner 2. Runner 2 takes it, runs, and passes it to Runner 3. In JavaScript, the baton is the result, and the runners are .then() handlers.

The Basics of Chaining

Passing results down the line

The whole concept works because every call to .then() returns a new promise. When a handler returns a value, that value becomes the result of that new promise.

Example: Doubling a number

new Promise(function(resolve, reject) {
  setTimeout(() => resolve(1), 1000); // (*)

}).then(function(result) { // (**)
  alert(result); // 1
  return result * 2;

}).then(function(result) { // (***)
  alert(result); // 2
  return result * 2;

}).then(function(result) {
  alert(result); // 4
  return result * 2;

});
The Flow: The initial promise resolves with 1. The first .then catches it, returns 2. The second .then catches 2, returns 4. The sequence of alerts is 1 → 2 → 4.

The Classic Newbie Error

Multiple handlers vs. Chaining

Technically, you can add many .then() handlers to a single promise. This is NOT chaining; they process the result independently.

Wrong: Adding to one promise

let promise = new Promise(
  resolve => resolve(1)
);

promise.then(r => alert(r)); // 1
promise.then(r => alert(r)); // 1
promise.then(r => alert(r)); // 1

All handlers get the same result (1). They don't pass data to each other.

Right: Chaining

let promise = new Promise(
  resolve => resolve(1)
);

promise
  .then(r => { alert(r); return r*2; })
  .then(r => { alert(r); return r*2; })
  .then(r => { alert(r); });

Each handler passes its transformed result to the next handler.

Returning Promises

Making the chain wait for async work

A .then() handler doesn't just return values; it can also return a new Promise. If it does, the rest of the chain waits until that new promise settles.

Adding delays to the chain

new Promise(resolve => resolve(1))
  .then(function(result) {
    alert(result); // 1
    return new Promise((resolve, reject) => {
      setTimeout(() => resolve(result * 2), 1000);
    });
  })
  .then(function(result) {
    alert(result); // 2 (shows after 1 second delay!)
    return result * 2;
  });
Analogy: The Drive-Thru 🚗
You order at the speaker (Promise 1 resolves). You drive to the first window to pay (return Promise 2). The second window waits until you pay before handing you the food. Returning a promise makes the next step wait for your async task to finish!

Real-World Example: loadScript

Loading scripts sequentially without the Pyramid of Doom

Let's use our promisified loadScript to load scripts one by one. Because loadScript returns a promise, we can chain them.

Clean, flat code

loadScript("/article/promise-chaining/one.js")
  .then(script => loadScript("/article/promise-chaining/two.js"))
  .then(script => loadScript("/article/promise-chaining/three.js"))
  .then(script => {
    // Scripts are loaded sequentially!
    one();
    two();
    three();
  });
Notice the shape: The code grows downwards, not to the right. We have completely eliminated the "Pyramid of Doom" that we had with callbacks, while ensuring each script waits for the previous one to finish.

Thenables

Promise-compatible custom objects

To be precise, a handler can return an object that has a method called .then(). This is called a thenable. JavaScript treats it exactly like a native Promise.

A custom Thenable

class Thenable {
  constructor(num) {
    this.num = num;
  }
  then(resolve, reject) {
    alert(resolve); // native resolve function
    setTimeout(() => resolve(this.num * 2), 1000);
  }
}

new Promise(resolve => resolve(1))
  .then(result => {
    return new Thenable(result); // returns a thenable
  })
  .then(alert); // shows 2 after 1000ms
Why does this matter? It allows 3rd-party libraries to create their own "promise-compatible" objects with extra features, without having to inherit directly from the native Promise class.

Bigger Example: Fetch

Chaining network requests

In frontend programming, promises are heavily used for network requests. The fetch(url) function returns a promise that resolves with a response object.

Fetching data and a GitHub Avatar

fetch('/article/promise-chaining/user.json')
  .then(response => response.json()) // Parse JSON
  .then(user => fetch(`https://api.github.com/users/${user.name}`))
  .then(response => response.json()) // Parse GitHub JSON
  .then(githubUser => {
    let img = document.createElement('img');
    img.src = githubUser.avatar_url;
    document.body.append(img);
    setTimeout(() => img.remove(), 3000);
  });
Analogy: Looking up a friend 📖
1. Look up their name in your contacts (Fetch user.json).
2. Use that name to find their social profile (Fetch GitHub API).
3. Show their profile picture (Display avatar).
Each step depends on the data from the previous step!

Making Chains Extendable

Always return a promise from async actions

In the previous example, what if we want to do something after the avatar is removed? Currently, the chain ends at the setTimeout. To make it extendable, return a new Promise! 

.then(githubUser => new Promise(function(resolve, reject) {
  let img = document.createElement('img');
  img.src = githubUser.avatar_url;
  document.body.append(img);

  setTimeout(() => {
    img.remove();
    resolve(githubUser); // (*) Resolve only after removal!
  }, 3000);
}))
// Now we can safely add more steps!
.then(githubUser => alert(`Finished showing ${githubUser.name}`));
Best Practice: An asynchronous action should always return a promise. It makes it possible to plan actions after it, even if you don't need to extend the chain right now.

Refactoring into Reusable Functions

Cleaning up long promise chains

Long chains can get messy. We can split them into small, single-purpose functions that return promises. This makes the code highly readable and reusable. 

// 1. Reusable fetch function
function loadJson(url) {
  return fetch(url).then(response => response.json());
}

// 2. Reusable GitHub fetcher
function loadGithubUser(name) {
  return loadJson(`https://api.github.com/users/${name}`);
}

// 3. Reusable avatar shower
function showAvatar(githubUser) {
  return new Promise(resolve => {
    // show img logic...
    setTimeout(() => {
      // remove img logic...
      resolve(githubUser);
    }, 3000);
  });
}

// The chain is now incredibly clean!
loadJson('/user.json')
  .then(user => loadGithubUser(user.name))
  .then(showAvatar)
  .then(githubUser => alert(`Finished showing ${githubUser.name}`));
