Generators

Functions that can pause and resume

Regular functions return one value and finish. Generators can return ("yield") multiple values, one after another, on-demand. They can pause their execution and resume later.

Real-World Analogy: The Vending Machine 🥤
A regular function is like a chef making one meal and closing the kitchen. A Generator is like a vending machine. It holds many items. You press the button (next()), it dispenses one drink (yield) and pauses. You press it again, it dispenses the next.

Generator Functions & Syntax

Creating a generator with function*

To create a generator, we use the function* syntax. Inside, we use the yield keyword instead of return to output values.

Basic Syntax

function* generateSequence() {
  yield 1;
  yield 2;
  return 3;
}

It doesn't run immediately!

When you call generateSequence(), the code does NOT execute. Instead, it returns a special Generator Object that manages the execution.

Styling tip: Both function* f() and function *f() are correct, but function* is preferred because the star describes the kind of function, not the name.

The next() Method

Resuming execution step-by-step

The main method of a generator is next(). When called, it runs the code until the nearest yield, pauses, and returns an object with the yielded value and status.

Step-by-Step Execution

let generator = generateSequence();

let one = generator.next(); 
// {value: 1, done: false} - Paused at first yield

let two = generator.next(); 
// {value: 2, done: false} - Paused at second yield

let three = generator.next(); 
// {value: 3, done: true} - Reached the return
Property Meaning
value The yielded or returned value.
done false if paused at yield. true if the function finished.

Generators are Iterable

Using for..of and the spread syntax

Because generators have a next() method, they are naturally iterable. We can loop over them using for..of instead of calling next() manually.

Looping over a generator

function* generateSequence() {
  yield 1;
  yield 2;
  yield 3; // Use yield, not return, for the last item!
}

let generator = generateSequence();

for(let value of generator) {
  alert(value); // 1, then 2, then 3
}
Crucial Gotcha: for..of ignores the final return value! If the last value is a return 3, the loop only shows 1 and 2. If you want all values in the loop, you must use yield 3 at the end.

Spread Syntax works too!

let sequence = [0, ...generateSequence()];
alert(sequence); // 0, 1, 2, 3

Using Generators for Iterables

Simplifying custom iterators

Earlier, we created iterable objects using a complex [Symbol.iterator] method with manual state tracking. Generators make this incredibly easy.

Old Way (Verbose)

let range = {
  from: 1, to: 5,
  [Symbol.iterator]() {
    return {
      current: this.from,
      last: this.to,
      next() {
        if (this.current <= this.last) {
          return { done: false, value: this.current++ };
        } else {
          return { done: true };
        }
      }
    };
  }
};

New Way (Generator)

let range = {
  from: 1, to: 5,
  *[Symbol.iterator]() {
    for(let value = this.from; 
        value <= this.to; 
        value++) {
      yield value;
    }
  }
};

alert( [...range] ); 
// 1,2,3,4,5

Generator Composition

Embedding generators inside each other

We can combine multiple generators into one using the yield* syntax. This delegates execution to another generator transparently, without using extra memory for intermediate arrays.

Composing Sequences

function* generateSequence(start, end) {
  for (let i = start; i <= end; i++) yield i;
}

function* generatePasswordCodes() {
  // 0..9
  yield* generateSequence(48, 57);
  // A..Z
  yield* generateSequence(65, 90);
  // a..z
  yield* generateSequence(97, 122);
}

let str = '';
for(let code of generatePasswordCodes()) {
  str += String.fromCharCode(code);
}
alert(str); // 0..9A..Za..z
Analogy: The Mega-Playlist 🎶
Think of yield* as importing a whole playlist into your main playlist. It just seamlessly plays through the imported songs as if they were part of the original list.

Yield is a Two-Way Street

Passing values back into the generator

yield doesn't just send values out; it can also receive values from the outside! If we pass an argument to generator.next(arg), that argument becomes the result of the current yield.

Example: Q&A Session

function* gen() {
  let result = yield "2 + 2 = ?"; // (*)
  alert(result); // 4
}

let generator = gen();

let question = generator.next().value; 
// yields "2 + 2 = ?" and pauses

generator.next(4); 
// Passes 4 back into the generator as the result of yield
Analogy: The Drive-Thru Intercom 🍔
1. The speaker asks "What would you like?" (yield).
2. It pauses and waits for you to speak.
3. You say "A burger" (next("A burger")).
4. The speaker receives your answer and the kitchen resumes working.

Throw & Return

Error handling and early termination

generator.throw(err)

We can also pass an error into the generator. The error is thrown at the line with the yield. 

function* gen() {
  try {
    let result = yield "2 + 2?";
  } catch(e) {
    alert(e); // Catches the error!
  }
}

let generator = gen();
let q = generator.next().value;
generator.throw(
  new Error("Database error")
);

generator.return(value)

Instantly finishes the generator, returning the given value. 

function* gen() {
  yield 1;
  yield 2;
  yield 3;
}

const g = gen();

g.next();        // { value: 1, done: false }
g.return('foo'); // { value: "foo", done: true }
g.next();        // { value: undefined, done: true }
Summary: Generators are unique because they allow a function to exchange data with the calling code during execution. While rarely used for everyday tasks, they are perfect for making custom iterables and handling streamed data (like async generators).
