WeakMap and WeakSet

Memory management for collections

As we know from the chapter Garbage collection, JavaScript engine keeps a value in memory while it is "reachable" and can potentially be used.

For instance:

let john = { name: "John" };

// the object can be accessed, john is the reference to it

// overwrite the reference
john = null;

// the object will be removed from memory

Usually, properties of an object or elements of an array or another data structure are considered reachable and kept in memory while that data structure is in memory.

For instance, if we put an object into an array, then while the array is alive, the object will be alive as well, even if there are no other references to it.

let john = { name: "John" };

let array = [john];

john = null; // overwrite the reference

// the object previously referenced by john is stored inside the array
// therefore it won't be garbage-collected
// we can get it as array[0]

Similar to that, if we use an object as the key in a regular Map, then while the Map exists, that object exists as well. It occupies memory and may not be garbage collected.

let john = { name: "John" };

let map = new Map();
map.set(john, "...");

john = null; // overwrite the reference

// john is stored inside the map,
// we can get it by using map.keys()

WeakMap is fundamentally different in this aspect. It doesn't prevent garbage-collection of key objects.

Let's see what it means on examples.

WeakMap Details

Understanding how WeakMap works

The first difference between Map and WeakMap is that keys must be objects, not primitive values:

let weakMap = new WeakMap();

let obj = {};

weakMap.set(obj, "ok"); // works fine (object key)

// can't use a string as the key
weakMap.set("test", "Whoops"); // Error, because "test" is not an object

Now, if we use an object as the key in it, and there are no other references to that object – it will be removed from memory (and from the map) automatically.

let john = { name: "John" };

let weakMap = new WeakMap();
weakMap.set(john, "...");

john = null; // overwrite the reference

// john is removed from memory!

WeakMap does not support iteration and methods keys(), values(), entries(), so there's no way to get all keys or values from it.

WeakMap has only the following methods:

  • weakMap.set(key, value)
  • weakMap.get(key)
  • weakMap.delete(key)
  • weakMap.has(key)

Why such a limitation?

That's for technical reasons. If an object has lost all other references (like john in the code above), then it is to be garbage-collected automatically. But technically it's not exactly specified when the cleanup happens.

The JavaScript engine decides that. It may choose to perform the memory cleanup immediately or to wait and do the cleaning later when more deletions happen. So, technically, the current element count of a WeakMap is not known. The engine may have cleaned it up or not, or did it partially. For that reason, methods that access all keys/values are not supported.

Where do we need such a data structure?

The main area of application for WeakMap is an additional data storage.

If we're working with an object that "belongs" to another code, maybe even a third-party library, and would like to store some data associated with it, that should only exist while the object is alive – then WeakMap is exactly what's needed.

We put the data to a WeakMap, using the object as the key, and when the object is garbage collected, that data will automatically disappear as well.

weakMap.set(john, "secret documents");
// if john dies, secret documents will be destroyed automatically

WeakMap Use Cases

Practical applications of WeakMap

Use case: additional data

The main area of application for WeakMap is an additional data storage.

If we're working with an object that "belongs" to another code, maybe even a third-party library, and would like to store some data associated with it, that should only exist while the object is alive – then WeakMap is exactly what's needed.

Let's look at an example of a counting function with Map vs WeakMap:

Using Map (problematic)

// 📁 visitsCount.js
let visitsCountMap = new Map(); // map: user => visits count

// increase the visits count
function countUser(user) {
  let count = visitsCountMap.get(user) || 0;
  visitsCountMap.set(user, count + 1);
}

Problem: When the user object is no longer needed, it remains in the map, causing memory leaks.

Using WeakMap (solution)

// 📁 visitsCount.js
let visitsCountMap = new WeakMap(); // weakmap: user => visits count

// increase the visits count
function countUser(user) {
  let count = visitsCountMap.get(user) || 0;
  visitsCountMap.set(user, count + 1);
}

When the user object is garbage collected, the data is automatically removed from the WeakMap.

Use case: caching

Another common example is caching. We can store ("cache") results from a function, so that future calls on the same object can reuse it.

Let's compare Map vs WeakMap for caching:

Map for caching (problematic)

// 📁 cache.js
let cache = new Map();

// calculate and remember the result
function process(obj) {
  if (!cache.has(obj)) {
    let result = /* calculations of the result for */ obj;

    cache.set(obj, result);
    return result;
  }

return cache.get(obj);
}

// 📁 main.js
let obj = {/* some object */};

let result1 = process(obj); // calculated

// ...later, from another place of the code...
let result2 = process(obj); // remembered result taken from cache

// ...later, when the object is not needed any more:
obj = null;

alert(cache.size); // 1 (Ouch! The object is still in cache, taking memory!)

Problem: The object remains in the cache even when no longer needed, causing memory leaks.

WeakMap for caching (solution)

// 📁 cache.js
let cache = new WeakMap();

// calculate and remember the result
function process(obj) {
  if (!cache.has(obj)) {
    let result = /* calculate the result for */ obj;

    cache.set(obj, result);
    return result;
  }

return cache.get(obj);
}

// 📁 main.js
let obj = {/* some object */};

let result1 = process(obj);
let result2 = process(obj);

// ...later, when the object is not needed any more:
obj = null;

// Can't get cache.size, as it's a WeakMap,
// but it's 0 or soon be 0
// When obj gets garbage collected, cached data will be removed as well

Solution: When the object is garbage collected, cached data is automatically removed.

WeakMap is ideal for scenarios where you need to associate data with objects without preventing those objects from being garbage collected when they're no longer needed elsewhere in your code.

WeakSet

A collection of unique object references

WeakSet behaves similarly to WeakMap:

  • It is analogous to Set, but we may only add objects to WeakSet (not primitives).
  • An object exists in the set while it is reachable from somewhere else.
  • Like Set, it supports add, has and delete, but not size, keys(), and no iterations.

Being "weak", it also serves as an additional storage. But not for arbitrary data, rather for "yes/no" facts. A membership in WeakSet may mean something about the object.

For instance, we can add users to WeakSet to keep track of those who visited our site:

let visitedSet = new WeakSet();

let john = { name: "John" };
let pete = { name: "Pete" };
let mary = { name: "Mary" };

visitedSet.add(john); // John visited us
visitedSet.add(pete); // Then Pete
visitedSet.add(john); // John again

// visitedSet has 2 users now

// check if John visited
alert(visitedSet.has(john)); // true

// check if Mary visited
alert(visitedSet.has(mary)); // false

john = null;

// visitedSet will be cleaned automatically

WeakSet vs Set

Feature Set WeakSet
Key Types Any type Objects only
Memory Management Objects remain as long as the Set exists Objects are automatically removed when no longer referenced elsewhere
Iteration Supported (keys(), values(), entries()) Not supported
Size Available (size property) Not available

Practical use cases for WeakSet

Tracking object relationships:

WeakSet can be used to track relationships between objects without preventing garbage collection.

class Person {
  constructor(name) {
    this.name = name;
  }

let friends = new WeakSet();

function makeFriends(person1, person2) {
  friends.add(person1, person2);
  friends.add(person2, person1);
}

function areFriends(person1, person2) {
  return friends.has(person1) && friends.has(person2);
  }

let alice = new Person("Alice");
let bob = new Person("Bob");

makeFriends(alice, bob);
alert(areFriends(alice, bob)); // true

// When alice and bob are no longer referenced elsewhere,
// the friendship information is automatically cleaned up

DOM element references:

When working with DOM elements, you might want to track which elements have certain event listeners attached without preventing those elements from being garbage collected.

const attachedListeners = new WeakMap();
// Attach an event listener to an element
function attachListener(element, event, handler) {
  // Store the reference
  if (!attachedListeners.has(element)) {
    attachedListeners.set(element, new Set());
  }

  // Add the handler to the set
  attachedListeners.get(element).add(handler);
  }

// Remove the listener when done
function removeListener(element, handler) {
  if (attachedListeners.has(element)) {
    const listeners = attachedListeners.get(element);
    listeners.delete(handler);

    if (listeners.size === 0) {
       attachedListeners.delete(element);
    }
  }
}

WeakSet is ideal for tracking object relationships and references without creating memory leaks. It automatically cleans up when objects are no longer needed elsewhere.

Object.keys, values, entries

Iterating over object properties

Let's step away from the individual data structures and talk about the iterations over them.

In the previous chapter we saw methods map.keys(), map.values(), map.entries().

These methods are generic, there is a common agreement to use them for data structures. If we ever create a data structure of our own, we should implement them too.

They are supported for:

  • Map
  • Set
  • Array

Plain objects also support similar methods, but the syntax is a bit different.

Object.keys, values, entries

For plain objects, the following methods are available:

  • Object.keys(obj) – returns an array of keys.
  • Object.values(obj) – returns an array of values.
  • Object.entries(obj) – returns an array of [key, value] pairs.

Please note the distinctions (compared to map for example):

Map Object
Call syntax map.keys() Object.keys(obj), but not obj.keys()
Returns iterable "real" Array

Here's an example of using Object.values to loop over property values:

let user = {
  name: "John",
  age: 30
};

// loop over values
for (let value of Object.values(user)) {
  alert(value); // John, then 30
}

Object.keys/values/entries ignore symbolic properties

Just like a for..in loop, these methods ignore properties that use Symbol(...) as keys.

Usually that's convenient. But if we want symbolic keys too, then there's a separate method Object.getOwnPropertySymbols that returns an array of only symbolic keys. Also, there exist a method Reflect.ownKeys(obj) that returns all keys.

Transforming objects

Objects lack many methods that exist for arrays, e.g. map, filter and others.

If we'd like to apply them, then we can use Object.entries followed by Object.fromEntries:

  1. Use Object.entries(obj) to get an array of key/value pairs from obj.
  2. Use array methods on that array, e.g. map, to transform these key/value pairs.
  3. Use Object.fromEntries(array) on the resulting array to turn it back into an object.

For instance, we have an object with prices, and would like to double them:

let prices = {
  banana: 1,
  orange: 2,
  meat: 4,
};

let doublePrices = Object.fromEntries(
  // convert prices to array, map each key/value pair into another pair
  Object.entries(prices).map(entry => [entry[0, entry[1] * 2])
);

alert(doublePrices.meat); // 8

It may look difficult at first sight, but becomes easy to understand after you use it once or twice. We can make powerful chains of transforms this way.

The Object methods (keys, values, entries) combined with array methods and Object.fromEntries provide a powerful toolkit for working with object data structures.

Transforming Objects

Converting objects to arrays and back

Objects lack many methods that exist for arrays, e.g. map, filter and others.

If we'd like to apply them, then we can use Object.entries followed by Object.fromEntries:

Object

Original object with properties

→

Object.entries()

Array of [key, value] pairs

→

Array Methods

Transform each pair using map, filter, etc.

→

Object.fromEntries()

Convert back to object

Let's look at a more complex example with multiple transformations:

function transformObject(obj, transformer) {
  // Convert object to array of key/value pairs
  let entries = Object.entries(obj);

  // Apply the transformer function to each pair
  let transformedEntries = entries.map(transformer);

  // Convert back to object
  return Object.fromEntries(transformedEntries);
}

// Example: Convert object values to strings and keys to uppercase
const user = {
  name: "john",
  age: 30,
  email: "john@example.com"
};

// Transform: values to strings, keys to uppercase
const transformed = transformObject(user, ([key, value]) => [key.toUpperCase(), String(value)]);

alert(JSON.stringify(transformed, null, 2)); // {"NAME":"john","AGE":"30","EMAIL":"john@example.com"}

Practical Example: Filtering Object Properties

Let's create a function that filters object properties based on certain criteria:

function filterObjectProperties(obj, predicate) {
  const result = {};

  for (const [key, value] of Object.entries(obj)) {
    if (predicate(key, value)) {
      result[key] = value;
    }
  }

return result;
}

// Example usage:
const user = {
  name: "John",
  age: 30,
  isAdmin: false
  email: "john@example.com"
};

// Get only string properties
const stringProps = filterObjectProperties(user, (key, value) => typeof value === 'string');

alert(JSON.stringify(stringProps)); // {"name":"John","email":"john@example.com"}

The combination of Object.entries and Object.fromEntries provides a powerful pattern for transforming objects, allowing you to easily manipulate object structures while maintaining the original data.

Summary

Complete overview of WeakMap, WeakSet, and Object methods

WeakMap

  • Map-like collection that allows only objects as keys.
  • When a key object is no longer referenced elsewhere, it's automatically removed from the WeakMap.
  • Only supports methods: set, get, has, delete.
  • Doesn't support iteration or size property.
  • Use case: Additional data storage for objects without preventing garbage collection.

WeakSet

  • Set-like collection that stores only objects.
  • When an object is no longer referenced elsewhere, it's automatically removed from the WeakSet.
  • Only supports methods: add, has, delete.
  • Doesn't support iteration or size property.
  • Use case: Tracking object relationships or "yes/no" facts about objects.

Object Methods

  • Object.keys(obj) – returns an array of keys.
  • Object.values(obj) – returns an array of values.
  • Object.entries(obj) – returns an array of [key, value] pairs.
  • These methods ignore Symbol properties; use Object.getOwnPropertySymbols for symbolic keys.
  • Use Object.entries with Object.fromEntries to transform objects.

Practical Applications

  • Caching: Use WeakMap to cache results of expensive computations without memory leaks.
  • Relationship tracking: Use WeakSet to track relationships between objects.
  • DOM element tracking: Use WeakMap to track event listeners without preventing garbage collection.
  • Object transformation: Use Object.entries → array methods → Object.fromEntries to transform objects.
  • Filtering properties: Use Object.entries to filter object properties based on criteria.
