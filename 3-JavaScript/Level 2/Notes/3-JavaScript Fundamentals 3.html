Why Loops?

Loops let us repeat code:

  • Process list items
  • Count numbers
  • Run logic until a condition changes

Example:

// Instead of writing this:
alert(1);
alert(2);
alert(3);

// We can use a loop:
for (let i = 1; i <= 3; i++) {
  alert(i);
}

while loop

Runs while the condition is truthy.

while (condition) {
  // loop body
}

Example:

let i = 0;

while (i < 3) {
  alert(i); // 0, 1, 2
  i++;
}
Each run = one iteration

Condition as a Value

Any value can be a condition (converted to boolean):

let i = 3;
while (i) {   // stops when i becomes 0
  alert(i);
  i--;
}

Single-line body

Curly braces are optional for one statement:

while (i) alert(i--);
0, null, undefined, "", NaN are falsy - all other values are truthy

do…while loop

Runs the body at least once, then checks the condition.

do {
  // loop body
} while (condition);

Example:

let i = 0;

do {
  alert(i);
  i++;
} while (i < 3);
Use only when at least one execution is required.

for loop (most common)

Best when the number of iterations is known.

for (begin; condition; step) {
  // loop body
}

Example:

for (let i = 0; i < 3; i++) {
  alert(i); // 0, 1, 2
}

How for loop works

  • begin → runs once
  • condition → checked before each iteration
  • body → executed if condition is true
  • step → runs after each iteration

Visual representation:

for (let i = 0; i < 3; i++) {
  alert(i);
}

// Step by step:
// 1. let i = 0  (begin)
// 2. i < 3 ?    (condition, true)
// 3. alert(i)   (body, shows 0)
// 4. i++        (step, i becomes 1)
// 5. i < 3 ?    (condition, true)
// 6. alert(i)   (body, shows 1)
// ... and so on

Inline Variable Scope

Block-scoped variable:

for (let i = 0; i < 3; i++) {
  alert(i);
}
alert(i); // ❌ error (i is block-scoped)

Using an existing variable:

let i;

for (i = 0; i < 3; i++) {
  alert(i);
}
alert(i); // 3
Block-scoped variables are generally safer and prevent bugs.

Skipping Parts of for

All parts are optional (but semicolons stay).

No begin:

let i = 0;
for (; i < 3; i++) alert(i);

No step:

let i = 0;
for (; i < 3;) alert(i++);

Infinite loop:

for (;;) {
  // runs forever
}

break and continue

break

Stops the loop immediately.

while (true) {
  let value = +prompt("Enter a number", "");

  if (!value) break;

  sum += value;
}

continue

Skips the current iteration, moves to the next one.

for (let i = 0; i < 10; i++) {
  if (i % 2 === 0) continue;
  alert(i); // 1, 3, 5, 7, 9
}

Labels and When to Use What

Labels (advanced but important)

Used to exit multiple nested loops.

outer: for (let i = 0; i < 3; i++) {
  for (let j = 0; j < 3; j++) {
    if (!prompt(`(${i},${j})`)) break outer;
  }
}
alert("Done!");

When to use what?

  • while - Unknown number of iterations
  • do…while - Must run at least once
  • for - Counter-based loops

What is switch?

switch is an alternative to multiple if…else if checks.

It compares one value against many possible values in a readable way.

Think of it as: "If the value is this → do that"

Example scenario:

// Instead of multiple if statements:
if (x === 1) {
  // do something
} else if (x === 2) {
  // do something else
} else if (x === 3) {
  // do another thing
}

// We can use switch:
switch (x) {
  case 1:
    // do something
    break;
  case 2:
    // do something else
    break;
  case 3:
    // do another thing
    break;
}

Basic Syntax

switch (x) {
  case value1:
    // code
    break;

  case value2:
    // code
    break;

  default:
    // code
}

How it works:

  • x is compared using strict equality (===)
  • First matching case runs
  • Execution continues until break or end of switch
  • If nothing matches → default runs

Simple Example

let a = 2 + 2;

switch (a) {
  case 3:
    alert("Too small");
    break;

  case 4:
    alert("Exactly!");
    break;

  case 5:
    alert("Too big");
    break;

  default:
    alert("I don't know such values");
}

What happens:

  • a is compared with 3 ❌
  • Compared with 4 ✅
  • Code runs until break
  • Switch stops

Why break is Important

Without break, execution falls through to the next cases.

Example without break:

let a = 2 + 2;

switch (a) {
  case 3:
    alert("Too small");
  case 4:
    alert("Exactly!");
  case 5:
    alert("Too big");
  default:
    alert("I don't know such values");
}

Output:

Exactly!
Too big!
I don't know such values
This behavior is sometimes useful—but often a bug.

Any Expression is Allowed

Both switch and case can use expressions, not just values.

let a = "1";
let b = 0;

switch (+a) {
  case b + 1:
    alert("This runs");
    break;

  default:
    alert("This doesn't");
}

How it works:

  • +a converts "1" → 1
  • b + 1 is also 1
  • Strict match → runs

Grouping Multiple Cases

Multiple cases can share the same code.

let a = 3;

switch (a) {
  case 4:
    alert("Right!");
    break;

  case 3:
  case 5:
    alert("Wrong!");
    alert("Why don't you take a math class?");
    break;

  default:
    alert("Strange result");
}
No break after case 3 → Execution "falls through" into case 5 → Shared logic runs once

switch Uses Strict Equality (===)

Type matters.

let arg = prompt("Enter a value?");

switch (arg) {
  case '0':
  case '1':
    alert("One or zero");
    break;

  case '2':
    alert("Two");
    break;

  case 3:
    alert("Never runs!");
    break;

  default:
    alert("Unknown value");
}
Why case 3 never runs:
  • prompt() returns a string
  • "3" !== 3
  • Strict comparison fails

Fix by converting input:

switch (+arg) { ... }

When to Use switch

Use switch when:

  • Comparing one value
  • Against many fixed options
  • Logic is simple and flat

Avoid switch when:

  • Conditions are complex
  • Ranges are involved (>, <)
  • Boolean logic is needed

Key takeaways:

  • switch replaces many if…else if
  • Uses strict equality (===)
  • break prevents fall-through
  • Missing break → code continues
  • Multiple cases can share one block
  • Always watch types when matching

What is a Function?

A function is a reusable block of code designed to perform one task.

Why functions exist:

  • Avoid repeating code
  • Make programs easier to read
  • Change logic in one place

Built-in examples:

alert()
prompt()
confirm()

We can also create our own functions.

Function Declaration

The basic syntax:

function showMessage() {
  alert("Hello everyone!");
}

Structure:

function name(parameter1, parameter2, ...) {
  // function body
}

Calling a function:

showMessage();
showMessage();

Each call runs the function body again.

Main purpose: reuse code instead of copying it.

Local Variables

Variables declared inside a function exist only there.

function showMessage() {
  let message = "Hello!";
  alert(message);
}

showMessage();
alert(message); // ❌ Error

Example with multiple local variables:

function calculateSum() {
  let a = 5;
  let b = 10;
  let result = a + b;
  return result;
}

// a, b, and result don't exist here
Local variables are invisible outside the function.

Outer Variables

Functions can access variables outside them.

Reading outer variables:

let userName = "John";

function showMessage() {
  alert("Hello " + userName);
}

showMessage(); // Hello John

Modifying outer variables:

let userName = "John";

function showMessage() {
  userName = "Bob";
}

showMessage();
alert(userName); // Bob

Variable Shadowing

If a function declares a variable with the same name, it hides the outer one. 

let userName = "John";

function showMessage() {
  let userName = "Bob";
  alert(userName); // Bob
}

showMessage();
alert(userName); // John

Visual explanation:

let value = "outer";

function check() {
  let value = "inner"; // shadows the outer value
  alert(value); // "inner"
}

alert(value); // "outer"
Local variables always win.

Global Variables

Variables declared outside all functions are global.

  • Accessible everywhere
  • Can be shadowed by locals
  • Should be used sparingly

Example:

let globalVar = "I'm global";

function showGlobal() {
  alert(globalVar); // Can access global
}

showGlobal(); // "I'm global"
Modern best practice: Use local variables + parameters, not globals.

Parameters and Arguments

Functions can receive data.

function showMessage(from, text) {
  alert(from + ": " + text);
}

showMessage("Ann", "Hello!");

Terminology:

  • Parameter → variable in function definition
  • Argument → value passed during the call
showMessage("Ann", "Hello");
// "Ann" and "Hello" are arguments

Parameters are Copied

Functions receive copies, not originals (for primitives).

function showMessage(from) {
  from = "*" + from + "*";
  alert(from);
}

let name = "Ann";
showMessage(name);

alert(name); // Ann (unchanged)

What happens:

  • name is passed to the function
  • A copy of name is created as the parameter "from"
  • The function modifies the copy, not the original
  • Original name remains unchanged

Default Parameter Values

If an argument is missing → value becomes undefined.

function showMessage(from, text = "no text given") {
  alert(from + ": " + text);
}

showMessage("Ann"); // Ann: no text given

Defaults also apply when argument is undefined:

showMessage("Ann", undefined); // Ann: no text given

Default values are evaluated at call time:

function showMessage(text = anotherFunction()) {
  // anotherFunction runs only if text is missing
}

Old Ways to Set Defaults

Using undefined:

if (text === undefined) {
  text = "no text given";
}

Using || (problematic for falsy values):

text = text || "no text given";

This is problematic because 0, "", false, etc. are valid values that would be replaced.

Modern default handling: ??

Best when 0, "", or false are valid values.

function showCount(count) {
  alert(count ?? "unknown");
}

showCount(0);    // 0
showCount(null); // unknown
showCount();     // unknown

Returning Values

Functions can return results.

function sum(a, b) {
  return a + b;
}

let result = sum(1, 2); // 3

return stops execution:

function checkAge(age) {
  if (age >= 18) return true;
  return confirm("Permission?");
}
A function can only return one value, but it can be an object or array containing multiple values.

return Without a Value

Returns undefined.

function doNothing() {}
doNothing(); // undefined

Same as:

function doNothing() {
  return;
}

Example with early exit:

checkAge(age) {
  if (age < 0) return; // exit early
  if (age < 18) return false;
  return true;
}

Never Split return and Value

❌ Wrong:

return
  a + b;

JavaScript automatically inserts a semicolon after return, so this returns undefined!

✅ Correct:

return (
  a + b
);

Parentheses prevent automatic semicolon insertion.

This is a common source of bugs in JavaScript!

Naming Functions

Functions represent actions, so names should be verbs.

Common prefixes:

  • get… → returns a value
  • calc… → calculates
  • create… → creates something
  • check… → returns true/false
  • show… → displays something

Examples:

getAge()
calcSum()
checkPermission()

One Function = One Action

Bad design:

getAge() → also shows alert ❌
checkPermission() → displays messages ❌

Good design:

  • One responsibility
  • Predictable behavior
function getAge(user) {
  return user.age; // just returns the age
}

function showAge(age) {
  alert(`You are ${age} years old`); // just displays
}

Functions as Self-Documenting Code

Hard to read:

nextPrime:
for (...) {
  ...
}

Clear and readable:

if (!isPrime(i)) continue;
Function names act like comments.

Example:

// Instead of this:
if (user.age >= 18 && user.hasPermission) {
  // allow access
}

// Use this:
if (isAdult(user) && hasAccess(user)) {
  // allow access
}

Why Small Functions are Better

  • Easier to test
  • Easier to debug
  • Easier to understand
  • Easier to reuse

Example:

// Instead of one big function:
function processUser(user) {
  // 50 lines of code
}

// Break it into smaller functions:
function processUser(user) {
  validateUser(user);
  transformUserData(user);
  saveUser(user);
  notifyUser(user);
}
Even single-use functions improve readability.

Final Summary

Functions are reusable building blocks

  • Parameters are local copies
  • Local variables are isolated
  • Functions may return values (or undefined)
  • Prefer parameters + return over globals
  • Clear names + single responsibility = clean code

Key concepts from all sections:

  • Loops: repeat code efficiently
  • Switch: compare one value against many options
  • Functions: reusable blocks of code
Mastering these fundamentals is essential for JavaScript development!
