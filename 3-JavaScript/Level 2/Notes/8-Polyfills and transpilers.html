Problem: Modern JavaScript may not work everywhere

JavaScript keeps evolving. New features are added frequently:

New syntax examples:

  • Nullish coalescing operator (??)
  • Optional chaining (?.)
  • Arrow functions (=>)
  • Destructuring assignment

New functions examples:

  • Math.trunc()
  • Array.prototype.includes()
  • String.prototype.padStart()
  • Promise.allSettled()
Older browsers or environments might not understand these new features. If you write modern code, it might break in older environments.

Example of the Problem

If you write:

let height = height ?? 100;

Modern browsers:

Understand ?? → works fine

let height = height ?? 100;
// height = 100 if height is null or undefined

Old browsers:

Don't understand ?? → code breaks

let height = height ?? 100;
// SyntaxError: Unexpected token ??
So we need a way to make modern code compatible with older browsers. That's where transpilers and polyfills come in.

Transpilers: translate modern syntax to older syntax

A transpiler reads your modern code and rewrites it into equivalent old-style code that all browsers understand.

Example: Nullish coalescing operator (??)

Modern code:

let height = height ?? 100;

Transpiler output for older engines:

let height = (height !== undefined && height !== null) ? height : 100;

✅ Behavior is the same
✅ Works in older browsers

Tools: Babel is the most popular JavaScript transpiler. In projects with build systems like Webpack, Babel can automatically transpile code whenever you save changes.

Step-by-step demo for transpiler

Step 1: Write modern code using ??

let height = undefined;
height = height ?? 100;
console.log(height); // 100

Step 2: Use Babel online (https://babeljs.io/repl)

  • Paste the code
  • Click "Transform"

Step 3: You'll see the transpiled output

"use strict";

var height = void 0;
height = height !== null && height !== void 0 ? height : 100;
console.log(height);

Copy this transformed code → now it works in older browsers.

Polyfills: add missing functions

Sometimes the syntax exists, but the browser doesn't have certain functions.

Example: Math.trunc()

Modern browsers:

console.log(Math.trunc(1.23)); // 1
console.log(Math.trunc(-1.23)); // -1

Old browsers:

console.log(Math.trunc(1.23)); // TypeError: Math.trunc is not a function

Solution: Polyfill

A script that defines the missing function if it doesn't exist:

if (!Math.trunc) {
  Math.trunc = function(number) {
    return number < 0 ? Math.ceil(number) : Math.floor(number);
  };
}

✅ Adds Math.trunc for browsers that don't support it
✅ Works without breaking modern browsers

Step-by-step demo for polyfill

Step 1: Old browser environment

Math.trunc is missing

Step 2: Add polyfill

if (!Math.trunc) {
  Math.trunc = function(number) {
    return number < 0 ? Math.ceil(number) : Math.floor(number);
  };
}

Step 3: Use Math.trunc normally

console.log(Math.trunc(3.7));  // 3
console.log(Math.trunc(-3.7)); // -3

Works everywhere!

Polyfills check if a feature exists before defining it, so they don't interfere with modern browsers that already have the feature.

When to use what

Feature type Solution Example
New syntax Transpiler ??, arrow functions, let/const
New functions Polyfill Math.trunc(), Array.prototype.includes

Summary in plain words

  • Transpilers → rewrite modern code into old-style code so browsers understand new syntax
  • Polyfills → add missing functions so new functionality works in old browsers
Together, they let you use modern JS features safely without worrying about browser compatibility.

Practical example combining both

Modern code using new syntax and function:

let height = undefined;
height = height ?? 100; // new syntax
console.log(Math.trunc(5.7)); // new function

After processing:

// Transpiler converts ??
var height = undefined;
height = height !== null && height !== undefined ? height : 100;

// Polyfill provides Math.trunc if missing
if (!Math.trunc) {
  Math.trunc = function(number) {
    return number < 0 ? Math.ceil(number) : Math.floor(number);
  };
}

console.log(Math.trunc(5.7));
After processing, it works on old browsers too! This combination allows developers to write modern, clean code while maintaining compatibility with older environments.
